# R5 单章高质量写作闭环

> 状态：已接通。本文是本阶段唯一的设计与实现合同。项目负责人阶段验收仍待确认。
>
> 所属阶段：R5
>
> 设计目标：从已确认路线图节点或方向试写出发，生成作者可审阅、可修改、可定稿的一章正文；选区改写不错位覆盖；定稿后的最小记忆失败不回滚正文。

## 1. 结论

R5 不新建第二套智能体运行时。章节质量工作流、Finding Merger、公开阶段和模型供应商仍使用 R3 内核与既有 `ModelProvider`。本阶段补上产品状态：开篇试写、冻结上下文后的单章候选、按有效评估选稿、选区改写、定稿 revision，以及最小 `chapter.posthoc`。

```text
已选方向 → 非正式试写 → 反馈回策划
                ↓ 档案确认 + 复检 + 显式接受（仍不入正式记忆、不计定稿字数）
已确认路线图节点 → 预检 → Context Manifest → 导演任务
                ↓ 只把冻结任务交给主写
                隔离审阅 → Finding Merger → 核验 → 有界修订
                ↓
        按有效评估选稿（不取最后一份产物）→ 作者定稿（新 revision）
                ↓
        chapter.posthoc（陈述 / 发言 / 猜测）→ 下一章预检读取已提交事实
```

## 2. 范围与非目标

### 2.1 本阶段范围

- 方向后的开篇试写：局部交接即可生成非正式候选；反馈为继续策划、调整或放弃；方向变化使旧试写失效；转正必须同时满足档案已确认、复检通过和作者显式接受。失败或取消保留原候选。
- 从已确认路线图节点生成章节候选。预检记忆可用性与预算。Context Manifest 可审计。主写只接收冻结后的导演任务。
- 审阅彼此隔离，同轮读取同一冻结正文。确定性合并去重并暴露证据冲突。问题分为硬冲突、语义不确定和偏好建议。核验结果为成立、不成立或证据不足。
- 人物发言或猜测不得写成世界事实，也不得直接升级为世界规则硬冲突。偏好建议不得自动升级为硬阻断。
- 有界修订不得静默改写作者约束。修订若改变知识边界或引入新冲突，该稿评估失效，可以退回仍有效的前稿。
- 选稿必须指向有效评估和准确版本，并记录理由。
- 选区改写绑定章节 revision、Unicode rune 范围和原文哈希。正文已变化则拒绝。全部采纳、部分采纳和放弃都留下记录；部分采纳使旧评估失效；采纳写入新 revision。
- 最小后验：带语境提取客观陈述、人物发言和猜测，按证据采纳、待定或冲突。提交与正文定稿分离。失败写入 `memory_pending_rebuild`，不回滚正文，不锁编辑。下一章生成必须预检；同一来源可恢复，来源变化必须重做。
- 新步骤只有在预先冻结的 Harness 门槛通过后才能进入默认工作流。
- 正文工作台保持三栏。试写面板和选区动作接通上述规则，窄窗口不丢未保存输入。

### 2.2 不在 R5 实现

- R6 的 3–10 章批次、滚动窗口和批次默认拓扑。
- R7 的五层长期记忆、跨卷扩量和历史重写执行。
- 重写 R3 内核、改冻结工作流或 Schema 的含义，或把试写写入 canonical 记忆。

## 3. 领域规则

1. 试写正文永远 `CountsAsMemory()==false` 且 `CountsAsFinalizedWords()==false`，包括已转正的记录。转正只标记作者接受该非正式候选。
2. 试写来源摘要与当前方向不一致时状态为 `stale`，不能转正。
3. 路线图节点未确认、预算超限、取消、结果未知或冻结版本变化时，不得继续模型调用。
4. 未授权补查直接拒绝。授权补查未命中时保留“证据不足”，不编造事实。
5. 同轮审阅的正文哈希必须相同。
6. 合并只去重和标记冲突，不发明新问题。
7. 最终候选必须 `Valid` 且带评估标识。序列更晚的无效稿不能被自动选中。
8. 选区应用前重新计算当前正文的 rune 切片哈希。不一致返回冲突，不改正文。
9. 部分采纳清空评估标识。放弃不改正文。
10. 发言和猜测的处置不能是“作为世界事实采纳”。
11. 后验失败只改自身状态。幂等键重复提交返回已有成功记录，不再调用模型。
12. 存在 `memory_pending_rebuild` 时，下一章生成在恢复前失败。
13. Harness 门槛未冻结或未达标时，该步骤不能成为默认步骤。

## 4. 持久化

`chapter_loop_records` 只追加产品记录：`opening_sample`、`production`、`selection`、`posthoc`。载荷是不可变 JSON。同一项目、种类、对象和幂等键不能重复插入。正文 canonical 仍只由既有章节 `Commit` 事务更新。

## 5. 接口

桌面命令只转发到当前可写工作区：

- `GenerateOpeningSample`、`RecordOpeningSampleFeedback`、`PromoteOpeningSample`、`CurrentOpeningSample`
- `StartChapterProduction`、`FinalizeChapterProduction`
- `PrepareSelectionRewrite`、`AcceptSelectionRewrite`、`ExplainSelection`
- `CommitChapterPosthoc`、`RecoverChapterPosthoc`

模型调用使用项目已固定创作方案中的规划、主写和审阅角色；角色缺失时不能静默换成别的供应商。测试可注入记录调用的完成器。

## 6. 验收

- 领域测试覆盖第 3 节全部规则，包括连续两章“定稿候选 → 后验提交 → 下章只读已采纳客观事实”。
- 存储测试覆盖追加、幂等和失败不增加记录。
- 工作区测试覆盖定稿创建新 revision、后验失败后正文仍在、选区哈希冲突不覆盖。
- 前端测试覆盖试写生成与反馈不丢输入，以及选区解释不再借用整章生成。
