# R2.1 模型基础设施收口

> 状态：已完成（2026-08-20）
>
> 所属阶段：R2.1
>
> 设计目标：让应用级模型配置真正驱动项目内的真实 AgentRun，为 R3 Agent Kernel 与创作质量 Harness 提供稳定入口。
>
> 验收结论：自动测试、静态检查、前端类型检查与生产构建通过；macOS、Windows 真实 Provider 人工验收通过，未发现阻断问题。

## 1. 背景与结论

当前仓库已经具备应用级设置库、操作系统凭据库、OpenAI/Anthropic Provider、不可变创作方案版本、项目方案版本引用和项目内 AgentRun，但它们尚未形成一条完整链路。

主要断点如下：

| 环节 | 当前状态 | 必须解决的问题 |
|---|---|---|
| 模型连接 | 可保存元数据和 API Key | 更新失败时凭据不能回滚；删除连接未删除凭据 |
| 连接测试 | 应用设置只检查凭据是否存在 | 必须发起真实、最小费用的模型请求，并返回稳定结果 |
| 角色配置 | 后端使用 3 个角色，前端使用 5 个不同标识 | 统一为首版兼容槽 `planner`、`writer`、`continuity_reviewer` |
| 模型名称 | 后端存于方案角色绑定，前端重载时丢失 | 明确模型属于角色绑定，并完整保存、重载和编辑 |
| 创作方案 | 后端可发布不可变版本 | 前端需要加载全部方案的最新版本，并正确设置或清除默认方案 |
| 项目锁定 | 新项目能记录默认方案 ID 和版本 | AgentRun 尚未解析该引用，仍读取旧项目级配置 |
| 真实运行 | Provider 调用能力已存在 | 需要从项目锁定方案生成运行冻结快照，并完成一次真实 AgentRun 冒烟 |
| 用户反馈 | 成功提示为主 | 补齐加载、失败、费用来源、用量和可恢复提示 |

R2.1 的完成定义不是“设置页可以填写”，而是打通以下闭环：

```text
保存模型连接
  → 使用指定模型真实测试
  → 发布三角色创作方案
  → 设置默认方案
  → 新项目锁定具体方案版本
  → 创建运行时冻结快照
  → 真实执行并观察 AgentRun
```

## 2. 范围

### 2.1 本功能包含

- 应用级模型连接的创建、更新、真实测试和安全删除；
- API Key 只进入操作系统凭据库，不进入 SQLite、前端持久状态或日志；
- 首版三个兼容角色槽的统一定义、展示和校验；
- 创作方案的创建、版本发布、列表重载和默认方案选择；
- 新项目锁定默认方案的具体版本；
- 项目 AgentRun 解析锁定版本，并冻结实际使用的连接、模型、参数和预算；
- 一次由用户主动触发、可观察、可取消、可恢复的真实 AgentRun 冒烟测试；
- OpenAI API 与 Anthropic API 的真实调用；
- Windows Credential Manager 与 macOS Keychain 的行为验证；
- 稳定错误分类、局部操作状态、Token 用量和费用来源提示。

### 2.2 本功能不包含

- 新增章节策划、内容编辑、文风编辑、记忆抽取等可组合 Agent 能力；
- Prompt、工作流、输出 Schema 的完整版本系统；
- 创作质量评分、人工盲评和 Creative Quality Harness；
- 兼容 API、本地模型或订阅运行时的正式发布支持；
- 项目级方案切换和逐角色覆盖界面；
- 自动发现 Provider 账户下的全部模型；
- 自动回退到其他模型、连接或收费来源。

上述能力分别由 R3 及后续阶段实现。R2.1 只提供可靠的模型基础设施和首个真实运行入口。

## 3. 核心设计决策

### 3.1 连接、模型和方案分层

- `ProviderConnection` 只保存显示名称、Provider 类型、接口地址和凭据引用。
- 模型名称不属于连接；同一连接可以供不同角色使用不同模型。
- `CreativeProfileVersion` 保存角色到连接、模型和生成参数的绑定。
- 项目只保存选中的方案 ID、版本和运行冻结快照，不保存 API Key。
- API Key 始终通过 `credential_ref` 在调用时从操作系统凭据库读取。

设置页中的“测试模型”只是一次测试请求的输入，不作为连接字段持久化。需要长期保存的模型名称必须进入创作方案角色绑定。

### 3.2 统一角色标识

R2.1 对外只使用后端现有的三个稳定标识：

| 标识 | 中文名称 | 职责 |
|---|---|---|
| `planner` | 规划 | 将作者目标和故事上下文转换为本次写作计划 |
| `writer` | 正文写作 | 根据计划生成叙事正文 |
| `continuity_reviewer` | 连续性审阅 | 检查事实、人物状态和连续性，不与正文写作使用完全相同的连接与模型组合 |

前端删除 `planning`、`writing`、`review`、`memory`、`impact` 这一套平行定义。R3 新增的能力节点使用独立的工作流能力类型，不修改 R2.1 的兼容槽含义，也不把 Agent 数量永久固定为三个。

### 3.3 不可变创作方案

- 编辑已发布方案时，发布一个新版本，不原地修改旧版本。
- 设置页加载每个方案的最新版本；历史版本暂不提供管理界面，但必须能按 ID 和版本解析。
- 默认方案只影响以后创建的新项目，不改变已有项目。
- 默认方案允许明确清除；清除后作者仍可创建项目并手写，但 AI 功能显示“项目未配置创作方案”。
- 发布前必须校验恰好包含三个角色、连接存在、模型非空、预算有效，且正文写作与连续性审阅不能同时使用相同连接和相同模型。

### 3.4 应用方案到 AgentRun 的解析

新增只读应用端口 `CreativeProfileResolver`，由应用设置服务实现：

```go
type CreativeProfileResolver interface {
    ResolveCreativeProfile(
        ctx context.Context,
        profileID string,
        version int64,
    ) (ResolvedCreativeProfile, error)
}
```

解析结果包含方案预算，以及三个角色实际使用的非敏感连接元数据、模型和生成参数；不包含 API Key。

创建 AgentRun 时执行：

1. 读取项目锁定的方案 ID 和版本；
2. 按确切版本解析，不读取当前默认方案或最新版本；
3. 检查三个角色、连接、凭据和预算；
4. 将实际连接、模型、参数和方案来源写入运行步骤冻结快照；
5. 创建排队状态的 AgentRun；
6. 执行时只读取步骤冻结快照和凭据库，不重新解析可变设置。

这样可以避免作者更新接口地址、切换默认方案或发布新版本后，已经创建的任务被静默改变。

### 3.5 运行冻结快照

`AgentRunStep` 增加以下冻结字段：

- `creative_profile_id`；
- `creative_profile_version`；
- `provider_connection_id`；
- `provider_name`；
- `provider_kind`；
- `base_url`；
- `credential_ref`；
- `model`；
- `max_output_tokens`；
- `temperature`。

`AgentRun` 继续冻结 `token_budget` 和 `context_char_budget`。

旧的项目级 `provider_connections` 和 `agent_profiles` 仅作为历史项目兼容来源，不再由应用设置页编辑。数据库迁移需要把旧运行步骤可以推导出的连接和模型信息回填到冻结字段；无法回填的历史任务仍可查看，但不能直接重试，界面提示重新创建任务。

R3 再在该快照上增加 Prompt、工作流、Schema、输入资产和 Context Manifest 版本。

### 3.6 真实连接测试

新增应用端口 `ProviderProber`，Provider 适配器通过现有真实生成协议实现。测试必须由用户主动触发，并满足：

- 输入为已保存的连接 ID 和用户指定的模型名称；
- 从凭据库读取 API Key；
- 发起短 Prompt、低输出上限、零或低温度的真实生成请求；
- 默认超时 20 秒；
- 不自动重试到其他连接或模型；
- 不保存响应正文，只返回请求 ID、延迟和 Token 用量；
- 界面在发送前提示“会产生一次极低额度的真实模型调用”；
- CI 只使用 Fake/Recorded Provider，不调用真实模型。

测试成功只能证明接口鉴权、模型名称和当前调用协议可用，不代表创作质量合格。

### 3.7 凭据一致性

创建连接：

1. 校验非敏感输入；
2. 保存凭据；
3. 保存连接元数据；
4. 元数据保存失败时删除刚写入的凭据。

更新连接：

1. 读取旧元数据和旧凭据；
2. 写入新凭据；
3. 更新元数据；
4. 元数据更新失败时恢复旧凭据；
5. 恢复失败时返回独立的凭据回滚错误，并将连接显示为“凭据需要重新输入”。

删除连接：

1. 检查是否被任一不可变方案版本引用；
2. 被引用时禁止删除，并明确列出原因；
3. 未引用时先读取旧凭据，再删除凭据；
4. 删除元数据；
5. 元数据删除失败时恢复旧凭据；
6. API Key 只允许短暂存在于后端内存，不能进入错误或日志。

不在 R2.1 引入“静默归档连接”。若以后需要保留大量历史方案再隐藏旧连接，应单独修改产品架构和领域状态。

## 4. 后端接口设计

### 4.1 Wails 接口

保留并收口现有接口：

```text
ApplicationBootstrap() -> ApplicationBootstrapView
SaveApplicationPreferences(input) -> ApplicationPreferencesView
SaveApplicationProvider(input) -> ApplicationProviderView
DeleteApplicationProvider(providerID) -> void
PublishCreativeProfile(input) -> CreativeProfileVersionView
```

调整连接测试：

```text
TestApplicationProvider({ providerId, model }) -> ProviderTestView
```

`ProviderTestView`：

```text
providerId
providerName
providerKind
model
status                 // succeeded
latencyMs
providerRequestId
inputTokens
outputTokens
testedAt
```

失败继续通过统一桌面错误返回，不把 Provider 原始响应、请求正文或密钥送到前端。

`ApplicationBootstrapView` 必须返回：

- 当前偏好；
- 全部模型连接及 `hasCredential`；
- 每个创作方案的最新版本，而不是只返回当前默认方案；
- 最近项目。

`SaveApplicationPreferences` 必须始终处理 `defaultCreativeProfileId`，空字符串表示清除默认方案，不能因空值而跳过更新。

### 4.2 稳定错误分类

新增或补齐以下前端可处理错误码：

| 错误码 | 用户含义 |
|---|---|
| `PROVIDER_NOT_FOUND` | 连接已被删除或页面数据已过期 |
| `PROVIDER_CREDENTIAL_MISSING` | API Key 未保存或凭据库不可用 |
| `PROVIDER_IN_USE` | 连接仍被创作方案引用，不能删除 |
| `PROVIDER_UNAUTHORIZED` | API Key 无效或无权访问 |
| `PROVIDER_MODEL_NOT_FOUND` | 模型名称不存在或账户不可用 |
| `PROVIDER_QUOTA_EXCEEDED` | 额度不足或账单受限 |
| `PROVIDER_RATE_LIMITED` | 请求被限流 |
| `PROVIDER_NETWORK_FAILED` | DNS、TLS、代理或网络失败 |
| `PROVIDER_CONTENT_REJECTED` | Provider 内容政策拒绝 |
| `PROVIDER_INCOMPATIBLE` | 接口协议与所选 Provider 类型不兼容 |
| `OPERATION_TIMEOUT` | 测试或调用超时 |
| `CREDENTIAL_ROLLBACK_FAILED` | 配置失败且旧凭据未能自动恢复 |
| `CREATIVE_PROFILE_INVALID` | 三角色、模型或预算配置不合法 |
| `CREATIVE_PROFILE_NOT_FOUND` | 项目锁定的方案版本不存在 |

Provider 适配器负责把 HTTP 状态、响应错误类型和网络错误转换为领域错误；Wails 层只转换为安全中文提示。

## 5. 前端交互设计

### 5.1 模型连接

设置页左侧列出连接，右侧编辑当前连接：

- 显示名称；
- Provider：OpenAI API / Anthropic API；
- 接口地址；
- API Key；
- 测试模型；
- 保存、测试连接、删除。

交互规则：

- 新连接保存成功后立即用后端返回的真实 ID 替换前端临时 ID；
- API Key 不进入全局 Store、`localStorage`、URL 或调试输出，保存成功及页面卸载时清空输入；
- 已保存的 Key 永不回显，只显示“已安全保存”；
- 测试仅对已保存连接开放；未保存时提示先保存；
- 测试按钮在运行中禁用，并显示“正在调用指定模型”；
- 成功显示模型、延迟、Token 用量和测试时间；
- 失败显示可操作原因，不把异常交给未处理 Promise；
- 删除前二次确认；被方案引用时保留连接并提示先处理引用。

### 5.2 创作方案

创作方案页显示方案列表和当前最新版本。每个角色行包含：

- 中文角色名称；
- 模型连接选择；
- 模型名称；
- 最大输出 Token；
- 温度。

页面同时提供运行 Token 预算和上下文字符预算。发布按钮文案为“发布新版本”；发布成功后刷新版本号和创建时间。默认方案通过明确的单选或“设为默认”操作选择，允许清除。

前端和 Wails DTO 直接使用后端角色标识，不再通过不安全的字符串强制转换。

### 5.3 AgentRun 冒烟入口

R2.1 不新增完整创作页面。使用现有章节工作区提供一个开发期薄入口：

- 仅在项目存在锁定方案且当前章节可写时启用；
- 启动前显示三个角色实际使用的 Provider、模型、最大预算和“将调用真实模型”；
- 作者确认后创建并执行 AgentRun；
- 复用现有 JobEvent/快照展示状态、步骤、取消、失败和用量；
- 成功输出继续进入候选/变更集，不直接覆盖正文；
- 运行失败保留作者正文和已有候选，不自动换模型。

## 6. 数据与迁移

### 6.1 应用设置库

应用设置库继续保存：

- `app_preferences`；
- `app_provider_connections`；
- `creative_profile_versions`；
- `creative_profile_role_bindings`；
- 最近项目索引。

不增加 API Key 字段。若现有仓库缺少按方案枚举最新版本的能力，扩展 `AppSettingsRepository`，由 SQL 一次查询每个 `profile_id` 的最大版本，避免 Wails 层循环拼装事实。

### 6.2 项目库

新增迁移扩展 `agent_run_steps` 的运行冻结字段，并保证：

- 新任务所有字段非空且可独立执行；
- 旧任务尽可能从 `agent_profiles` 与 `provider_connections` 回填；
- 已完成历史任务保持可读；
- 缺失冻结信息的历史排队/失败任务标为不可直接重试；
- 迁移不读取或复制 API Key。

旧项目级连接和角色表暂不删除，避免破坏历史项目、导入任务和回滚路径。完成 R3 运行时统一后再决定清理迁移。

- 扩展 AgentRunStep 冻结快照；
- 保持 Provider 实现不依赖 Wails 或 React 类型。

- 实现按 ID/版本解析完整创作方案；
- 校验连接存在及凭据状态。

### 7.3 工作区 Agent 运行时

- 从项目方案锁定解析运行配置；
- 创建步骤冻结快照；
- 执行阶段只使用冻结快照；
- 保留旧项目配置的兼容读取；
- 冒烟任务继续使用候选隔离、取消、恢复和 JobEvent。

### 7.4 Wails 与 React

- 更新 DTO 与生成绑定；
- 修复 Bootstrap、默认方案清除和真实测试接口；
- 将设置页角色统一为三个稳定标识；

- 增加操作级加载、错误、成功、费用和用量反馈；
- API Key 仅保留在连接编辑组件的短生命周期内。

## 8. 测试策略

### 8.1 自动测试

后端至少覆盖：

- 创建连接的凭据保存与元数据失败补偿；
- 更新连接失败时旧凭据恢复；
- 删除未使用连接时凭据同步删除；
- 删除被方案引用连接时元数据和凭据均不变化；
- Provider 测试成功、未授权、模型不存在、额度不足、限流、网络失败、内容拒绝、超时；
- 方案恰好三个角色及审阅独立性；
- 多个方案的最新版本列表；
- 默认方案设置和清除；
- 新项目锁定具体版本；
- 发布新版本或修改默认方案不改变旧项目；
- AgentRun 使用锁定版本生成冻结快照；
- AgentRun 创建后修改应用连接不改变执行参数；
- 缺少方案、版本、连接或凭据时不发起模型请求；
- 旧项目兼容与数据库迁移。

前端至少覆盖：

- Bootstrap 正确还原连接、三个角色、模型和默认方案；
- 新连接保存后不再保留临时 ID；
- API Key 不进入全局状态和浏览器持久存储；
- 测试成功和各类错误正确显示；
- 发布请求只包含三个合法角色；
- 清除默认方案可持久化；
- 快速连续操作不会用旧响应覆盖新选择。

### 8.2 真实人工验收

真实 API 不进入 CI。发布 R2.1 前，在 macOS 和 Windows 各完成：

1. 创建一个 OpenAI 或 Anthropic 连接；
2. 退出并重启应用，确认连接存在且 Key 不回显；
3. 使用指定模型完成真实连接测试；
4. 发布三角色方案并设为默认；
5. 创建新项目，确认锁定方案 ID 和版本；
6. 启动真实 AgentRun，观察三个步骤、取消、恢复和 Token 用量；
7. 确认结果进入候选而非直接覆盖正文；
8. 发布方案新版本，确认已有项目及已创建任务不被改变；
9. 删除未使用连接，确认凭据库同步清理；
10. 尝试删除被引用连接，确认安全阻止并显示原因。

## 9. 验收标准

- 用户可以通过正式设置界面创建、更新、真实测试和删除连接；
- API Key 只存在于操作系统凭据库和调用期间的后端内存；
- 前后端只使用三个首版兼容角色标识，不再发生角色转换错误；
- 模型名称、角色绑定、预算和默认方案在重启后完整恢复；
- 创作方案发布后形成不可变版本，新项目锁定创建时的确切版本；
- 项目锁定版本能真实驱动 AgentRun，不依赖旧项目级手工模型配置；
- AgentRun 执行参数来自运行冻结快照，不受后续设置修改影响；
- 用户在调用前看到真实模型来源和预算，在调用后看到实际 Token 用量；
- 失败、取消或 Provider 拒绝不会覆盖正文，也不会静默切换收费来源；
- Fake/Recorded Provider 自动测试通过，macOS 与 Windows 真实人工验收有记录；
- 满足上述标准后，R3 才开始扩展 Agent Kernel、任务协议和创作质量 Harness。

## 10. 实施顺序与停止条件

建议按以下顺序实施：

1. 统一角色契约和错误分类；
2. 修复应用设置服务、凭据补偿和方案列表；
3. 实现真实连接测试；
4. 实现方案解析端口与 AgentRun 冻结快照迁移；
5. 改造工作区真实运行链；
6. 绑定 Wails 与 React 设置页；
7. 增加 AgentRun 薄入口；
8. 完成自动测试和双平台人工验收。

出现以下任一情况时不得进入 R3：

- 设置页成功但真实 Provider 请求失败；
- 项目只记录方案版本，AgentRun 仍读取另一套配置；
- 更新设置能改变已经创建的 AgentRun；
- API Key 出现在数据库、前端持久状态、日志或错误正文；
- Provider 失败会静默换模型、换连接或继续计费；
- macOS 或 Windows 任一平台无法可靠保存、读取和删除凭据。
