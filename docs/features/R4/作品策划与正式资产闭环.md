# R4 作品策划与正式资产闭环

> 状态：设计已补齐，待实现对齐与重新验收。本文规定目标契约，不表示现有代码已满足全部条款。
>
> 所属阶段：R4
>
> 设计目标：灵感经三方向或作者已有方案经缺口检查，形成适用作品方案、人物/世界与四层路线图；作者可编辑、锁定、比较和共创，确认后才写入正式资产；退出、取消、重启和并发编辑不损坏内容或重复发起付费调用。

## 1. 结论

R4 是 R3 Agent Kernel 之上的业务闭环。内核只产出带谱系的候选和质量结果；应用层负责输入装配、创作状态、候选审阅、影响分析、Action 和正式确认。生产界面以 `prototype/` 为视觉与交互基准。

```text
灵感 → 三套方向 → 作者选定方向（R5 可选试写后反馈）
或：作者已有方案 → 缺口检查与适用阶段复用
→ 作品方案 → 人物/世界 → 四层路线图
                                                        ↓
                          差异、影响与逐项审阅 → 确认作品档案
                                                        ↓
                            ChangeSet → 类型表 + StoryAsset revision
```

补齐的关键边界：

- 输入必须包含实际选中的上游版本，不能始终只传意图和整套方向；
- 候选正文、审阅选择、字段锁、会话状态和运行结果各自有版本，不用旧会话整行覆盖新编辑；
- 执行完成不等于质量通过，结果选择不依赖内部节点名或 Artifact 顺序；
- 生成、恢复、取消、项目切换共用既有 job lease、store generation 和 Kernel；
- 确认事务同时检查版本、依赖、锁、质量、选择和 canonical head，不能只校验前端摘要；
- UI 必须接通各项操作，不能用只读文本、固定运行状态或浏览器临时选择代替闭环。

## 2. 范围与非目标

### 2.1 本阶段范围

- 原创创作会话、阶段轨、分步审阅与自动推进；
- 方向比较、保留、组合、单卡重做、原地编辑和明确选择；
- 作品方案、人物/世界、路线图的字段/实体编辑、锁定、接受、拒绝与版本比较；
- 实际上游输入冻结、候选依赖与 stale 影响处理；
- 绑定当前对象的 AI 共创、持久化 Action、作者定向修订；
- 硬锚点、软锚点、禁止项与稳定的跨实体引用；
- 原子入档、完整 revision 快照、来源证据、重复提交与重启恢复；
- 已入档内容的回看和继续调整：生成差异候选，确认后更新原资产 revision；
- 不隐藏既有手工或导入资产，不改变已有正文项目的正常访问能力。

### 2.2 不在 R4 实现

- R5 正文生成、选区改写与章节定稿；R6 批次；R7 完整长期记忆、历史 `retcon` 执行；
- 整书模型抽取与确认；导入作品沿用现有确定性导入能力；
- 自动把候选写入 canonical；Agent、React 或对话服务直接操作项目数据库；
- 重做 R3 内核、修改已冻结工作流/Schema/Prompt 的含义，或重新进行已完成的 R3 真实模型校准。

R4 的重新验收验证业务接线与可靠性，不以重新校准基础模型代替集成验证。

## 3. 现有基础与实现对齐范围

已有基础包括 R3 运行、预算、Artifact、质量门禁、Directive、公开投影，R1 工作区锁与运行 lease，ChangeSet、类型表，以及 R4 的领域模型、持久化、产品工作流、应用用例、绑定和驾驶舱初版。

现有模块可以复用，但“模块存在”不是完成依据。实现须按本文对齐以下端到端契约：会话初始化；单卡身份；阶段输入；锁与并发版本；最终质量结果；持久化幂等与恢复；Action 修订；无损映射；确认前置条件；UI 操作和入档后的状态刷新。第 14 节是本功能唯一实施顺序，第 15 节是验收合同；历史实现过程由 Git 保留。

## 4. 不可破坏的领域规则

1. 未确认候选只可作为显式 `provisional` 输入，不是正式事实，不能进入长期记忆或档案正式列表。
2. 阶段接受与正式入档分离；只有作者明确确认的 ChangeSet 可以写 canonical。
3. 候选 payload 和谱系不可变。编辑、合并、AI 修订都创建新版本；后台完成不替换作者正在审阅的版本。
4. 锁绑定稳定实体和字段。改变锁、删除包含锁的实体、修改被锁字段都必须经过相应确认与版本检查。
5. 结构错误、未解决硬约束、必须修复的 stale、目标过期不能通过“接受风险”绕过。
6. 自动推进只生成候选，不代替作者选择方向、接受实体或正式确认；无有效预算授权不得发起调用。
7. 恢复先查询原运行与持久化结果，不自动重新付费。不能承诺外部 Provider 恰好执行一次。
8. 质量驱动修订与作者定向修订分开建模，不把聊天意见伪造成审阅 Finding。
9. UI 只消费公开 DTO；不读内部节点 ID、数据库表、Prompt 或隐藏推理。
10. 类型表是已有资产载荷的权威来源；信封提供身份、版本、锁、来源和失效状态，revision 保存完整快照。
11. Model IO 不持有数据库事务或工作区全局锁；每次异步写入均验证 lease 和 store generation。
12. 原创会话不是所有项目的前置条件；没有会话不意味着没有正式资产或不能手工写作。

## 5. 核心架构与运行生命周期

### 5.1 模块职责

| 模块 | 职责与边界 |
|---|---|
| `internal/domain/creation` | 阶段、候选身份、锁、选择、版本前置条件、依赖与确认规则 |
| `internal/domain/assistant` | 对话目标、Action 参数冻结与状态机 |
| `internal/domain/storyasset` | 资产身份、revision、来源、锁、stale |
| `internal/application/creation` | 冻结输入、调度、结果物化、影响分析、确认映射；不复制内核执行器 |
| Agent Kernel / `internal/agentassets` | 版本化任务、Schema、Prompt、运行、用量、审阅与可恢复工件 |
| `internal/persistence/sqlite` | CAS、唯一约束、依赖边、操作回执与短事务 |
| `workspace.Service` | 项目可写性、OS 锁、store generation、job lease、取消与 draining |
| Wails / React | 薄命令绑定、权威投影、局部编辑缓冲与操作反馈 |

消费方定义小接口：会话仓储提供条件更新而非无条件整行 Save；运行端口提供 Start/Get/Cancel/显式恢复；结果端口返回确定的结果 Artifact 和质量；确认端口把全部前置条件与 ChangeSet 放入同一事务。接口不能允许调用方绕开可写会话和 lease。

### 5.2 运行启动与关闭

1. 预览装配输入、费用和权限，不创建 AgentRun，不调用模型。
2. 确认时取得当前项目的可写 job lease，冻结 `project_id/branch_id/store_generation`；短事务校验参数和依赖，预留运行槽与持久化操作记录。
3. 返回 `operation_id/run_id` 及最新投影，后台使用同一 lease 执行 Kernel。Wails 请求不等到模型完成才返回。
4. Kernel 的运行、步骤、事件、用量、Artifact 以及业务候选物化均属于该 lease 的生命周期。终态与回执落库后才释放 lease。
5. 项目关闭/切换先进入 draining，拒绝新任务，按既有工作区协议请求取消并等待安全退出；旧任务不可转向新项目的 store，也不能在 store 关闭后继续写入。
6. 取消是请求，不保证 Provider 已停止或不计费。结果已返回时仍保留工件与用量，按最终状态展示；不得因取消覆盖 canonical。

所有完成回调只携带捕获的运行上下文，不再次读取“当前项目”来选择数据库。运行失败、启动失败、取消和物化失败都有终态/可恢复回执，不能遗留永久占用的 active run。

## 6. 会话、阶段与推进

### 6.1 初始化与独立状态

`EnsureCreationSession` 仅用于可写原创项目的明确构建入口，事务内创建或返回唯一的 `(project_id, branch_id)` 活跃会话。新项目首次进入时先 Ensure，再恢复和读取工作台，不以 `sql.ErrNoRows` 当业务失败。

读取档案、打开导入/已有正文项目、只读打开均不隐式创建会话。查询不到会话返回 `not_applicable` 或 `not_started`，而不是空白错误页；只读项目可查看已有会话和候选，不执行恢复写入。

状态必须分离：

- `highest_reached_stage`：已到达的最远创作阶段；
- `accepted_refs_by_stage`：作者已接受的准确版本与实体选择；
- `review_cursor`：当前查看的阶段/候选/实体/分节；回看不撤销阶段或确认；
- `archive_status`：尚未入档或已有确认档案；已有档案的待调整状态另行投影；
- `active_operation_id/active_run_id`：运行槽；不是是否存在可审阅候选的判断依据。

### 6.2 阶段与前置条件

会话增加版本化的 `entry_kind: idea | author_plan`、`source_material_refs`、`stage_applicability`、`gap_report_ref` 和 `sample_handoff_ref`。起点不是固定用户身份；已有正文继续走导入与正文入口，不因打开驾驶舱隐式创建原创会话。

- `idea` 按原三方向流程。已选方向可建立试写交接引用，冻结方向、视角/语气、关键约束、范围与来源版本；真实 `opening_sample` 生成和转正属于 R5。R4 不预建正式章节、不调用尚未验证的写作旁路，未就绪入口明确提示。
- `author_plan` 保存作者原文与 revision；本地录入不付费，AI 解析/缺口分析通过 Action 授权。标准化为同一 Proposal/PeopleWorld/Roadmap 候选载荷，保留原文范围和字段来源。已有内容只验证和补缺，不强制重生成。
- 缺口报告区分 `required / optional / conflict`，包含字段路径、原因、来源与建议动作；作者可手工补齐，无需模型也能提交合法候选。方向阶段记为 `not_applicable`，已有材料阶段为 `provided_pending_validation`，验证并接受后才进入 `accepted`，不能创建虚构方向卡或把跳过当接受。
- 显式 `ChangeCreationEntry` 绑定会话版本，预览影响并暂停活动付费流程；保留旧输入、候选和接受指针，重算实际依赖。切换后需重新授权付费，旧结果迟到不得改新起点。
- `author_plan` 的准入以必要规格、主线/结局方向、适用人物世界、有效四层路线图和引用闭合为准；资料来源可替代生成步骤，不能替代正式确认。已接受不自动锁字段，锁字段不自动接受。

#### 6.2.1 起点与材料的版本存储合同

起点和作者原文通过 `EntryRevision` 追加保存：`id / session_id / parent_id / version / kind / material / material_sha256 / created_at`。材料逐字保留，包括首尾空格、换行和 Unicode 字符；单版最多 100,000 个 Unicode rune，超限返回可处理错误，不静默截断。切换起点也追加版本，旧材料可按会话与版本 ID 读取，不原地修改或复制为正式档案。

Schema 32 新增 `creation_entry_revisions` 与 `creation_entry_heads`，使用同会话父引用、版本唯一约束和头引用外键。追加来源、移动头与递增会话内容版本在同一事务内完成，同时比较会话内容版本和运行槽版本；活动运行/操作未清理时拒绝追加。应用层后续须先展示影响、请求取消并完成对账，再以新快照提交切换，不能强行清空运行槽。保存后回到分步模式，付费预览必须重新生成。旧会话不回填虚构作者来源，继续沿用既有灵感流程。

`MaterialSpan` 使用 `entry_id / material_sha256 / start / end`，范围为左闭右开的 Unicode rune 位置。缺口报告的 `PlanGapReport@1` 绑定准确来源；必填、可选与冲突项分别表达，冲突须有来源证据；标记解决必须引用候选 ID 与内容哈希。结构校验通过及必填项都有解决引用仅代表可进入后续应用核验，不能代替候选存在性、会话归属、当前版本、质量、锁与引用闭合检查。

当前应用命令为 `SaveCreationEntry(SaveEntryRequest)` 与 `UseCreationMaterial(UseMaterialRequest)`。保存命令核对项目、会话、内容版本和运行槽版本，原子追加来源并回到 `intent`；有活动运行时拒绝保存，需先取消并完成对账。工作台返回 `entry/contentVersion/runSlotVersion/material`，编辑中的原文不被轮询覆盖，保存失败保留输入。未保存材料不能发起解析或候选复用。来源读取通过会话版本复核避免混合快照。

作者材料解析复用现有持久化候选与运行回执：`intent` 阶段保存 `KindProposal` 的 `author_material.schema@1` 分析候选，不将它误当标准方案。结果包含 `entry_id/source_hash/proposal/people_world/roadmap/gaps/field_sources`；不足以形成完整合法阶段的内容返回 `null` 与必填或冲突缺口，补齐生成继续读取完整原文。每个已提取的顶层字段必须对应原文中的唯一引文；应用层验证引文后计算 Unicode 范围，不接受模型猜测的位置。这里校验来源存在性与结构完整性，语义是否忠实仍须独立审阅和作者核对。

作者在适用阶段显式复用分析中的完整内容，得到统一 Schema 的草稿候选，保留父分析与 Artifact 引用；复用不调用模型、不自动接受、不覆盖作者已编辑候选。`author_plan` 不生成方向卡，方向阶段投影为不适用。入档时由冻结分析与当前候选重建 `PlanGapReport@1` 并重新校验：必填缺口须引用当前已确认、来源有效且未被质量阻断的阶段候选；来源冲突必须修改原文后重新解析，不能通过接受候选消除；可选项允许保持未解决。分析与标准候选均进入确认摘要，来源变更使旧分析、下游依赖和费用预览失效。报告解决状态按当前快照派生，不另外保存可被独立修改的解决标志。

`SampleHandoff` 冻结方向候选 ID/哈希、卡 ID、视角、语气、约束、目标字数与创建时间。默认值仍由需求规定为 800–1,500 字，合同允许 1–10,000 字的单场景/单章范围；过期、被替代、废弃、质量阻断或不存在的方向卡不能交接。该结构不是费用授权，也不创建正文、正式记忆或定稿字数。

| 创作阶段 | 工作台粗阶段 | 正常推进前置条件 |
|---|---|---|
| `intent` | `idea` | 非空意图或作者材料、偏好/未决定项已保存；仅在发起付费操作时要求有效费用授权 |
| `directions` | `idea` | idea 起点三卡有效并选中准确版本；author_plan 标为不适用，以作者来源进入方案，保留不等于选择 |
| `proposal` | `proposal` | 当前方案结构完整、必要分节被接受，无阻断质量/依赖/锁冲突 |
| `people_world` | `proposal` | 必要实体被接受，引用闭合，各分类已检查或有省略原因 |
| `roadmap` | `roadmap` | 四层结构有效、近期 3–10 章、引用和锚点有效、无阻断项 |
| `archive_confirm` | `roadmap` | 精确版本和实体集合已审阅，确认预览有效，等待作者入档 |
| 确认成功 | `writing` | ChangeSet、资产 revision、项目状态和回执原子提交 |

阶段 rail 的“已接受”来自 `accepted_refs_by_stage`，不得把运行成功当作作者接受。退回查看不降低 `highest_reached_stage`；修改被接受版本后，其接受指针保留为旧版本证据，新版本需要重新接受，下游按第 11 节处理。

### 6.3 推进模式与费用授权

- `step_review`：每次候选生成后暂停，作者接受并确认下一阶段调用。
- `auto_advance`：作者选定方向或确认使用已有方案来源后，可在一次明确授权的适用阶段范围内连续生成方案、人物世界、路线图候选；下游可使用尚未正式确认的运行结果，但标记为 provisional，不能伪造阶段接受。
- 自动流程只在质量 `passed`、输入未变、预算仍有效且无待处理影响/冲突 Action 时继续；授权该流程的父 Action 不算冲突。`needs_review`、`blocked`、适用的方向待选择、锁定目标、费用来源变化、估算未知或预算不足均暂停。
- 自动运行不抢占审阅指针：调度器使用该流程的显式结果引用，UI 留在作者当前对象并提示新版本可用。
- 自动到达 `archive_confirm` 后，作者必须完成所有适用阶段的审阅；“全部接受”是显式命令，不因没有逐项选择而默认全包入档。
- 开启自动模式本身不授权付费。授权冻结阶段范围、输入摘要、方案版本、各角色 Provider/模型、参数、最大调用数、Token 和费用上限；包含审阅、格式修复、有界修订的最坏预算。
- 费用估算未知显示 `unknown` 而不是 0；暂停自动推进，由作者重新确认有明确调用/Token 上限的单次操作并知悉价格未知。不得只显示“预计调用次数”。
- 失败和未知结果占用的预算不得按未消费清零。切换 Provider/模型、扩大目标或重启后继续新调用，必须重新授权；不同审阅角色可使用不同模型。

自动授权冻结起始输入与允许的阶段链，而不是预知尚未生成的下游内容。每个子操作启动前，将该链前序的准确结果重新冻结为自己的输入，关联父授权与递增序号并原子扣留剩余预算；作者在链外改选/编辑上游时暂停，不静默更新授权摘要。这里只允许推进下一阶段，不能自动重生成已有且受影响的下游。锁定项作为只读保持输入不必阻断；拟写入范围与锁相交时才按锁冲突暂停。

### 6.4 恢复与结果重放

恢复仅做查询、对账、补投影与不调用模型的结果物化。持久化的 `running` 不代表进程中仍有活跃 lease。

| 数据状态 | 恢复行为 |
|---|---|
| 同进程已有有效 lease | 重新订阅原运行，允许取消；不再启动 |
| 操作已预留、尚未创建运行 | 标记可恢复；作者重新授权后使用原操作关联创建，不重新占槽 |
| 运行执行中但进程/lease 已丢失 | 标记中断/结果待核实，查询已持久化步骤和 Provider 可查询结果；禁止直接重放 |
| 运行完成且结果工件齐全、候选未落库 | 按唯一结果键物化一次候选并完成回执；不调用模型 |
| 已有候选但回执或槽未对齐 | 返回原候选，条件更新回执/释放原槽；不能清除较新运行 |
| 失败或取消且无可用结果 | 保留工件、用量和错误；清理已终结槽，允许预览新操作 |
| 外部调用是否完成无法确定 | `outcome_unknown`，先查原操作；提示可能已计费，不自动重试 |

`PreviewResume/ConfirmResume` 明确剩余节点、复用工件、未知费用和新授权。复用内核已成功步骤，不从头再跑；若该运行无法安全续接，只能显示“新建尝试”及原因，建立关联的新 attempt，不把新调用伪装成恢复。重启后自动推进授权暂停，即使旧流程设置仍为自动。

## 7. 数据、版本与并发合同

### 7.1 会话与视图

```text
CreationSession:
  session_id / project_id / branch_id / content_version
  intent_version / intent_text / preferences / locked_preferences / undecided
  advance_mode / authorization_ref
  highest_reached_stage / working_refs_by_stage / accepted_refs_by_stage
  selected_direction_ref / kept_direction_refs
  active_operation_id / active_run_id / run_slot_version
  archive_status / latest_archive_changeset_id / blocking_reasons

CreationReviewState:
  session_id / view_version
  stage / candidate_ref / entity_id / section_id / comparison_ref
```

写意图、选择、模式、接受状态使用 `expected_content_version` 条件更新；运行槽使用独立 CAS；审阅位置使用 `view_version`，不使生成输入失效。滚动位置、面板宽度等纯展示偏好可本地保存，不是业务状态。

当前会话持久化合同：`CreateSession` 原子创建或返回既有会话，不替换其 ID；`SaveSession` 使用读取快照中的 `ContentVersion` 作为预期版本，只更新作者内容并递增内容版本；`SaveRunSlot` 使用 `RunSlotVersion`，只更新运行/操作引用、运行暂停原因并递增槽版本。版本冲突不自动重放作者命令，返回可识别的冲突提示。完成/恢复清槽还须核对原 run ID；只允许对此幂等清理作有界重读重试。入档清除暂停原因时，在同一事务中校验内容与槽两个版本。Schema 29 为旧会话初始化内容版本 1、槽版本 0，不改既有内容。该持久化对齐不代表审阅状态、前端完整 expected-version 命令或其余确认前置条件已经完成。

`working_refs_by_stage` 是作者选作后续工作的候选，不同于正在查看的 `review_cursor`，也不等于已接受的版本。显式 `UseCandidateVersion` 才切换工作基线；比较或打开新结果不切换。首次生成与自动流程使用独立的流程结果引用供作者选择，不能通过省略工作指针回退到“最新一条”。

运行启动冻结内容、候选和锁版本；完成时只追加结果、更新自己的操作记录并条件释放自己的槽，不用启动时会话快照覆盖新意图、模式、选择或审阅位置。若输入已经改变，新结果保留为 stale，不自动推进或转为当前候选。

### 7.2 候选与审阅元数据

```text
CreationCandidate（不可变）:
  candidate_id / logical_candidate_id / version / session_id / kind / stage
  parent_candidate_refs[] / supersedes_candidate_ref
  origin: author | model | mixed | import
  run_id? / result_artifact_id? / workflow_ref? / schema_ref
  payload / content_sha256 / dependencies[]
  execution_status / quality_status / quality_evidence_refs[]

CandidateReview（版本化）:
  candidate_ref / review_version
  selected_entity_ids[] / rejected_entity_ids[] / checked_categories[]
  field_locks[] / accepted_sections[] / impact_resolution_refs[]
  stale_state / impact_refs[]
```

`candidate_ref` 包含 ID、版本与内容哈希。原始生成、人工编辑、组合和修订均可比较；作者版本不伪造 model origin。`selected/superseded/discarded` 是审阅关系，stale 是独立有效性，不能用单一 status 相互覆盖。discard 是保留历史的放弃标记，不删除工件。

候选的质量字段记录生成时结论；后续复核是另一个不可变、绑定 content hash 的评估记录，审阅元数据引用它，不覆盖原结论。`QualityAssessment` 与风险接受记录的版本也进入确认前置条件。

### 7.3 方向身份与选择

初始 `direction_set` 恰好包含三张有稳定 `direction_id` 的卡。命令的方向引用为 `(candidate_ref, direction_id)`，后端校验卡确实属于该版本；只传整套候选 ID 不足以选择方向。

保留列表持久化，重启可恢复；选中列表恰好一张。单卡重做以一张目标卡为范围，生成新的整套候选版本，其余两卡内容/ID 保持；目标卡保持逻辑 ID、拥有新版本内容。组合要求至少两张保留卡的精确引用，生成独立 `direction` 候选，不静默替换原三卡；组合结果也需作者明确选中。选择版本变化会触发实际下游失效。

### 7.4 字段锁与新版本

锁记录 `entity_id + schema_field_path + value_hash + review_version`。路径由服务端 Schema 白名单生成；数组通过稳定实体 ID 寻址，不把 `/characters/0/name` 当作跨版本身份。锁定父实体意味着其全部后代受保护，禁止通过删除、换 ID、排序或类型转换绕过。

生成前冻结锁及保留值并装配到输入；生成后先对原始模型结果与基线做差异检查，再按合法目标范围合并、复制未修改字段和锁元数据，最后做完整 Schema、引用与硬约束校验。模型改变锁定值或目标外内容时结果进入冲突待审，不能先覆盖回旧值再掩盖违规。格式修复也不能突破这些规则。

人工编辑同样校验 expected candidate/review version 和锁。锁变化不会改写旧候选的历史锁快照；新版本继承适用的锁，若目标或锁在执行期间改变，旧结果不得自动选用。解锁是显式作者命令；AI 请求解锁必须先形成 Action。

### 7.5 持久化操作回执与幂等

```text
CreationOperation:
  operation_id / project_id / branch_id / command / idempotency_key
  arguments_hash / frozen_input_ref / authorization_ref
  base_versions / status / run_id? / result_refs[] / changeset_id?
  error_code / created_at / updated_at
```

数据库唯一键为 `(project_id, branch_id, command, idempotency_key)`；预留操作与运行槽在同一短事务完成，运行与操作关联唯一。相同键不同参数返回冲突；相同参数返回原运行/原结果，不依赖内存缓存。对重复请求先核对原参数并读取回执，不因当前 head 已前进而重新执行；对首次请求再检查当前版本。

操作状态为 `reserved/running/recoverable/succeeded/failed/canceled/outcome_unknown`，只按核实结果转移；创建超时不能直接把 running 记成 failed 并释放重跑权限。同一项目/分支至多一个创作生成操作占用运行槽，DB 条件更新保证并发安全，不用先查再存实现互斥。

创建运行与候选物化都有稳定操作关联；候选结果唯一键至少覆盖 `(run_id, result_artifact_id, candidate_kind)`。跨重启、重复事件和并发确认不会产生第二份业务结果。外部网络不在本地事务内，未知结果按第 6.4 节处理。

### 7.6 正式资产与锚点

```text
StoryAsset:
  asset_id / project_id / branch_id / kind / current_revision
  typed_table? / typed_id? / origin / source_refs[]
  locks / stale_state

StoryAssetRevision（不可变）:
  asset_id / revision / full_payload / content_sha256
  source_candidate_refs[] / source_artifact_refs[] / dependency_refs[]
  lock_snapshot / change_intent / created_at

Anchor:
  anchor_id / strength: hard | soft | forbidden
  statement / scope: project | asset | roadmap_node | chapter_range
  target_ref? / from_chapter_position? / to_chapter_position?
```

`full_payload` 必须包含对应实体的完整业务字段与引用，不能只保存名称。类型行、信封当前 revision 与 revision 快照在同一事务维护；已有带信封资产的手工编辑也走统一应用写入合同，不能造成双份载荷分叉。尚无信封的旧类型行正常展示，不伪造来源；后续编辑需纳入信封时记录真实的当前快照与未知历史边界。

锚点作用域使用稳定引用或明确的全局章序区间，禁止把 `scope_hint` 文案、标题猜测当作已解析引用。未解析作用域可以留在候选中供编辑，但必须阻断入档。世界禁写与章节锚点都映射，不能遗漏来源分类。

## 8. 输入、工作流与输出 Schema

### 8.1 冻结输入矩阵

输入由版本化 Creation ContextAssembler 装配为 Manifest；每项记录来源类型、对象 ID、版本、哈希、选择范围、用途与省略原因。没有入档的上游标为 `provisional`；已有正式资产按 `canonical` 引用具体 revision。所有影响生成的材料和锁都进入输入摘要，不能只引用会话 ID。

| 操作 | 必须冻结的输入 |
|---|---|
| 初始三方向 | 意图/偏好版本、作者约束、已确认且适用的背景资产（如有） |
| 单卡重做 | 上述输入、目标卡、其余卡用于差异比较、锁与保持项 |
| 方向组合 | 上述输入、被保留并选作组合源的每张卡准确版本、组合指令 |
| 方案生成/补齐 | 意图/约束、起点；idea 使用唯一选中卡，author_plan 使用作者方案来源与缺口报告；不以未选整套方向或虚构卡替代 |
| 人物世界 | 意图/约束、适用的选中方向或作者方案来源、方案具体版本和已接受/流程选用范围 |
| 路线图 | 意图/约束、适用的选中方向或作者方案来源、方案、人物世界及其实体选择、锚点/禁写、已有高层和近期边界（如有） |
| 定向修订 | 不可变基线 Artifact、目标字段/实体、作者指令、保持项、锁、该基线的实际依赖与新授权 |

预算不足以容纳必须输入时阻断预览，不静默省略锁、必要上游或禁止项。候选实体之间的引用必须闭合；排除人物后依赖其关系/路线图不能继续当作有效。

试写交接只导出局部输入引用，不把示例写入正式档案；R5 返回的样稿和反馈若被作者选作策划参考，必须作为 provisional Artifact 明确加入 Manifest，不把正文假设当作已确认世界规则。其来源变化触发相同 stale 机制。

### 8.2 版本策略与工作流

已发布的 `story.directions@1`、`story.proposal@1`、`story.people_world@1`、`story.roadmap@1` 和旧 Schema 保持原定义哈希。对齐后发布以下新版本，不原地扩改旧工件解释：

| 新工作流 | 输出合同 | 行为 |
|---|---|---|
| `story.directions@2` | `story_directions` v2 | 生成三卡或显式单卡重做/组合模式，独立审阅 |
| `story.proposal@2` | `story_blueprint` v3 | 方案生成、独立审阅、最多一次质量修订、修订后复核 |
| `story.people_world@2` | `story_cast` v2 | 生成人物世界、独立审阅 |
| `story.roadmap@3` | `story_roadmap` v3 | 四层规划、故事弧目标、独立审阅 |
| `story.author_revision@1` | `story_candidate_revision` v1 | 作者定向修订四类候选，范围校验与独立审阅 |

族仍为 `story.foundation` 与 `story.roadmap`。R3 `quality.blueprint` v1/v2、`story_blueprint` v1 和既有作者修订定义不变。产品方案 v3 的生成、审阅、质量修订与复核必须绑定一致的产品 Schema，不能把 v3 输出送入只接受旧六字段的修订校验器。

故事弧目标扩展使用路线图 v3 和对应新工作流；已有路线图 v2 工件与冻结定义保持不变，不把缺失目标解释为空且已通过。新候选确认前补齐或显式处理适用字段，历史正式档案仍可访问。

已有方案新增 `story.author_material@1`（`author_material.schema@1`，解析与独立审阅）及 `story.author_proposal@1`、`story.author_people_world@1`、`story.author_roadmap@1`（当前分别使用 story_blueprint/story_cast/story_roadmap 的 v2 Schema，补缺与独立审阅；上表 v3 扩展仍待对齐）。上述工作流装配准确的来源版本与原文，后续阶段再加入上游候选；不改变依赖选中方向的冻结工作流。解析预算上限为 30,000 token，具体运行仍受所选模型、角色和项目预算约束；必需来源无法装入上下文时失败，不静默裁剪作者材料。缺口与来源的存储、验证和入档合同见第 6.2.1 节。

既有方案专用修订链路补齐显式基线输入时，发布 `story.author_revise@2`，声明 `$base/$directive` 选择器；`story.author_revise@1` 的定义与哈希保持不变。基线内容必须重新计算哈希并与冻结摘要一致，不能只校验摘要格式。该兼容版本仍使用方案专用合同，不代表上表四类候选通用修订、基线工件持久化与独立审阅已经完成，也不替代其验收。

新修订任务能力为 `revise_story_candidate`，继续在同一 Kernel 注册与调度；Schema 用 `candidate_kind + payload_schema_ref` 判别目标载荷，领域校验分发到对应版本的具体类型，不把任意 JSON 当合法输出。旧任务及运行恢复路径保持兼容。

每个工作流冻结角色、异构模型、Prompt、Schema、参数及预算。项目级规划使用项目/分支目标，不创建占位章节；若现有任务输入含章节专有必填，增加兼容的项目目标适配与校验，不能伪造 chapter/revision ID，也不新建平行运行时。

### 8.3 输出字段与身份

所有实体/节点 ID 在同一候选内唯一、稳定、可被引用，编辑名称不改变身份。下列为必要业务字段；具体持久化类型由 Schema 注册表承载并有完整 fixture。

| Schema | 必须表达的内容 |
|---|---|
| 方向 v2 | `mode`；卡的 ID、卖点、目标读者、题材、主角、核心冲突、成长代价、节奏、结局方向；初始恰好三卡，单卡重做/组合各一张结果及基线引用 |
| 方案 v3 | 兼容原方案含义的标题、定位、冲突、人物弧、世界规则、里程碑；创作规格、目标读者与篇幅、卖点/题材、成长代价、节奏、主支线/结局；主要人物/关系、世界/势力/地点/物品概要；全书结构、卷/弧概要与预计章节；风险、锚点、禁止项与分类省略原因 |
| 人物世界 v2 | 人物 ID、名称、角色、别名、概要、欲望/动机、恐惧、秘密、人物弧；关系用角色 ID 引用；势力、地点、物品、世界规则均有 ID 与完整描述；结构化禁写/锚点、分类省略原因 |
| 路线图 v3 | 全书/卷/弧/近期章的 ID 和显式父引用；命题、目标、冲突、转折、回报、人物变化、伏笔、节奏、章节区间与结构化锚点；弧的读者期待、不可逆变化、待兑现承诺、保留悬念和终局贡献 |

方案中的实体概要使用可沿用的逻辑 ID，人物世界补全时保留/显式关联该 ID；不能按同名自动认定同一人。概要是该实体的规划描述，入档时由选定人物世界载荷形成唯一类型行，不重复创建一份人物。

允许题材不需要的分类为空，但须有明确 `omission_reason`；“尚未决定”是候选的显式状态，不伪装成已完成字段。方案的必要创作规格、主线、结局方向和关键约束未解决时不能确认入档。人物角色枚举与现有类型表一致，不靠未知值默认降为配角。

方向差异门禁校验核心字段不得整组相同；语义差异交给独立审阅，不能把文本不相等作为显著不同的充分证据。

字段合同补充：

```text
DirectionOutput:
  mode: initial | regenerate_one | combine

ProposalOutput:
  title / positioning / core_conflict / protagonist_arc

```

概要项均包含 `id/name/summary` 及适用引用，结构概要保留卷/弧逻辑 ID 供路线图沿用。`omission_reasons` 使用 `category/reason`，仅允许可选分类；目标字数/章数是正数或明确上下界，不能用 0 表示未知。`forbidden` 与 `anchors` 共用第 7.6 节结构，前者 strength 必为 forbidden；重复 ID/矛盾强度阻断。角色沿用 `protagonist/supporting/antagonist/minor`；关系 kind、地点/物品 kind、规则作用域等必须在版本化 Schema 中映射现有领域枚举，未知值不能静默转换。必填业务内容和引用在生成与入档两次校验；编辑中可暂存不完整草稿，但保持不可推进状态。

### 8.4 四层路线图与作用域

```text
book: id, title, proposition, ending, protagonist_arc, inviolable[]
volumes[]: id, book_ref, title, goal, conflict, payoff, position, chapter_range
arcs[]: id, volume_ref, title, causal_chain, character_change,
        reader_expectation, stage_payoff, irreversible_change,
        commitments[], retained_questions[], ending_contribution,
        turns[], foreshadowing[], pacing, position, chapter_range
near_term_chapters[3..10]: id, arc_ref, title, goal, conflict, outcome,
                         turns[], foreshadowing[], pacing, anchors[],
                         position, chapter_position
```

`position` 是同父节点内连续顺序，`chapter_position` 是全书章序；`chapter_range` 使用同一章序坐标。近期窗口由作者确认的起点定义，为连续 3–10 章，不能每次从第 1 章重置。每章必须指向实际弧，弧必须指向实际卷；禁止使用标题猜父节点或回退到第一卷/第一弧。父区间包含子区间，同级范围不得无说明重叠；远期规划范围可标记估计，近期范围必须确定。

各层映射为 `outline_nodes`，近期章只创建大纲节点，不预建空正文。锚点包含 `strength/statement/scope`，章节中的字符串列表不能代替三种强度和作用域。既有高层默认稳定；滚动规划只修改授权的近期范围，修改高层必须进入影响方案。

弧目标说明向读者建立的期待、阶段回报、人物不可逆变化及对终局的贡献；`commitments` 项含稳定 ID、statement、预期兑现范围及相关实体/锚点引用，`retained_questions` 项含稳定 ID、statement 和保留理由。可选列表允许为空并说明原因；不可逆变化不适用时显式标明理由，不能用填满字段代替章节或故事弧质量。

上述字段均为规划目标，不是正文已经建立或兑现的事实。R4 负责生成、编辑、锁定、审阅、确认和无损保存；R6 对照实际章节做批次/弧评估，R7 扩展跨卷承诺。不在 R4 执行正文补查、章节审阅裁决或长期记忆提取。mapper、完整资产信封与投影必须保留目标及稳定引用，不能把它们压成不可追踪的一段摘要。

### 8.5 执行结果与质量

内核/公开应用适配返回稳定的 `WorkflowResult`：`run_id/result_artifact_ref/payload_schema_ref/revision_artifact_ref?/quality_status/review_refs`。结果引用由冻结工作流的结果出口声明，不能由业务层搜索 `architect` 节点、取第一个 Artifact 或拼内部节点名。

- 无修订时结果是通过输出校验的初稿；有修订时结果指向明确选定且绑定有效评估的候选，完整保留产品字段。通常选择改善后的修订稿；若修订引入问题，可保留在当前输入/约束下仍有效的前稿，不默认最后 Artifact 最好。结果投影保留选择原因、评估引用和未解决项；旧冻结工作流仍按原结果协议读取，新协议使用新版本。
- `execution_status` 和 `quality_status` 独立：`completed` 表示执行完成，不表示可推进或入档。
- `passed` 可以生成可用候选；`needs_review` 保留候选但暂停自动推进，软风险经作者明确处理后才可接受；`blocked` 保留可阅读的问题候选，禁止推进/入档。
- 结构/引用不合法的输出保留为失败 Artifact，不伪造有效候选。每节点最多一次格式修复，纳入预算；质量修订最多一次，修订后复检范围、锁、引用及原问题和新增问题；无有效可选候选则停止，不将未经验证的前稿作为恢复捷径。
- 人工编辑后的质量证据不能沿用为新内容已通过；记录为待审。确定性校验必须重跑，继承的硬问题必须被实际解决，软风险可绑定准确新版本由作者确认。

硬问题若能由确定性校验验证修复，保存新版本时记录相应证据；仍需语义判断的阻断通过 `PreviewReviewCandidate/ConfirmReviewCandidate` 付费复核，不必为了审阅重新生成候选。复核只产出绑定该版本的评估，不修改 payload。人工编辑后的普通待审与质量 blocked 分开；不得把“作者已读”当作消除硬问题的证据。

运行面板使用真实 `RunProjection` 的执行状态、公开阶段、用量与终态；产品阶段轨独立。不得固定显示 `running` 或在已完成后一直显示 `story_planning`。

## 9. 正式确认与无损映射

### 9.1 审阅与确认单位

接受单实体/分节只更新候选审阅元数据；阶段“确认并进入下一步”冻结该阶段接受指针，仍不写类型表。入档集合显式包含方案版本、各分类选择、路线图节点、锚点和省略原因；未选择不是默认全选。

预览需显示将创建/更新的资产、排除项、引用冲突、锁、影响、正式差异和来源。依赖缺失的关系/锚点必须提示补选、重映射或明确排除，不静默丢弃。

### 9.2 确认事务

`PreviewConfirmArchive` 生成不可变预览记录和 digest，绑定项目/分支、会话内容版本、候选与 review/lock 版本、实体选择、依赖闭包、影响处理记录、目标资产 revisions、canonical head 与映射器版本。

`ConfirmArchive` 提交预览 ID、digest、expected versions/head、幂等键。首次执行必须在同一个短事务内：

1. 验证可写项目、分支和预览参数未变；锁定/条件检查操作回执。
2. 从数据库重读基准，校验全部版本、选择、锁和依赖；没有未解决 `must_fix`、无效引用、质量阻断或过期影响豁免。
3. 验证被排除实体不会破坏引用闭合，检查类型行/资产 head 与预览一致；禁止用一次预览哈希替代这些当前条件。
4. 按拓扑排序应用 ChangeSet，写类型行、完整 revision、来源/锁/依赖。
5. 原子更新项目资料、档案 head、会话确认指针和工作台状态，写成功回执。

任一步失败全部回滚，不出现半份档案或错误进入 `writing`。失败结果给出具体冲突对象；重新预览不是复用已过期参数。重复成功请求返回同一 ChangeSet 和结果，不重复创建实体。

### 9.3 映射合同

| 输入 | 目标与必须保留的信息 |
|---|---|
| 作品方案 | proposal 信封/完整载荷；项目标题、题材、概要；规格、风险和省略原因不可丢失 |
| 人物/关系 | 类型行 + 信封；关系通过稳定 ID 映射，不按名字猜测 |
| 势力/地点/物品 | 相应类型行 + 信封；地点所需 region 显式确定或事务内建立默认 world region |
| 世界规则 | 类型行 + 信封；完整描述、作用域、锁与版本 |
| 四层路线图 | 类型行 + 信封；全部父子引用、顺序、章序区间与载荷 |
| 各来源的硬/软锚点、禁止项 | 锚点 + 信封；强度、作用域、语句与来源，包含人物世界禁写和近期章锚点 |

候选引用先建立到正式资产 ID 的确定性映射；依赖顺序为方案身份、人物/势力/地点/物品/规则、大纲父节点到子节点、关系和依赖目标的锚点，再写完整来源/依赖关系。具体排序由引用图决定，不把锚点放在尚不存在的大纲之前。原子事务不能靠“找不到就省略”完成。

类型表没有现成字段时，必须在既有类型模型的受支持载荷/版本化迁移中保留，不仅塞进信封让正式查询永远读不到。proposal/anchor 等无对应旧类型表的独立对象由其专用载荷存储负责。

### 9.4 确认后继续调整

`latest_archive_changeset_id` 是历史引用，不是“一生只能确认一次”的布尔闩。后续确认冻结目标资产 revision，保持已有 asset/typed ID，通过更新操作产生新 revision；新增实体用创建操作。删除或解除引用必须在差异中明确选择，不因新候选少了一项而自动删除正式资产。

原档案在新候选待审、失败或 stale 时仍可读取。高层硬约束变化先声明第 11 节的变更意图；未完成安全影响处理不得以再次全包创建绕过。

确认响应返回最新项目/档案摘要、工作台投影、ChangeSet ID 和变更 asset refs。前端先更新共享 Project/AppContext 与查询缓存，再导航；读到已提交档案时不再因旧 `archive_status` 被拦回构建页。

## 10. 对话、Action 与定向修订

### 10.1 会话与付费边界

`AssistantSession` 绑定项目、分支及 `creation` 类型。消息持久化作者可见文本、当前阶段/候选/实体/字段引用、相关 Action/结果，不保存隐藏推理。切换对象后新消息使用新目标，不暗中重新解释旧 Action 的目标。

本地确定性只读解释可直接返回；若解释本身需模型调用，也必须先形成付费 Action。作者可一次确认限定目标/模型/预算的聊天授权 Action，后续只读消息在该授权内建立关联操作；越界则重新确认。已有待确认/执行中 Action 时，暂停同会话可能改变目标的后续消息；无关只读解释仍可使用。

### 10.2 Action 合同

```text
action_id / assistant_session_id / project_id / branch_id
operation / risk / target_refs[] / base_versions[]
arguments / arguments_hash / preserve_refs[] / impact_preview_ref
cost_preview / authorization_ref / idempotency_key / expires_at
state / operation_id? / result_refs[] / error_code?
```

操作包含重新生成、单卡重做、组合方向、`revise_fields`、修改锁和提出入档建议。AI 可以提出 `confirm_archive` 提案，但不能代作者确认；所有实际入档最终走第 9 节作者命令。

状态沿用架构：`pending_confirmation → executing → succeeded | failed | outcome_unknown`，待确认还可转 `rejected/expired/conflict`。参数、目标版本、锁、影响或费用变化后旧 Action 失效；不得在确认时重新获取最新目标并静默替换参数。结果未知查询原 operation/run/ChangeSet，不生成第二次执行。

工具栏直接发起的付费生成/修订/复核同样由预览创建持久化 Action，确认按钮复用授权和操作回执，不因没有聊天消息就绕过费用规则。自动流程由作者确认的父 Action 授权第 6.3 节范围内的子操作；不需要在每一阶段重复展示相同授权。取消操作的 Action 记为 failed 并带 canceled 原因，保留部分结果和用量，不伪造 succeeded。

### 10.3 可执行的修订输入与结果

1. 对所有基线版本（包括手工草稿）物化不可变 `base_candidate` Artifact，记录 Schema、完整内容、哈希与原候选谱系；人工版本不可假借旧模型工件充当基线。
2. 构造作者定向 `RevisionDirective`：准确目标、作者指令、保持项、锁和输入摘要；四类候选都可修订，不局限于方案。
3. 新工作流显式声明 `base_candidate` 与 `directive` 输入绑定，并装配到实际注册的 Prompt 变量。仅支持的 `$task/$context` 等选择器可使用；发布校验必须证明变量全部绑定，不能在模板中留下无来源的 `Directive/Blueprint`。
4. `story_candidate_revision` 返回基线引用、目标种类/Schema、完整修订 payload 和变更摘要；结果出口明确标记该输出，不读取任务输入或“第一个 Artifact”。
5. 服务端重新计算差异并检查实际变更落在授权范围内，未触及字段、未授权实体及锁保持；模型自述的变更列表不作为安全证据。原实体 ID 不变，新增/删除须在目标范围中显式允许。
6. 创建带 `derived_from/revises` 的新候选；审阅、差异接受与入档仍由作者执行。接受部分修改时，确定性合成新的作者候选并重校验，而非修改原 Artifact。

### 10.4 直接编辑

`SaveCandidateDraft` 保存具体候选/实体/字段补丁，绑定 candidate/review version；只保存意图不是候选草稿保存。草稿先在 UI 缓冲，服务端成功后显示新版本与未重新接受提示。冲突保留本地输入并展示比较，不能用刷新覆盖作者文字。

作者直接编辑、锁定和接受按钮本身是明确的作者命令，不必伪造 AI Action，但仍须版本校验和持久化；AI 发起同类修改则必须先建 Action。

## 11. 依赖、失效与影响选择

依赖是实际 Manifest 的有向边，不仅是硬编码的阶段链。至少覆盖意图/偏好、选中卡、方案、人物世界、路线图、高层节点/锚点、候选选择和正式资产 revisions。每边记录源版本/哈希与使用范围；单卡和实体选择使影响可以精确到对象。

上游新版本被选用/接受或正式资产被修改时，事务内标记直接影响并传播到实际依赖的下游。仅创建一个未选用的替代候选不使现有工作流全体失效；但依赖的作者硬约束或锁变化立即触发检查。生成期间输入已变的迟到结果落为 stale。

`ImpactProjection` 区分：

- `must_fix`：硬约束/锁冲突、缺失引用、Schema 无效、禁止项违反；不能豁免入档。
- `maybe_affected`：有证据的软关联变化，可经作者检查并记录具体例外。
- 无法判断的必要依赖：保守阻断，不能默认为无影响。

作者有四种处理：局部重算（新的费用授权，只重算选定范围）、保留例外（仅软影响，绑定源/目标版本和理由）、继续讨论（保持待处理）、放弃上游调整（恢复先前选用指针，不删除新版本）。处理记录不能直接把全会话 stale 清零；任一绑定版本再变则记录过期。档案确认在事务内重新验证依赖和处理记录。

已有正式内容的高层硬约束修改必须声明 `future_only`、`in_story_change` 或 `retcon`。R4 只执行有明确章节/事件生效边界、且确认不触及历史修改的 `future_only`；另外两类保留候选与冲突说明，提示 R7 尚未就绪，不降级为无条件 future_only。已有正文的项目不能假设“尚无定稿”；必要历史影响无法安全判定时阻断正式更新，历史内容保持不变。

## 12. 应用命令与权威投影

### 12.1 公共参数与返回

所有命令带明确 project/branch，已有会话的命令再带 session；Ensure 不要求事先存在 session。修改带 expected versions；付费和入档带 preview/action ID、参数摘要和幂等键。后端重新验证而非相信前端 capabilities。投影包含自身版本和事件 cursor，可完整重建，不把 React local state 当业务真相。

```text
CreationWorkbenchProjection:
  applicability / read_only / projection_version / event_cursor
  session_summary / stage_rail / review_cursor / advance_mode
  direction_refs / selected_direction_ref / kept_direction_refs
  candidate_summaries / accepted_refs / selected_entities / locks
  archive_summary / current_run / operation_summary
  pending_actions / impact / blocking_reasons / capabilities
```

候选正文经 `GetCreationCandidate` 有界读取；大型实体列表分页，运行事件按 cursor 补拉。订阅丢失、Bridge 重挂载和重复事件都能以查询投影收敛；正文/Prompt/凭据不进入日志或普通摘要。

### 12.2 命令清单

| 用例 | 命令及结果 |
|---|---|
| 初始化/恢复/查询 | EnsureCreationSession、GetCreationWorkbench、RecoverCreation、GetCreationCandidate、GetCreationOperation |
| 意图/模式/位置 | SaveIntent、SetAdvanceMode、SaveReviewCursor |
| 方向选择/保留 | SelectDirection、KeepDirection、UnkeepDirection；参数含卡引用 |
| 初次/阶段生成 | PreviewGenerateDirections/Stage、ConfirmGenerateDirections/Stage；确认立即返回运行引用 |
| 单卡/组合 | PreviewRegenerateDirection、ConfirmRegenerateDirection、PreviewCombineDirections、ConfirmCombineDirections |
| 草稿/比较/锁 | SaveCandidateDraft、CompareCandidateVersions、UseCandidateVersion、LockField、UnlockField |
| 质量复核 | PreviewReviewCandidate、ConfirmReviewCandidate；仅评估指定候选，不重新生成 |
| 选择与推进 | AcceptEntity/Section、UnacceptEntity/Section、AcceptAll、AdvanceStage；不隐式写 canonical |
| 影响处理 | PreviewResolveImpact、ConfirmResolveImpact；付费重算复用生成授权 |
| 正式入档 | PreviewConfirmArchive、ConfirmArchive；返回最新项目与工作台 |
| 共创 | SendCreationMessage、GetAssistantSession、ConfirmAssistantAction、RejectAssistantAction |
| 运行 | CancelCreationRun、PreviewResumeCreationRun、ConfirmResumeCreationRun、事件订阅/补拉 |

预览可以持久化无付费的冻结记录，但不能启动运行或改 canonical。错误至少区分 not_applicable、read_only、version_conflict、stale_dependency、locked_target、quality_blocked、budget_required、operation_in_progress、outcome_unknown 和存储故障；返回可执行的恢复建议，不暴露底层 SQL 文本。

## 13. 界面与绑定验收合同

布局沿用原型设计 Token 和组件：顶部阶段轨，左侧分类/实体，中央结构化编辑和差异，右侧当前对象 AI 共创，底部保存/重新生成/推进，可收起运行面板。不得用新的视觉语言替换已接受原型。

| 界面操作 | 必须接通的行为 |
|---|---|
| 首次打开原创项目 | 初始化成功进入意图；无会话、只读、导入路径分别展示真实状态 |
| 三卡选择 | 每卡提交自己的 direction ID；选中、保留、比较、单卡重做和组合均可用并持久化 |
| 方案/人物/世界/路线图 | 字段可编辑，分类/实体导航、锁、逐项接受/拒绝、全部接受、版本选择与差异比较 |
| 保存草稿 | 保存中央正在编辑的对象；dirty、保存中、成功、冲突可见，不仅保存意图文本 |
| 自动推进 | 可设置模式并确认流程预算；显示暂停原因，不能隐藏中间候选或代替方向选择 |
| AI 面板 | 消息绑定当前对象，显示真实 Action 的目标、基线、保持项、影响、费用、确认/拒绝/过期/未知结果 |
| 运行面板 | 确认后立即可见，真实事件/查询更新，取消与恢复可用，完成后主动打开候选，不硬编码状态 |
| 入档 | 预览全部选择和差异；成功先刷新权威项目状态，再打开对应正式资产 |
| 档案访问 | 只过滤未确认候选；已存在的手工/导入/历史正式行始终可看，不用 R4 archive_status 全页封锁 |
| 退出/重启 | 恢复同一候选、分节/实体、锁、保留卡、Action 和运行；不自动续费 |

无模型配置、Schema/运行失败必须展示真实错误，不用示例数据伪装成功。已有正式档案与待调整候选同时存在时清楚区分。R5/R6/R7 尚未实现入口显示未就绪；本节属于 R4 的操作在收尾前不能以永久禁用按钮算作完成。

R4 交互补充：驾驶舱根据权威状态展示进展、待决定、下一步；已有正文不固定显示创意构建中。支持作者方案入口、材料来源/缺口、阶段不适用、明确范围批量接受；接受、锁定、正式入档独立。首页实验室入口移至设置高级分类。窄窗口阅读和试写真实运行在 R5 接通，R6 完成批次问题归组与定位；原型的目标交互遵循 `prototype/contract/design-contract.md`，不能将旧占位布局作为已满足本合同的证据。

- Domain 验证不变量；SQLite 集成验证真实事务、外键、CAS 与唯一键，不用内存 Map 代替持久化结论。

- Mapper 用完整非空字段 fixture 做候选→类型行→正式投影→revision 往返，检查丢字段、父子引用、origin 与锁。
- 并发/恢复用可控阻塞 Provider 与故障注入，断言调用次数、用量、运行槽及数据库最终状态，不靠固定 sleep 猜时序。
- 前端/Wails 集成使用实际 DTO 合同，断言第二张卡请求、运行异步返回、保存目标、Action 和确认后的共享状态；按原型验视觉/交互。
- 后续实现提交前要求 gofmt、go vet、受影响包与全仓测试、针对并发路径的 race；Windows/macOS 生产构建及关键生命周期验证。
- CI 不调用真实模型。作者业务冒烟覆盖真实界面从方向到入档，记录最小结果与用量，不提交密钥、手稿或本地数据库；R3 校准无需重做。

## 16. 迁移与兼容

- 仅新增向前迁移，编号按实施时当前最大版本顺延，不重写已发布迁移。新增字段、关系表、唯一索引和 CHECK 必须覆盖全部新旧合法任务与能力。
- 数据结构须持久化会话/审阅 CAS、稳定实体引用、锁快照、依赖边、操作回执、预览/授权、完整资产 revision 与 Action；不允许用进程内 Map 或 localStorage 代替可靠性数据。
- 旧 Schema/工作流/Prompt 定义及哈希保持不变。旧运行按原冻结定义读取/恢复，新运行固定新版本；迁移不得把旧输出标成新 Schema 已验证。
- 旧数据缺少卡 ID、父引用、锚点作用域或完整快照时，仅做有确定证据的转换；无法恢复的字段标记需作者复核，不按标题、第一弧或空对象补造正确性。
- 旧未完成候选可查看/比较；需补齐新确认合同后才能入档。已有正式档案不因新规则被删除或整体隐藏；旧不完整历史快照显示证据不足，不伪造历史。
- R5/R6 只把已确认资产 revision 与路线图作为正式事实；R4 候选若用于策划阶段输入必须明确 provisional，不进入正式长期记忆。
- 不引入 Rust、CGO、第二套运行时或并行 canonical 存储。继续复用 Go/Wails/React/SQLite 和既有工作区安全边界。

## 17. 退出标准

1. 灵感经真实入口得到三方向并产出方案、人物世界与四层路线图；已有方案可跳过方向并补缺复用。试写交接有准确状态，实际生成属于 R5；两条策划路径均有正确来源、选择、接受与锁定。
2. 各阶段使用正确上游版本；最终修订结果、质量、锁和依赖共同控制推进，不以执行成功冒充质量通过。
3. 分步/自动模式符合授权边界；任一付费/写入 Action 都可确认、拒绝、过期、恢复与追溯。
4. 首次和后续入档均原子、幂等、无损；正式页可见全部选定字段、正确父子结构及锚点，旧正式资产始终可访问。
5. 并发编辑不丢失，旧结果不覆盖当前对象；stale、锁、版本或质量阻断不能绕过确认事务。
6. 新项目首次打开、项目切换、取消、退出重启和各崩溃窗口可恢复；没有未经授权的重付费或跨 store 写入。
7. 第 13 节 R4 UI 契约与 C01–C25 全部有对应验证证据，生产代码质量检查、全仓/race 测试、双平台构建与作者业务验收通过。

只有实现对齐并满足以上标准后，才能关闭 R4、进入 R5。设计完成本身不等于功能验收完成。
