# R4 作品策划与正式资产闭环

> 状态：设计完成，实现中
>
> 所属阶段：R4
>
> 设计目标：把 R3 已验证的作品策划能力接入作者可走完的产品闭环——一句中文创意生成三套方向、完整作品方案、人物/世界与四层路线图；作者确认后才写入正式资产，作品进入可写状态；重启后可恢复。

## 1. 结论

R4 是 R3 Agent Kernel 之上的第一层正式业务。内核继续只产出带谱系的未确认候选；本阶段负责阶段编排、候选编辑、对话提案、影响标记和原子确认。

主线：

```text
创作会话与阶段状态机
→ 三套方向候选（story.foundation / story_directions）
→ 选中方向生成作品方案（复用 story_blueprint，发布产品 Schema v2）
→ 人物/世界候选
→ 四层路线图候选（story.roadmap）
→ 作者确认 → ChangeSet 写入既有类型表 + StoryAsset 信封
→ 作品进入可写；档案页展示正式资产
```

核心判断：R4 不重写人物、大纲、世界规则等已有类型表，也不把 Agent Kernel 改成对话运行时。应用层编排多次可恢复 AgentRun，把结构化候选映射为既有 ChangeSet 操作；`AssistantSession` / `AssistantAction` 只调用 R3 的作者定向修订契约。

## 2. 范围与非目标

### 2.1 本阶段范围

- 原创作品 `CreationSession` 与细粒度阶段状态机；
- 与原型视觉一致、与架构阶段轨一致的构建工作台；
- `step_review` 与 `auto_advance`；自动推进只连续生成候选；
- 三套显著不同的方向：比较、保留、组合、单卡重做、原地编辑；
- 可编辑、可锁定的作品方案、人物/世界和路线图候选；
- 硬锚点、软锚点、禁止项进入候选与确认后的正式资产；
- 候选确认映射到统一 `StoryAsset` 信封，并写入既有类型表；
- 字段/实体级 AI 调整：先形成 `AssistantAction`，确认后才调用内核或执行写入；
- 上游变更后下游 `stale`、影响说明和作者选择，不静默级联重生成；
- 原子确认、幂等、失败回滚、来源证据；
- 重启恢复：阶段、当前候选版本、锁定项、待确认 Action、运行投影。

### 2.2 明确不在 R4 实现

- R5 章节定稿、选区改写、完整正文三栏工作台；
- R6 批次、检查点、provisional 跨章上下文；
- R7 五层长期记忆、`chapter.posthoc`、`retcon` 完整影响执行；
- 导入整书模型抽取与确认（沿用现有确定性导入；抽取候选不接入本阶段确认流）；
- 把内部节点 ID、工作流拓扑或 Agent 数量做成作者必须理解的步骤；
- 自动把候选写入 canonical，或对话绕过应用用例直写 SQLite；
- 替换 R3 Harness 使用的 `story_blueprint` Schema v1。

## 3. 现有基础与必须解决的缺口

### 3.1 可复用基础

- R3：`AgentRun`、公开阶段、`RevisionDirective`、候选谱系、`quality.blueprint.v2`、`story_architect`、作者定向方案修订；
- ChangeSet：`create_character`、`create_relationship`、`create_world_rule`、`create_outline_node`、`create_story_event`、`create_fact`、`create_foreshadowing_hook` 及对应 apply；
- 类型表：`characters`、`factions`、`outline_nodes`、`world_rules`、`locations`、`items` 等；
- 工作台投影：`idea / proposal / roadmap / writing` 占位；
- 原型 `Cockpit`：方向三卡、方案分节编辑/锁定/接受、右侧创作上下文。

### 3.2 当前缺口

- 生产驾驶舱仍是“尚未就绪”占位，没有阶段轨和真实候选；
- `StoryBlueprintOutput` 只有标题、定位、冲突、人物弧、世界规则、里程碑，不够支撑产品方向卡和方案分节；
- 没有创作会话、候选版本、字段锁、待确认 Action；
- 没有 `story.foundation` / `story.roadmap` 产品工作流；
- ChangeSet 缺少势力、地点、物品、锚点、方案信封的创建操作；
- 没有下游 `stale` 计算；
- `agent_runs.task_kind` 的 CHECK 仍停留在 00019 的短枚举，写入新任务类型会失败，R4 必须扩表。

## 4. 不可破坏的领域规则

1. 模型输出永远不是 canonical。未确认候选不得出现在档案页的正式列表，也不得进入 Context Manifest 的正式来源。
2. 确认必须走 ChangeSet 短事务。失败回滚，成功才更新阶段和 `archive_status`。
3. 重新生成只产生新候选版本，不能覆盖作者正在审阅的版本。
4. 锁定字段在重新生成和作者定向修订中必须保持；要改锁定字段必须先解锁或形成高风险 Action。
5. 自动推进不得越过：正式写入、锁定内容变更、费用来源变化、无法预估费用、阻断冲突。
6. 恢复不得自动继续未重新确认的付费调用。
7. 质量修订与作者定向修订不得混用；对话建议不能伪造成 `ReviewFinding`。
8. 产品界面只消费 `CreationWorkbenchProjection`、`RunProjection` 和 `AssistantSessionProjection`，不解析内部 `node_id`。
9. 导入作品不强制进入本闭环；已有章节的项目保持现有 workbench 阶段。
10. 既有类型表仍是人物、大纲、世界规则等的权威载荷；R4 不把它们折叠成单一 JSON 大表。

## 5. 核心架构

```text
React 构建工作台
  ↓ 命令 / DTO
Creation Application Service
  ├─ CreationSession 状态机
  ├─ Candidate Store（版本、锁、谱系）
  ├─ Auto-advance 编排（只排队下一阶段生成）
  ├─ Asset Mapper（候选 → ChangeSet）
  ├─ Impact Analyzer（下游 stale）
  └─ Assistant Service（Session / Action）
        ↓ 创建 AgentRun
Agent Kernel（R3，不改主协议）
  ↓ Artifact + 谱系
CreationCandidate
  ↓ 作者确认
ChangeSet Apply
  ↓
Typed tables + StoryAsset 信封
```

模块边界：

- `internal/domain/creation`：会话、阶段、候选、锁、确认前置条件；
- `internal/domain/assistant`：会话、Action 状态机；
- `internal/domain/storyasset`：信封身份、种类、revision、来源、stale；
- `internal/application/creation`：编排、映射、影响、恢复；
- `internal/agentassets`：产品 Schema/Prompt/工作流新版本；
- `internal/persistence/sqlite`：迁移与存储；
- `apps/desktop`：薄绑定；
- React：只渲染权威投影。

`workspace.Service` 继续持有项目锁和活动 store；创作用例通过它取得可写会话，不另建项目生命周期。

## 6. 阶段状态机

### 6.1 创作阶段

原创构建使用细粒度阶段，写入 `creation_sessions.stage`，并投影到既有 `WorkbenchStage`：

| 创作阶段 | 作者文案 | 工作台粗阶段 | 主要产物 |
|---|---|---|---|
| `intent` | 灵感与创作意图 | `idea` | 意图文本、锁定偏好 |
| `directions` | 三套故事方向 | `idea` | 三张方向候选 |
| `proposal` | 作品方案 | `proposal` | 方案分节候选 |
| `people_world` | 人物与世界 | `proposal` | 人物、关系、势力、地点、规则、禁写 |
| `roadmap` | 全书路线图 | `roadmap` | 全书/卷/弧/近期章 |
| `archive_confirm` | 确认作品档案 | `roadmap` | 待确认 ChangeSet |
| （确认成功） | 可写 | `writing` | 正式资产 + `archive_status=confirmed` |

旧项目 `workbench.stage=idea` 且无会话时，打开驾驶舱即创建 `intent` 会话。导入且已有章节的项目不创建本会话。

合法前进：

```text
intent → directions
  →（至少选中一套方向）proposal
  → people_world
  → roadmap
  → archive_confirm
  → writing
```

允许回看任意已到达阶段；回看不等于撤销确认。已确认阶段的正式资产保持；若作者修改已确认内容，只产生新候选或 Action，并把下游标 `stale`。

后退：

- 未确认阶段可回到上一阶段，当前阶段候选保留为 `draft`/`superseded`；
- 已确认阶段不能用“上一步”撤销正式写入；必须走新的 Action 或 ChangeSet。

### 6.2 推进模式

```text
advance_mode: step_review | auto_advance
```

- `step_review`：每个生成运行结束后停在候选审阅；
- `auto_advance`：运行成功且质量非 `blocked` 时，自动为下一阶段创建生成运行；在下列条件暂停并进入 `needs_confirmation`：
  - 即将写入正式资产（进入 `archive_confirm` 或任何 Confirm 命令）；
  - 目标含锁定字段；
  - 存在未处理冲突 / `stale` 必须修复项；
  - 费用来源变化或无法预估；
  - 作者未确认的待处理 Action。

暂停后不创建新的付费运行。重启后保持暂停，不自动续跑。

### 6.3 阶段完成条件

| 阶段 | 可进入下一阶段的最低条件 |
|---|---|
| `intent` | 非空意图文本 |
| `directions` | 恰好三张有效方向卡，且作者选中一套（或组合生成的新卡并选中） |
| `proposal` | 当前方案候选通过结构校验；锁定字段完整 |
| `people_world` | 至少一名主角、至少一条世界规则；禁写项允许为空但必须显式记录“无”或省略原因 |
| `roadmap` | 全书层 + 至少一个卷 + 至少一个故事弧 + 近期 3–10 个章节范围节点 |
| `archive_confirm` | 作者确认；ChangeSet 全部 apply 成功 |

字段数量不是完成度。题材不需要的地点、势力可以省略，候选里记录 `omission_reason`。

## 7. 数据模型

### 7.1 `CreationSession`

每个原创项目至多一个活跃会话。

```text
session_id / project_id / branch_id
stage
advance_mode
intent_text
locked_preferences[] / preferences[] / undecided[]
selected_direction_candidate_id
current_candidate_id_by_stage
active_run_id
blocking_reason
review_cursor          // 当前分节/实体 ID，供恢复审阅位置
updated_at
```

会话不是 AgentRun。一次阶段生成对应一次内核运行；会话保存当前运行引用以便恢复和取消。

### 7.2 `CreationCandidate`

```text
candidate_id / session_id / stage / kind
version
parent_candidate_id / supersedes_candidate_id
run_id / artifact_id / workflow_id / workflow_version
payload_json / payload_schema_id / payload_schema_version / content_sha256
lock_map            // JSON Pointer → locked
status              // draft | selected | confirmed | superseded | stale | discarded
stale_reason / impact_refs[]
created_at / updated_at
```

`kind`：`direction_set` | `direction` | `proposal` | `people_world` | `roadmap`。

三套方向作为一次 `direction_set` 运行产物，内含三张 `direction` 卡；组合或单卡重做产生新版本，不改正在看的版本。

谱系：候选引用 Agent Artifact；修订候选继续使用 `derived_from` / `revises`。应用层额外记录 `parent_candidate_id`，供工作台比较，不要求 React 读 Artifact 表。

### 7.3 `StoryAsset` 信封

确认后写入：

```text
asset_id / project_id / kind / status
current_revision
origin                 // author | model | import
source_candidate_id / source_run_id / source_artifact_id
typed_table / typed_id   // 映射到既有行；方案/锚点可为空表名
locked
stale
created_at / updated_at
```

`kind` 至少包括：`proposal`、`character`、`relationship`、`faction`、`location`、`world_rule`、`item`、`outline_node`、`hard_anchor`、`soft_anchor`、`forbidden`、`story_event`。

`story_asset_revisions` 保存该 revision 的 payload 快照与内容哈希，供差异和过期检测。类型表仍是档案页读写的权威载荷；信封负责身份、来源、锁和 stale。

R4 不把历史手工创建的人物回填为信封；仅本阶段确认路径和本阶段之后的确认写入创建信封。档案页对无信封的旧行仍可展示，但不显示来源谱系。

### 7.4 锚点

```text
anchor_id / asset_id
strength            // hard | soft | forbidden
scope_kind          // proposal | roadmap_node | chapter_range
scope_id
statement
created_at
```

硬锚点与禁止项确认后必须能进入后续章节 Context Manifest；R4 只负责持久化与信封，R5 负责生成期逐项对照。

### 7.5 四层路线图

映射到既有 `outline_nodes`：

| 层 | OutlineLevel | 规则 |
|---|---|---|
| 全书 | `book` | 命题、终局、主角弧、不可破坏设定 |
| 卷 | `volume` | 阶段目标、核心冲突、阶段回报 |
| 故事弧 | `arc` | 事件因果、人物变化、伏笔 |
| 近期章 | `chapter` | 未来 3–10 章可执行目标；`chapter_id` 可空 |

R4 不为全书每一章预建空章节正文。近期层只建大纲节点。进入 `writing` 后，R5 再按作者选择的节点创建 `chapters`。

高层已确认内容默认稳定。R4 若作者改全书/卷/弧，只生成影响候选，不自动改近期层；近期层标 `stale`。完整 `retcon` 执行留在 R7；R4 只提供 `future_only` 的标记和下层失效。

## 8. 工作流、任务与 Schema

### 8.1 产品工作流族

| 工作流 ID | 版本 | 任务类型 | 何时运行 |
|---|---|---|---|
| `story.directions` | 1 | `story_directions` | 意图提交或方向重做/组合 |
| `story.proposal` | 1 | `story_blueprint` | 选中方向后生成方案 |
| `story.people_world` | 1 | `story_cast` | 方案候选就绪后生成人物世界 |
| `story.roadmap` | 1 | `story_roadmap` | 人物世界候选就绪后生成路线图 |

它们属于架构中的 `story.foundation` 与 `story.roadmap` 族。工作流 ID 是不可变注册表键；族名只用于文档和后续统计。

每个产品工作流节点仍走 R3 内核：冻结、公开阶段、预算、取消、恢复。默认节点形态：

```text
story_architect（产品 Schema）
→ review_bundle（策划审阅，planner/continuity 槽按节点冻结）
→ quality_gate
→ bounded_revision（planner 槽，最多一次）
→ candidate_ready
```

`story.proposal` 复用 `quality.blueprint.v2` 的审阅/修订能力，但绑定产品 Schema v2 与产品 Prompt，发布为新工作流 ID，不修改 `quality.blueprint` v1/v2 定义哈希。

作者定向修订继续使用既有 `author_revise_blueprint` 入口或等价 Directive；R4 只构造 Directive 与费用确认。

### 8.2 新任务类型

| 标识 | 输出 |
|---|---|
| `story_directions` | 恰好三张方向卡 |
| `story_cast` | 人物、关系、势力、地点、规则、禁写、省略原因 |
| `story_roadmap` | 四层节点与锚点 |

`story_blueprint` 保持稳定。产品方案使用 Schema 版本 2，Go 类型为超集：旧 Harness 仍校验 v1 必填字段。

### 8.3 方向 Schema `story_directions.v1`

```text
directions[3]:
  id
  hook              // 卖点
  genre
  protagonist
  core_conflict
  growth_cost
  pacing
  ending
```

确定性门禁：

- 长度恰好为 3；
- 每张卡七字段非空；
- 任两张在 `{hook, protagonist, core_conflict, ending}` 上不得整组相等；
- 至少两组字段在三张之间取值不同（避免换词复述）。

失败则节点失败，允许一次同节点格式修复；仍失败则运行失败，不写候选。

### 8.4 方案 Schema `story_blueprint` v2

在 v1 字段之上增加：

```text
sell_point
genre
growth_cost
pacing
ending
subplots[]
forbidden[]
anchors[]: { strength, statement, scope_hint }
```

v1 必填仍必填。产品工作台分节映射：

| 分节 | 字段 |
|---|---|
| 故事定位 | `positioning` + `sell_point` + `genre` |
| 人物弧 | `protagonist_arc` |
| 世界规则 | `world_rules` |
| 主线 | `core_conflict` + `major_milestones` |
| 支线 | `subplots` |
| 结局 | `ending` |
| 禁写项 | `forbidden` |

作者编辑改的是候选 payload，不是内核 Artifact。保存草稿创建新候选版本，`parent_candidate_id` 指向被编辑版本，`run_id` 可空，`origin=author`。

### 8.5 人物世界 Schema `story_cast.v1`

```text
characters[]: name, role, aliases, summary, motivation, fear, secret, arc
relationships[]: source_name, target_name, kind, label, strength
factions[]: name, summary, goal
locations[]: name, kind, summary
world_rules[]: name, description, scope_type
forbidden[] / omission_reasons[]
```

角色枚举必须落入既有 `protagonist | supporting | antagonist | minor`。确认时名字解析到同 ChangeSet 内 `create_character` 的 `target_id`，复用导入抽取的关系解析策略。

### 8.6 路线图 Schema `story_roadmap.v1`

```text
book: title, proposition, ending, protagonist_arc, inviolable[]
volumes[]: title, goal, conflict, payoff, position
arcs[]: volume_ref, title, causal_chain, character_change, foreshadowing[], position
near_term_chapters[3..10]: title, goal, conflict, outcome, anchors[], position
```

确定性门禁：层次完整、position 从 1 连续、近期章数量 3–10、硬锚点非空语句。

### 8.7 公开阶段

产品运行面板继续使用 R3 公开阶段。方向/方案/人物世界/路线图的 architect 节点映射到已有 `story_planning`；完成后 `candidate_ready`。不新增作者必须学习的阶段名。工作台顶部阶段轨使用第 6 节创作阶段，与运行公开阶段分离。

### 8.8 迁移注意

`agent_runs.task_kind` 与 `agent_run_steps.capability` 的 CHECK 必须在新迁移中重建，纳入现有全部任务/能力以及 `story_directions`、`story_cast`、`story_roadmap`。不得让 SQLite CHECK 比领域 `ValidTaskKind` 更窄。

## 9. 候选到正式资产的映射

### 9.1 确认单位

作者可以：

- 在阶段内接受单个实体（人物、规则）——只把该实体标为 `selected`，仍不写入类型表；
- 使用「确认并进入下一步」：把当前阶段全部 `selected`（若无逐项选择，则当前候选整包）标为阶段确认，**仍不写类型表**；
- 仅在 `archive_confirm` 使用「确认作品档案」：一次性把已阶段确认的候选映射为 ChangeSet 并 apply。

这样避免方向尚未稳定就写入人物表。阶段确认是会话状态；档案确认才是 canonical 写入。

例外：作者在档案页手工新建人物等，仍走既有 workspace 直写 API；那是作者主权编辑，不属于本闭环的 AI 候选。

### 9.2 `archive_confirm` 映射表

| 候选 | ChangeSet 操作 | 类型表 / 信封 |
|---|---|---|
| proposal | 新 `create_story_asset`（kind=proposal）+ 更新 `projects.title/genre/summary` | 信封 + projects |
| characters | `create_character` | characters + 信封 |
| relationships | `create_relationship` | character_relationships + 信封 |
| factions | 新 `create_faction` | factions + 信封 |
| locations | 新 `create_location` | locations（若无 region，先确保默认 world region） |
| world_rules | `create_world_rule` | world_rules + 信封 |
| forbidden / hard / soft anchors | 新 `create_anchor` | 锚点表 + 信封 |
| roadmap | `create_outline_node`（book/volume/arc/chapter） | outline_nodes + 信封 |

同一 ChangeSet 内按依赖排序：方案信封 → 人物 → 势力/地点 → 关系 → 规则/锚点 → 大纲树。失败则整单冲突/回滚，会话留在 `archive_confirm`，不部分进入 `writing`。

幂等：`ConfirmArchive` 提交 `candidate_digest` + `idempotency_key`。相同键重复提交返回同一结果；摘要变化则拒绝。

### 9.3 确认后的工作台

- `archive_status = confirmed`
- `workbench.stage = writing`
- 档案页读取类型表，能看到人物、世界、大纲；
- 驾驶舱改为只读回看 + “继续调整”入口（产生新候选/Action，不再是空白占位）。

## 10. 对话、Action 与作者定向修订

### 10.1 会话

`AssistantSession` 绑定 `project_id + branch_id + session_kind=creation`。切换作品必须换会话。不保存隐藏推理。

消息只存作者可见文本、绑定的 `target_ref`（阶段/候选/字段路径）、关联 `action_id`。

### 10.2 Action

```text
action_id / session_id / project_id / branch_id
operation / risk
target_refs[]
base_versions[] / arguments / arguments_hash
idempotency_key / estimated_cost
state / expires_at
result_refs / error_code
```

R4 允许的 `operation`：

| operation | 风险 | 确认后做什么 |
|---|---|---|
| `regenerate_candidate` | 付费 | 新 AgentRun，新候选版本 |
| `revise_fields` | 付费 | 构造 `RevisionDirective`（author_directed）并运行 |
| `combine_directions` | 付费 | 以保留卡为源运行方向工作流 |
| `edit_locks` | 低 | 只改 lock_map，不调用模型 |
| `confirm_archive` | 正式写入 | 禁止由 AI 直接执行；只能由作者命令触发 |

只读解释（比较两套方向、说明影响）可以直接返回，不建 Action。任何付费、写入、改锁、改费用来源必须先建 Action。

状态机与架构 4.5 一致。`outcome_unknown` 先查询原运行/原 ChangeSet，禁止无条件重放。

字段路径必须来自服务端允许列表（Schema JSON Pointer）。前端不能提交任意路径。

### 10.3 直接编辑

作者在中央区改候选文本是本地草稿命令 `SaveCandidateDraft`：无模型调用、新候选版本、`origin=author`。锁定字段拒绝草稿写入，除非先解锁。

## 11. 影响分析与 stale

应用层维护候选/资产依赖：

```text
intent → direction_set → proposal → people_world → roadmap
```

上游内容哈希变化后：

1. 计算实际依赖的下游候选与已确认资产；
2. 标记 `stale`，区分 `maybe_affected` 与 `must_fix`；
3. 返回 `ImpactProjection`：范围、证据摘要、是否触及锁定/已确认、预计重算费用；
4. 作者选择：局部重算、保留为例外、继续讨论、放弃上游修改。

不得自动开新的付费运行。已确认正式资产不因下游 stale 被删除或改写。

R4 的高层路线图修改一律视为 `future_only`：只允许失效未写正文的近期层候选；不提供改写历史定稿的 `retcon` 执行（此时尚无正文定稿）。

## 13. 用户界面

生产驾驶舱替换占位页，对齐原型 Token 与组件，并补齐架构要求的阶段轨。

```text
顶部：作品名、阶段轨、完成提示、阻断原因
左：当前阶段分类/实体/完成状态（方向阶段可空）
中：结构化候选（三卡或分节卡片）
右：绑定当前对象的 AI 对话 + 锁定/偏好/未决定
底：上一步、重新生成、保存草稿、确认进入下一步
可收起运行面板：公开阶段、用量、取消、查看候选
```

规则：

- 无模型连接时显示真实未配置错误，不展示示例方向冒充成功；
- 生成中禁用重复提交；运行可取消；完成后不跳转正文页；
- 比较方向使用对话框，数据来自权威候选；
- 档案页在 `archive_status=confirmed` 后展示正式资产；确认前档案页显示“作品档案尚未确认”，可链回驾驶舱；
- 未实现的 R5/R6 入口保持未就绪。

## 17. 完成标准

- 一句中文创意可生成三套可区分方向、方案、人物世界和四层路线图候选；
- 未确认内容不出现在正式档案，不进入正式 Manifest 来源；
- 档案确认后人物、规则、大纲出现在对应页，作品阶段为可写；
- 锁定字段在重生成后保持；作者编辑与 AI 修订都形成新候选版本；
- 对话修改必经 Action；重启后会话、候选、锁、待确认 Action、运行可恢复且不自动扣费；
- 上游修改只标记下游 stale，不静默重写；
- Fake/Recorded 测试与受影响包测试通过；macOS/Windows 生产构建可用。

满足后关闭本阶段，进入 R5。
