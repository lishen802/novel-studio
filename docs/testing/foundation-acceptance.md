# P0 桌面基础纵向切片手工验收

本清单保留早期基础纵切的验收项，作为当前[产品需求](../product/requirements.md)和[系统技术设计](../architecture/system-design.md)的补充，不定义或限制完整 AI 长篇创作产品的功能范围。

提交级测试命令和 CI Job 由[自动化测试基线](automated-test-baseline.md)定义。本清单只覆盖必须在真实 Windows/macOS 应用环境观察的安装、WebView、原生对话框、文件锁、恢复和跨平台行为。

本清单用于同一候选提交在 Windows 与 macOS 上的人工验收。自动化测试通过不代替本清单；每次候选发布都应记录系统版本、应用提交、执行人、日期、结果和证据路径。

## 平台专项检查

### Windows

- [ ] Windows 10/11 的 WebView2 Runtime 已安装，应用可启动。
- [ ] 项目选择器使用原生目录对话框，取消操作不改变当前工作区。
- [ ] 含盘符、空格和非 ASCII 字符的路径可创建、打开和重启恢复。
- [ ] production build 不弹出控制台窗口，不要求管理员权限。
- [ ] Defender/企业安全软件扫描后项目包仍可正常读写。

### macOS

- [ ] 在受支持的 macOS 版本与 Apple Silicon 上启动 production build。
- [ ] 项目选择器使用原生目录对话框，取消操作不改变当前工作区。
- [ ] 含空格、组合字符和非 ASCII 字符的路径可创建、打开和重启恢复。
- [ ] 未发布的自签名开发包仅用于内部验收；不把它误记为公证通过。
- [ ] Finder 复制完整项目包后可正常打开，未只复制 `project.db`。

## 数据安全执行规则

1. 所有破坏性异常测试只针对验收专用副本；先按[恢复说明](../operations/project-recovery.md)备份完整项目包。
2. 不通过填满真实系统盘模拟空间不足；使用可删除的虚拟磁盘、磁盘配额或隔离测试卷。
3. 不手工编辑 `project.db`、`project.db-wal` 或 `project.db-shm`。
4. 失败时保存应用版本、系统版本、操作步骤和脱敏日志；不得上传作者正文、API 密钥或本地数据库。
5. F-01 至 F-08 两个平台均通过后，才能勾选总体路线图中的“双平台基础验收”。
