# 织境 Story Studio 产品设计与技术架构

- 状态：当前唯一权威的产品设计与技术架构文档
- 适用范围：首个商业版本及后续兼容演进
- 相关文档：[产品需求](requirements.md)、[开发路线图](roadmap.md)

## 1. 文档职责

本文统一描述产品交互、领域模型、Agent 运行时、数据边界、桌面架构、可靠性和质量门槛。功能实现不得建立与本文平行的产品事实来源。

具体子功能开始开发时，才按需建立 `docs/features/R<阶段>/` 目录，并在其中建立一份中文名称的功能设计文档。同一阶段的多个子功能设计放在同一个阶段目录下，例如 R7 的功能统一放入 `docs/features/R7/`。不预建空阶段目录。功能发生设计变化时修改原文档，不建立单独的修复、恢复、调整或 V2 文档。纯实现缺陷只修改代码和测试。

## 2. 产品体验

织境是本地优先的 AI 长篇小说创作桌面软件。AI 默认负责构思、规划、写作、审阅和长期连续性维护，作者负责方向选择、编辑、确认、定稿、回滚和导出。

产品不是传统编辑器旁附加聊天框，也不要求作者先手工填满人物、世界观和大纲表格。结构化资产首先服务于 AI 的长期记忆和作者控制。

### 2.1 核心流程

```text
创建或导入作品
→ 创意分析
→ 三套方向
→ 作品方案与世界观
→ 全书路线图
→ 确定性上下文装配
→ 章节导演与专业状态分析
→ 正文候选
→ 独立审阅、发现合并与有界修订
→ 作者定稿
→ 章节后验与长期记忆更新
→ 下一批
```

任何 AI 输出先进入候选区。只有作者确认后，才能写入正式资产或 canonical 正文。

### 2.2 首页和应用标题

- 首页提供“从一个想法开始”“导入小说并续写”“打开项目”和最近项目。
- 未打开作品时标题栏显示产品名；打开作品后标题栏显示当前作品名称，不重复显示产品名。
- 模型设置是应用级能力，入口位于窗口顶部及原生应用菜单。
- macOS 使用原生系统菜单；Windows 提供功能等价的窗口菜单。

### 2.3 作品导航

打开作品后使用固定一级导航：

- 创作驾驶舱；
- 正文与章节；
- 审阅与候选；
- 导入与续写；
- 作品档案；
- 版本与交付。

复杂度通过二级页面展开，不在一级导航继续堆叠资产类别。

### 2.4 阶段工作台

- 创意阶段突出自然语言输入和方向候选。
- 作品方案阶段以可编辑文档呈现定位、人物、世界观、结构和禁写项。
- 路线图阶段按全书、卷、故事弧和章节范围逐层展开。
- 写作阶段以章节队列、正文编辑器和候选审阅为中心。
- 正常正文编辑时 AI 面板默认收起，可通过快捷键或选中文本唤起。
- 后端尚未实现的能力必须明确显示“尚未就绪”，不得使用 mock 数据伪造成功。

### 2.5 作品构建工作台

原创作品使用连续的“构建作品”工作台，而不是把作者送进一组互不关联的资产表单：

```text
灵感与创作意图
→ 三套故事方向
→ 作品方案
→ 人物与世界
→ 全书路线图
→ 确认作品档案
```

- 顶部阶段轨道显示当前阶段、已确认阶段、阻断原因和恢复状态；对作者展示稳定的创作阶段，不展示内部 Agent 数量或具体节点拓扑。
- 左侧承载当前阶段的分类、实体和完成状态；中央区域展示结构化候选、版本和差异；右侧为绑定当前阶段、实体、字段和选中候选的 AI 共创面板；底部保留上一步、重新生成、保存草稿和确认进入下一步。
- 工作台支持“分步审阅”和“自动推进”。自动推进只省略无风险的中间停顿，不能越过正式资产确认、锁定内容变更、费用来源变化或阻断冲突。
- 每个区块支持直接编辑、锁定、请求 AI 修改、查看前后差异和接受/拒绝；重新生成和 AI 修改都产生新候选版本，不能原地覆盖作者正在审阅的内容。
- 作者可以随时退出并恢复到同一阶段、候选版本和审阅位置。上游内容变化后，应用层计算下游影响并返回 `stale`/影响待处理投影，React 不自行推断或自动级联重生成。
- 世界观、人物和路线图的字段由作品方向与题材按需装配，不用固定字段数量作为完成度；低价值字段允许省略并记录原因。

### 2.6 正文编辑工作台

正文页面采用三栏但可收起的工作台：

```text
卷与章节树 | 中央正文编辑器 | Context/候选/AI 侧栏
```

- 左栏显示章节顺序、字数、候选、待审阅、已编辑未定稿、已定稿、连续性阻断、下游 stale 和记忆待恢复等应用层状态。
- 中央编辑器保持安静，提供自动保存、当前 revision、字数、查找、撤销/重做、版本、专注和本地排版偏好；排版、面板开关和宽度是本机视图状态，不进入作品事实。
- 选中文本后才浮出解释、审阅、润色和改写入口。AI 返回独立候选与差异，作者可以全部接受、按差异项接受、放弃或撤销已应用修改；接受产生新 revision，不修改历史正文。
- 右栏优先解释当前章节实际使用的作品规则、人物状态、时间地点、知识边界、路线图、锚点、活跃伏笔、叙事债务和省略原因，并可切换到候选和作品级 AI 对话。
- 正文生产任务用可收起的运行面板展示作者可理解的阶段、进度、用量、失败和恢复；完成后保留“查看候选”，不强制跳转或自动应用正文。
- 正文定稿成功不依赖后验模型调用。事实、状态、摘要和伏笔后验异步运行；失败时标记 `memory_pending_rebuild`，不阻断手工编辑，但下一章 AI 生成前必须预检和恢复。

### 2.7 设置界面

设置采用类似 Codex 的左侧分类导航和右侧内容区，必须提供明确的“返回应用”。模型连接、创作方案、作者模板、外观和高级设置彼此分区。

普通作者不需要理解 Provider、Token、上下文窗口或内部 Agent 名称。高级参数按需展开。

## 3. Agent 创作系统

### 3.1 设计原则

- 先验证智能体能够规划和写出可接受的小说，再扩展上层产品页面。
- 角色按能力组合，不把角色数量和具体模型写死。
- 规划、写作和审阅相互隔离；写作模型不能读取其他审阅模型的隐藏推理。
- 每一步具有版本化输入、输出 Schema、预算、超时、取消和恢复协议。
- Prompt 是实现资产，不是产品事实；Prompt 变化必须通过质量 Harness 回归。

### 3.2 初始能力角色

当前后端兼容的第一版配置槽保持：

- `planner`：作品定位、故事结构、章节目标和场景节拍；
- `writer`：根据已确认目标生成正文候选；
- `continuity_reviewer`：检查事实、状态、知识边界、时间线和伏笔。

这三个配置槽是兼容起点，不是永久固定的 Agent 数量。执行工作流由下列可组合能力节点构成：

- 故事架构：题材定位、核心冲突、人物弧和全书结构；
- 章节导演：把路线图和确定性上下文转成章节目标、场景序列、视角、人物欲望、阻力、信息释放、状态变化、锚点、禁止提前揭示项、结尾钩子和允许即兴范围；每项区分 canonical 来源与本章创作建议；
- 专业状态分析：在需要时分别输出连续性、人物动机与知识边界、伏笔与叙事债务、世界规则等短小结构化约束或风险，不直接拼写整章正文；
- 正文写作：只负责叙事正文，不同时承担最终质量裁判；
- 连续性审阅：检查事实、人物状态、知识边界、时间线和伏笔；
- 内容编辑：检查节奏、因果、人物动机、钩子、冲突和信息密度；
- 文风编辑：检查重复、套话、机械排比、总结腔、空泛修辞和其他明显 AI 痕迹；
- 记忆抽取：从作者定稿正文提取状态、事实、摘要和证据候选。

简单章节可以运行“导演 → 写作 → 综合审阅 → 修订”，重要章节可以在导演后、写作前增加专业状态分析来检查和补充导演任务，并把综合审阅拆成独立内容、连续性、人物或文风审阅。专业分析默认只提供约束和风险，正文由一个主写模型完成；多写手整章生成只有在 Harness 证明特定题材质量收益明显高于声音不一致、衔接和成本风险后，才可作为高级工作流。对外配置使用稳定能力标识，显示名称可以中文化；具体 Provider 和模型由版本化创作方案绑定。写作与审阅必须能够使用不同连接或不同模型。

### 3.3 统一任务契约

每个 Agent 步骤接收：

- 任务类型和目标；
- 当前作品、分支和 canonical head；
- 已确认作品方案、路线图、锚点和禁止项；
- 人物、世界规则、状态、时间线、伏笔和证据；
- 作者指令；
- Provider、模型、参数、预算和输出限制；
- Prompt、工作流、Schema 和装配器版本。

输出包含结构化结果、正文或候选、风险、用量和可追踪证据。不能依靠解析任意自然语言判断领域状态。

### 3.4 创作质量闭环

长篇正文生产采用可持续重复的主循环：

```text
确定性上下文装配
→ 章节导演
→ 按需专业状态分析
→ 正文初稿
→ 相互隔离的专业审阅与确定性 lint
→ Finding Merger
→ 有边界修订
→ 候选持久化
→ 作者审阅、编辑与定稿
→ 章节后验
→ 长期记忆更新
```

`ContextAssembler` 由应用层按版本化规则选择输入，模型不得自由遍历作品或决定何者成为事实。章节导演只产出可执行叙事任务，不写正文；专业分析节点只输出有界约束和风险，主写模型负责统一叙事声音。

各专业审阅读取同一正文、原始约束和冻结 Manifest，不读取彼此结论。`Finding Merger` 是确定性应用组件，只按稳定规则去重、归类、关联证据和标出结论冲突，不新增模型问题、不改变严重度来掩盖 blocker。审阅发现必须带严重度、Unicode rune 范围或结构字段引用、证据和建议动作。自动修订只能修改未定稿候选，并保留上一个 attempt。

五类产品工作流共享同一 Agent Kernel，不建立平行运行时：

| 工作流族 | 首次落地 | 主要产物 |
|---|---|---|
| `story.foundation` | R4 | 作品方案、人物弧和世界规则候选 |
| `story.roadmap` | R4 | 全书、卷、故事弧和近期章节路线图候选 |
| `chapter.production` | R5 | 导演任务、正文候选、审阅与修订 |
| `batch.production` | R6 | 由独立 ChapterRun 组成的 3–10 章可恢复批次 |
| `chapter.posthoc` | R7 | 从定稿 revision 提取的事实、状态、摘要、伏笔和证据候选 |

工作流族是稳定用途标识，不等于某个固定节点图；Prompt、Schema、节点和条件变化继续发布不可变工作流版本。

### 3.5 创作质量 Harness

创作质量 Harness 与长篇连续性 Harness 分开建设：

- 使用原创固定种子、题材、作品规格和章节任务；
- 保存模型、参数、Prompt、工作流和 Schema 版本；
- 对比单次直出、智能体初稿和审阅修订稿；
- 对比最小工作流、增强章节导演、专业状态分析和拆分独立审阅等版本；新增节点只有在分项质量、失败率和成本证据均可接受时才能成为默认工作流；
- 自动检查结构、字数、锚点、重复、机械句式和格式；
- 人工盲评开篇钩子、阅读驱动力、推进、有效信息密度、人物动机、人物声音区分、场景感、因果、冲突、情绪递进、可读性和原创风险；
- 记录候选接受率、局部修改率、整章重写率和连续性问题。

测试结果按题材、任务和质量维度分别报告，不能用一个平均分掩盖严重短板。质量基线至少包含“同模型单次直出”，从而判断多步骤编排是否真正提升结果，而不是只增加成本。

“没有 AI 味”不能由单一检测器证明。确定性规则只作为写作 lint，最终以目标作者/编辑盲评和实际接受率为准。

### 3.6 可借鉴的外部方法与边界

可吸收成熟写作 Skill/Harness（包括 [oh-story](https://github.com/worldwonderer/oh-story-claudecode) 与 [DeterminFlow](https://github.com/alikon-art/DeterminFlow)）的工程方法：规划、写作和审阅分离；每个节点只处理边界明确的局部问题；写作前生成章节导演任务和状态快照；正文后执行确定性门禁；专业知识按任务加载；初稿与去 AI 味修订分阶段；每章更新人物状态、伏笔和时间线；主写模型与独立审阅模型分工；失败从可验证节点恢复。

不得直接照搬固定 Agent 数量、特定供应商模型绑定、大量 Markdown 文件持久化、单一 AI 检测器结论、默认扫榜或模仿特定作品，以及允许 Agent 绕过应用用例直接写项目文件的做法。生产数据继续通过领域模型、候选隔离、事务确认和版本化迁移管理。

### 3.7 上层界面的进入条件

Agent Kernel 阶段只建设三类必要薄界面：模型配置、Agent 运行观察器、候选/审阅/人工评分。创意方向、作品方案、世界观、大纲和章节创作等完整业务页面，必须在对应能力通过固定创作质量 Harness 后接入。

这不是先完成全部底层再开发界面的纯瀑布流程，而是以质量证据驱动的纵向切片：测试入口验证一个能力，随后接入该能力的正式界面，再继续下一层能力。

## 4. 领域模型

### 4.1 作品与资产

`NovelProject` 保存作品标题、阶段、目标篇幅、当前 canonical head、选中的创作方案版本和项目角色覆盖。

`StoryAsset` 统一承载作品方案、大纲、人物、势力、地点、规则、关系、时间线、事实、物品、知识边界和伏笔。资产具有类型、状态、revision、来源和证据。

路线图资产形成“全书 → 卷 → 故事弧 → 近期章节”层级。批次完成默认只新建或修订未来 3–10 章的近期层候选；高层资产保持版本稳定，只有作者确认影响方案或 `retcon` 后才产生新 revision。下层候选引用具体上层 revision，上层变化后由应用层计算实际依赖并标记 stale。

### 4.2 正文与候选

- `Chapter` 是章节身份和顺序。
- `ChapterRevision` 保存不可变正文版本。
- `DraftCandidate` 保存 AI 或导入生成的未确认候选。
- `CanonicalHead` 指向作者当前确认的正式 revision。
- 作者编辑、AI 改写和导入替换都产生新 revision，不覆盖历史。

### 4.3 方案、批次和作业

- `CreativeProfileVersion` 是应用级、不可变的角色与模型方案版本。
- 项目只保存方案版本引用、非敏感覆盖和运行冻结快照。
- `AgentRun` 表示单次可恢复智能体工作流。
- `GenerationBatch` 表示 1–50 章的有界批次；默认 3–10 章，并保存批次预检、冻结输入、检查点、熔断原因和所含 ChapterRun 顺序。
- `ChapterRun` 是批次内单章的编排记录，引用该章一个或多个 `chapter.production` AgentRun/attempt，拥有自己的 Context Manifest、用量、候选和恢复点；它不是第二套模型运行时。批次调度只协调依赖、provisional 传递与停止条件，不把多章合并为一次超长模型会话。
- `GenerationAttempt` 表示一次具体生成尝试；回退产生新 attempt，旧候选标记为 `superseded`。
- `JobEvent` 是单调事件源，`JobSnapshot` 是可恢复投影。

### 4.4 Canonical 与候选规则

- 已定稿正文和已确认资产是后续生成的事实来源。
- 未确认候选不得进入长期记忆。
- 同批前序候选可以 provisional 身份进入后序上下文，但不能成为正式事实。
- 模型调用不在数据库事务中运行。
- 定稿事务原子提交正文 revision、确认记忆、审阅摘要和版本信息。

### 4.5 对话、修改提案与幂等动作

`AssistantSession` 绑定单一作品和分支，保存作者与 AI 的公开消息、当前上下文引用和待处理 Action；不保存模型隐藏推理。切换作品后必须创建或恢复对应作品会话，不能把一个作品的对话或待处理动作复用到另一个作品。

`AssistantAction` 表示 AI 对话提出但尚未获准执行的结构化操作，至少包含：

```text
action_id / session_id / project_id / branch_id
operation / risk / target_refs
base_versions / arguments / arguments_hash
idempotency_key / estimated_cost
state / created_at / expires_at
result_refs / error_code
```

- 只读解释可以直接返回；任何写入作品、产生新付费调用、改变费用来源或修改锁定内容的操作都必须先形成 `AssistantAction`。
- 状态至少包括 `pending_confirmation`、`executing`、`succeeded`、`rejected`、`expired`、`conflict`、`failed` 和 `outcome_unknown`。
- 确认请求同时提交 `arguments_hash` 和幂等键；基准版本或参数变化时拒绝执行。`outcome_unknown` 必须先查询原操作结果，不能无条件再次执行。
- Action 执行只能调用应用用例；Agent、React 和 Wails binding 均不能直接写 SQLite、文件或模型 Provider。

字段改写和正文选区改写复用候选体系。请求必须绑定资源类型、资源 ID、稳定字段路径或 Unicode rune 范围、基准版本和原内容哈希；返回候选、差异、影响和预计费用。应用候选时再次比较 canonical head/资源版本，冲突后要求重新生成或显式合并。

## 5. Context Manifest 与长期记忆

每次 AI 调用先构造 `ContextManifest`，记录所使用的 canonical 资产、章节 revision、人物状态、事实、时间窗口、路线图、锚点、伏笔、作者指令、装配原因、预算、模型和版本。

上下文选择权属于版本化 `ContextAssembler`：它先用结构化关系、时间、近期窗口、路线图、活跃伏笔和知识边界建立候选集，再在预算内按确定性优先级装配。模型节点只能读取 Manifest 已选择的局部上下文，不能自行搜索整个项目或把未确认建议提升为事实；所有省略均记录原因。

长期记忆分为：

1. 宪法层：确认作品方案、世界规则、主线和不可违背设定；
2. 结构层：全书、卷、故事弧和章节路线图；
3. 状态层：人物、关系、物品、地点、能力和未解问题；
4. 摘要层：章节、卷和近期场景摘要；
5. 证据层：原文片段、revision、审阅发现和伏笔登记。

原始定稿正文始终是最高事实来源。派生记忆必须能够指回章节、revision 和正文证据，并支持从 canonical 内容幂等重建。

章节后验遵循独立工作流：

```text
canonical ChapterRevision
→ 事实/状态/摘要/伏笔与叙事债务抽取候选
→ 证据、有效区间和一致性校验
→ 幂等提交正式长期记忆
```

初稿、自动修订稿和未确认候选只能形成 provisional 状态，不能启动正式记忆写入。后续 revision 改变事实时，关联后验结果标记过期并从新的 canonical revision 重建；后验失败不回滚正文定稿。

长篇 Harness 使用固定种子和黄金事实/查询验证检索召回、证据支持、过期状态、上下文预算、项目体积和恢复；不使用有版权风险的真实小说。

## 6. 技术架构

### 6.1 技术栈

- Go；
- Wails v2；
- React、TypeScript、Vite；
- SQLite、WAL、Goose 版本化迁移。

Rust 只用于经过测量的性能瓶颈、Go 缺少可靠库或原生能力更安全的情况。优先独立 sidecar 和版本化 IPC，不使用未经批准的 CGO/FFI。Wails v3 稳定前不作为生产基线。

### 6.2 模块边界

```text
React UI
  ↓ DTO / Wails binding
Application Use Cases
  ↓
Domain
  ↓ ports
Persistence / Agent Runtime / Provider / Platform Adapters
```

- React 不直连 SQLite、文件系统或模型 Provider。
- Wails binding 保持薄，只做 DTO 转换、调用和事件通知。
- 领域层不依赖 Wails、React 或具体 Provider。
- Provider 适配器统一流式、错误、用量和取消语义。
- 平台适配器负责凭据库、目录、菜单、窗口和文件选择。

### 6.3 数据边界

应用数据目录保存 `settings.db`、最近项目索引、模型连接元数据和版本化创作方案。API Key 只保存在操作系统凭据库。

每部作品是独立 `.zjproject` 目录包，包含项目数据库、附件、导入原文、分支、快照、导出和可选调用工件。项目包不得保存 API Key。

项目数据库使用短事务、外键、WAL、有界忙等待和版本化迁移。禁止 GORM 自动迁移。扩大连接池或引入写入队列必须由基准测试证明必要。

### 6.4 模型运行时

统一运行时支持 OpenAI 兼容 API 和 Anthropic API，并为后续符合发布门槛的官方本地订阅运行时保留适配边界。

连接测试必须进行真实、最小费用的鉴权和模型可用性检查，而不是只检查凭据是否存在。错误稳定分类为未配置、未授权、模型不存在、额度不足、限流、网络失败、内容拒绝、上下文超限和 Provider 不兼容。失败不得静默切换模型或收费来源。

## 7. 导入、影响分析和恢复

TXT/Markdown 快速导入不调用模型，完成后正文立即可读写。整书档案由作者显式启动，内部可按章节和卷处理，但最终交付一份带跨章节证据、别名和冲突的全书候选包。

高层设定变更区分：

- `future_only`：只影响指定边界后的内容；
- `in_story_change`：由故事内事件导致状态变化；
- `retcon`：追溯修改既有事实。

影响分析先给范围、证据、风险和费用，作者确认后才能处理未定稿内容。历史定稿默认只报告冲突。

同一项目在可编辑模式下必须持有跨进程 OS 锁。锁冲突提供重试、只读打开或恢复副本。同步盘、网络目录、磁盘不足、路径过长和原子替换失败不得损坏 canonical 内容。迁移、恢复和备份必须操作完整 `.zjproject`，不能只复制数据库文件。

## 8. 前端状态、命令和事件

### 8.1 权威投影

Go 应用层提供权威工作台投影；React 不根据路由、mock 数据或本地猜测决定作品阶段、章节状态、候选是否可应用、Action 是否可执行或下游是否 stale。

至少提供以下投影边界，具体 DTO 在对应阶段功能设计中版本化：

```text
CreationWorkbenchProjection
ChapterEditorProjection
RunProjection
AssistantSessionProjection
CandidateDiffProjection
ContextExplanationProjection
```

投影只包含界面需要的结构化状态、稳定 ID、版本、摘要和动作能力，不发送无界正文、完整 Prompt、隐藏推理或内部凭据。大正文和差异按明确资源接口有界读取。

### 8.2 作者可见运行阶段

内部 Workflow Node 与作者可见阶段分离。应用层把一个或多个内部节点映射为稳定 `public_stage_id`，例如 `context_preparing`、`chapter_directing`、`prose_writing`、`independent_review`、`bounded_revision` 和 `candidate_ready`。

`RunProjection` 至少包含：

```text
run_id / public_stage_id / status / progress
current_attempt / recoverable / blocking_reason
input_tokens / output_tokens / estimated_cost / actual_cost
artifact_available / updated_at
```

React 只把公开阶段映射为作者语言。Workflow 拆分、合并或更换模型不得迫使页面依赖内部 `node_id`；诊断详情可在高级视图中单独展示节点和 attempt。

### 8.3 命令边界

直接编辑、候选应用和 AI 对话写操作使用明确命令，不使用前端字符串替换模拟持久化：

```text
PreviewAssetRewrite
ConfirmAssistantAction
RejectAssistantAction
RequestSelectionRewrite
ApplyRewriteCandidate
FinalizeChapter
```

- 预览/生成命令返回候选，不修改 canonical。
- 确认命令提交 expected version/head、参数哈希和幂等键，并在短事务中落库。
- 选区命令使用 Unicode rune 范围和选中文本哈希；正文变化后返回冲突。
- 字段路径来自版本化 Schema 或服务端允许列表，前端不能提交任意数据库路径。
- AI 生成内容的撤销通过 revision/candidate 语义实现，不依赖浏览器内存栈；纯排版与尚未保存的手工输入可继续使用本地编辑器撤销栈。

### 8.4 长任务事件与恢复

长任务异步返回，通过轻量 Wails 通知提示客户端按 cursor 拉取 `JobEvent`。客户端必须处理漏推、重复、乱序、Bridge 重挂载、事件清理和 snapshot 重建。运行面板可以收起或重挂载，但不得因此取消后台任务或丢失完成入口。

项目切换或关闭先阻止新作业并取消或等待现有 lease，禁止后台任务向已关闭 store 回写。Assistant Action、候选应用和节点人工重试同样使用 expected version/attempt 保护，拒绝旧页面或重复点击。

### 8.5 本机视图状态

面板开关、宽度、阅读布局、字号、行距、背景、专注模式和最近使用的侧栏标签属于本机视图偏好，可存应用设置或受控前端缓存；不得写入作品数据库的 canonical 资产，也不得参与 Context Manifest。跨设备恢复作品不依赖这些偏好。

## 9. 安全、隐私和成本

- 不记录或提交 API Key、订阅令牌、用户正文、本地数据库、签名证书和完整敏感 Prompt。
- 模型调用前显示来源、预算和可能费用，结束后显示实际用量。
- 参考材料只提取高层题材、结构、节奏和读者期待，不复制专名、角色关系、关键情节链、段落或可识别文风。
- 调用工件可压缩、去重和清理，但不得删除正文、候选、作者指令、必要证据或长期 Manifest。

## 10. 测试与发布门槛

- 生产功能使用测试驱动开发，覆盖领域、应用、持久化、运行时、Wails binding 和 React 交互。
- CI 不调用真实模型；使用 fake/Recorded Provider 验证状态、错误、取消、恢复和事件协议。
- Provider 发布前执行显式人工或隔离的真实 API 冒烟测试。
- Windows/macOS 均执行 production build 和关键流程验收。
- 数据迁移、旧项目打开、跨进程锁、恢复副本、磁盘满、Windows 路径和同步目录风险具有回归保护。
- 创作能力进入正式 UI 前必须通过创作质量 Harness；长篇发布前必须通过连续性 Harness。
- 商业发布前至少邀请 8 名目标作者封闭测试，其中至少 3 名具有 50 章以上长篇经验。

验证命令以仓库脚本、CI 配置和各模块测试文件为准，不在多个文档中复制易过期的命令清单。

## 11. 原型与生产界面

`prototype/` 是生产前端视觉和交互的权威参考。生产 UI 应复用其设计 Token、布局和组件结构，但原型不能成为生产运行依赖。界面调整先同步原型和契约，再更新生产实现；后端未实现能力继续显示明确的未就绪状态。
