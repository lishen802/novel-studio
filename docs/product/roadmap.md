# 织境 Story Studio 开发路线图

- 状态：当前唯一权威开发顺序
- 更新日期：2026-09-15
- 相关文档：[产品需求](requirements.md)、[产品设计与技术架构](architecture.md)

## 1. 推进原则

1. 智能体创作能力优先：先通过 Harness 证明能规划、能写、能审、能改，再扩展对应正式界面。
2. 纵向切片：每阶段只实现形成可验证结果所需的领域、应用、持久化、运行时、绑定和 UI。
3. 可靠性先于扩量：候选隔离、定稿安全、取消、恢复和费用边界先于批次数和长篇规模。
4. 质量证据过关：不以页面数量或代码量判断完成，必须有自动测试、Harness、双平台构建或作者验收证据。
5. 不平行重写：复用现有正文、revision、资产、ChangeSet、Provider、Agent Run、JobEvent、导入和恢复能力。
6. 当前阶段出现设计变化时直接修改产品文档和原功能设计，不建立单独修复计划。

## 2. 主阶段

```text
R0 测试与构建基线（完成）
→ R1 长任务与项目可靠性（完成）
→ R2 产品壳与交互基础（完成）
→ R2.1 模型基础设施收口（完成）
→ R3 Agent Kernel 与创作质量 Harness（完成）
→ R4 作品策划与正式资产闭环（当前：已有方案路径已接通，继续实现对齐与重新验收）
→ R5 单章高质量写作闭环
→ R6 3–10 章批次创作闭环
→ R7 长篇记忆、连续性与影响分析
→ R8 导入小说整书档案
→ R9 双平台商业发布硬化
→ R10 完整 V1 增强能力
```

## 3. R0：测试与构建基线

状态：已完成。

成果：

- Go、React、迁移、Provider、导入、快照和分支测试基线；
- fake/Recorded Provider；
- Windows/macOS Wails 生产构建；
- 旧项目迁移和恢复 fixture；
- 凭据、正文和本地数据库不进入仓库或测试日志。

## 4. R1：长任务与项目可靠性

状态：已完成。

成果：

- Model IO 不持有阻断正文保存的工作区全局锁；
- project/store generation 和 job lease；
- 可恢复 `JobEvent`、`JobSnapshot` 和 cursor 补拉；
- 项目跨进程 OS 锁、只读打开和恢复副本；
- 同步盘、网络目录、Windows 路径和原子写入风险处理。

## 5. R2：产品壳与交互基础

状态：已完成。

成果：

- 首页、最近项目、原生菜单、作品导航和阶段工作台；
- 应用级 `settings.db`、模型连接元数据和不可变创作方案版本；
- 标题栏、窗口关闭、设置返回和原型一致性；
- 后端未实现能力显示未就绪，不使用 mock 伪造成功。

## 6. R2.1：模型基础设施收口

状态：已完成。

目标：让后续智能体能力拥有真实、完整、可测试的模型配置与调用入口。

范围：

- API Key 使用操作系统凭据库；
- 前后端按钮绑定现有后端能力；
- 统一前后端角色标识；
- 真实连接和模型可用性测试；
- 模型名称、角色绑定和默认方案的保存与重载；
- 删除连接时同步清理凭据；
- 可理解的错误、加载、成功和费用反馈。

退出标准：

- 用户可通过界面创建、测试、更新和删除模型连接；
- 可发布包含 `planner`、`writer`、`continuity_reviewer` 的有效方案；
- 新项目固定创建时选择的方案版本；
- 使用真实模型完成一次可观察、可取消、可恢复的 AgentRun 冒烟测试；
- Windows/macOS 产品壳关键交互通过验证。

## 7. R3：Agent Kernel 与创作质量 Harness

状态：已完成。项目负责人已确认真实模型校准无问题，并同意本阶段收尾。

该结论对应已验收的冻结工作流；有界补查、审阅核验、最终版本复检和带语境的最小后验闭环属于 R5 新增范围，必须分别验证，不追认成 R3 已具备能力。复用现有 Kernel，通过版本化输出和工作流扩展，不建立第二套运行时。

目标：在继续扩展上层业务页面前，证明智能体能够稳定完成规划、写作、独立审阅和有边界修订。

范围：

- 版本化 Agent 任务协议、输入 Context、输出 Schema 和工作流；
- 规划、章节策划、正文写作、连续性审阅、内容编辑和文风修订能力；
- 将 `chapter_planner` 收口为可演进的章节导演协议，明确 canonical 来源、创作建议、场景视角、欲望、阻力、信息释放、状态变化、锚点、禁止提前揭示项和允许即兴范围；
- 角色按能力组合，不固定 Agent 数量或具体 Provider；
- Prompt、工作流、Schema、模型和参数的运行冻结；
- 原创固定种子和章节任务的创作质量 Harness；
- 单次直出、智能体初稿和修订稿对照；
- 锚点、长度、重复、机械句式、结构和格式自动门禁；
- 钩子、推进、人物声音、场景感、因果、情绪和可读性的人工盲评；
- 失败、取消、重试、预算、事件和候选持久化。
- 面向上层界面的稳定公开阶段、运行投影和事件语义；内部 Agent 节点可以演进，但不得把工作流拓扑直接暴露给产品界面。
- 区分质量问题驱动与作者指令驱动的修订输入，冻结基线、目标、保持项和输入摘要；两者都只生成候选；
- 候选 Artifact 谱系可追踪到基线、工作流和 Context Manifest，为后续差异审阅、撤销和恢复提供稳定引用；
- Harness 能比较最小工作流、增强章节导演、专业状态分析和拆分独立审阅等版本；拆分审阅使用确定性 Finding Merger，新增节点不以“更多 Agent”本身作为通过依据；
- 只建设模型配置、运行观察、候选审阅和人工评分所需的测试入口或薄界面；冻结其他非必要 UI 美化和完整业务页面扩展。

退出标准：

- 无需正式业务页面即可通过测试入口运行完整 Agent 工作流；
- 固定创意能够稳定产出结构化方案、章节细纲、正文和审阅结果；
- 修订稿相对单次直出在既定盲评和接受率指标上有可记录提升；
- 章节导演和审阅拆分等增强只有在分项质量、失败率与成本报告达到预设门槛后，才可成为 R5 默认工作流；
- 写作与审阅可使用不同模型；
- 任何失败不修改 canonical 正文或确认资产；
- 每次结果可追踪到模型、Prompt、工作流、输入版本和用量。
- R4/R5 无需读取内部节点 ID 或改造 Agent Kernel 主协议，即可观察公开阶段并请求带谱系的作者定向修订候选；
- 对应能力未达到预先定义的分项质量门槛时，不进入其完整上层业务界面开发。

## 8. R4：作品策划与正式资产闭环

状态：当前阶段。已有方案路径、试写准备入口、故事弧 v3 规划目标合同，以及绑定当前字段并转修改提案的共创对话首个切片已接通；正式规则、锚点和人物直接编辑支持按章节生效的版本修订，已审阅人物字段修改候选支持按章采用并核对来源；从最新正式人物版本发起 AI 修改、方案与路线图后续入档及语义影响分析仍未接通；继续完成只读讨论与多轮授权、更完整的修改与采用、方向组合/单卡重做、逐项接受与版本管理、驾驶舱其余交互对齐，以及整阶段重新验收。既有测试和双平台构建结果不能替代输入依赖、确认事务、恢复与完整交互的验收。R3 已完成的真实模型校准结论不变。

目标：完成灵感经三方向或作者已有方案经缺口检查，进入方案、人物/世界、路线图与正式档案的可恢复闭环；准备方向后可选试写的上下文交接，真实试写在 R5 实现。

范围：

- 原创作品多起点状态机；已有方案可跳过方向并复用已提供内容，不适用阶段不伪造接受；起点切换、来源与候选可恢复；
- 与原型一致的作品构建工作台：顶部阶段轨、左侧分类/实体导航、中央结构化候选、右侧绑定当前对象的 AI 对话和底部推进操作；
- “逐步审阅”与“自动推进”两种模式；自动推进只连续生成候选，遇到锁定字段、冲突、高风险修改、费用授权或正式写入时暂停；
- 三套显著不同的原创方向和比较、重做、组合；
- 可编辑、可锁定的作品方案；
- 人物弧、关系、世界规则、势力、地点和禁写项；
- 全书、卷、故事弧和章节范围路线图；
- 全书、卷、故事弧、未来 3–10 章的四层滚动规划规则；默认只刷新近期层，高层变化必须进入作者批准的影响方案；
- 故事弧规划表达读者期待、阶段回报、人物不可逆变化、待兑现承诺、保留悬念和终局贡献；这些是规划目标，运行期评估在 R6 实现；
- 硬锚点、软锚点和禁止项；
- 作品方案候选映射到统一正式资产；
- 字段级和实体级 AI 调整：对话先产生带目标、基线版本、差异、影响范围、费用和幂等键的修改提案，作者确认后才执行；
- 上游修改后的下游失效标记、影响说明和作者选择，不静默级联重写；
- 原子确认、幂等、失败回滚和来源证据；
- 驾驶舱按作品状态显示进展、待决定与下一步；接受/锁定/入档分离，实验室移入高级设置；原型契约与生产交互同时对齐。

原路线图 R3 的“正式资产确认与写入”并入本阶段：智能体生成作品方案后，必须由作者确认，才写入人物、世界观、大纲、关系、时间线和伏笔等正式资产。

退出标准：

- 一句中文创意可以生成并确认完整作品方案；已有方案无需生成三方向，缺口检查只要求补齐必要项；
- 起点切换和跳过步骤有真实状态与版本来源，试写入口在 R5 就绪前明确未就绪，不能解锁正式批次；接受不自动锁定，已有正文不会被固定显示为创意阶段；
- 确认内容进入对应正式资产页，未确认内容不进入 canonical；
- 路线图确认后作品进入可写状态；
- 故事弧目标经生成、编辑、确认和正式档案读取完整保留，不被当作已发生事实；候选选择绑定有效评估，不能默认最后修订版最好；
- 应用重启后能够恢复阶段、候选、锁定项、待确认动作和运行进度；
- 作者能够直接编辑或通过 AI 对话调整任一已生成对象，冲突和失效状态可见，未经确认不发生正式写入或新的付费调用；
- 阶段输入冻结实际选中的上游版本，最终修订稿和质量门禁正确控制推进；嵌套字段锁、实体选择与依赖失效不能被生成或确认绕过；
- 确认事务校验版本、锁、依赖、质量及正式资产 head，首次与后续入档保持载荷、层级、锚点和来源完整；
- 并发编辑、重复请求、项目切换与崩溃恢复不丢失作者修改、不重复物化结果，也不自动重放结果未知的付费调用；
- 运行、共创 Action、候选编辑与档案导航通过真实跨层合同验证，旧手工和导入资产不因原创会话状态被隐藏。

## 9. R5：单章高质量写作闭环

状态：未开始；依赖 R4 完成实现对齐与重新验收后，再进入功能设计与实现。

目标：生成一章达到作者可审阅、可修改和可定稿标准的网络小说正文。

范围：

- 方向后开篇试写：局部输入即可生成非正式候选，反馈回到策划，档案确认后复检并显式转正；保持正式章节准入独立，先通过质量 Harness 再接通入口；
- 最小 Context Manifest、任务/记忆可用性/预算预检，导演与审阅的结构化证据请求、应用层有界补查及不可变上下文版本；
- 章节导演任务：章节作用、起始/结束状态、关键选择与代价、适用的情节/人物/读者认知变化，以及场景序列、视角、信息释放、锚点和即兴范围；新增重要设定保持候选身份；
- 按需专业状态分析：连续性、人物动机与知识边界、伏笔与叙事债务、世界规则只输出结构化约束和风险，由单一主写模型统一完成正文；
- 章节正文候选；
- 连续性、人物动机、因果、节奏、世界规则、伏笔、重复和文风审阅；
- 拆分审阅彼此隔离，并由确定性 Finding Merger 去重、归类、关联证据和暴露冲突；
- 审阅区分硬冲突、语义不确定和偏好建议；合并后按需核验成立、不成立或证据不足，保留原发现、补查证据与争议，不以模型票数代替证明；
- 按需文风修订及项目内确认的文风约定、自有样章引用和修改偏好；仅正文的读者视角配置须经 Harness 验证，不作为固定默认拓扑，也不豁免最终复检；
- 基于目标问题、修改范围和保持项的有界修订；每版执行确定性检查和按影响范围的语义复检，记录新增问题；选择绑定有效评估的候选，退化时允许保留有效前稿，争议/预算/次数到限则停止；
- 与原型一致的三栏正文工作台：左侧卷章树和章节状态、中央沉浸式正文编辑器、右侧上下文解释与章节 AI 对话；
- 编辑器具备本地自动保存、revision 历史、查找替换、字数统计和可恢复的阅读偏好；
- 选区改写绑定正文 revision、Unicode rune 范围和原文哈希，先展示候选差异，支持全部采纳、部分采纳、放弃和撤销；
- 章节级 AI 写入与费用动作使用结构化待确认提案，并处理过期、冲突、执行中、失败和结果未知状态；
- 作者编辑、废弃、重写和定稿；所有采纳都创建新 revision，不原地覆盖 canonical 正文；
- 可最小化的生成运行面板使用稳定的作者可见阶段，完成后由作者主动打开正文候选；
- 最小 `chapter.posthoc`：从定稿 revision 提取带语境的陈述、状态和摘要，区分人物陈述/猜测与客观事件，按证据采纳/待定/冲突；验证通过后独立提交，不把未完成结果当作正式事实；
- 定稿后作业不阻塞编辑；提供幂等、来源失效、`memory_pending_rebuild`、下一章依赖预检和恢复，支持近期正文及有界历史证据，完整五层记忆与跨卷扩量在 R7 落地；
- 创作质量 Harness 持续回归；
- 1280×720 与 1440×900 正文/审阅布局、可收起导航和结论抽屉、键盘焦点与未保存内容保护。

退出标准：

- 从已确认路线图节点生成完整章节候选；方向后无需全书档案即可试写，但试写不入正式记忆、不计定稿字数；转正需重新复检，失败或取消保留原候选；
- 试写反馈、回到方案、重启恢复和旧方向试写失效通过回归；窄窗口正文可读、确认动作可达且面板变化不丢输入；
- 自动审阅和修订不会静默改变作者约束；
- 作者可以完整查看版本、问题、修改和模型用量；
- 选区改写和 AI 对话修改在正文已变化时不会错位覆盖，并可从 revision 历史撤销；
- 后置记忆任务失败不影响已定稿正文和编辑器可用性；
- 定稿事务安全更新 canonical revision。
- 漏召回可经授权补查恢复，未命中不伪造事实；超限、版本变化、取消和结果未知时不继续未授权调用；同轮审阅读取同一冻结正文与证据；
- 谎言/猜测不被直接判为世界冲突；误报与争议有核验记录，偏好建议不自动升级为硬阻断；
- 文风处理改变知识边界、修订引入新冲突和部分采纳后旧评估失效均有回归；最终选稿可追溯到准确版本与有效评估，不默认取最后 Artifact；
- 两次连续单章创作能完成“定稿 → 最小后验核验提交 → 下章读取”，陈述语义正确；后验失败或来源变化有恢复路径，不依赖尚未实现的 R7 旁路；
- 新步骤的误报、漏检、修订收益、新问题率与成本通过预先冻结的 Harness 门槛后才成为默认工作流。

## 10. R6：3–10 章批次创作闭环

目标：把已验证的单章能力扩展为默认 3–10 章的连续创作。

范围：

- 批次状态机和单作品/分支单活跃批次；
- 问题优先的批次摘要，重复诊断归组、逐章证据定位、返回原队列位置与独立定稿；
- `GenerationBatch → ChapterRun` 层级运行；每章拥有独立 Context Manifest、attempt、用量、候选和恢复点，批次只协调依赖、provisional 传递、检查点和熔断；
- 冻结 canonical head、路线图、锚点、方案版本和预算；
- 同批前序候选以 provisional 身份进入后序上下文；
- 每 3–5 章检查点，同时检查跨章衔接、重复冲突、节奏和近期推进；批次/故事弧结束后对照规划目标评估阶段回报、人物变化、承诺兑现和终局推进，提出滚动规划候选；
- 硬约束失败、严重连续性问题和预算不足熔断；
- 修正继续、接受风险、停止和非破坏性回退；
- `GenerationAttempt`、`superseded` 和作者逐章定稿；
- 批次运行在作品和章节工作台中共享稳定阶段投影，可最小化、恢复，并能定位到每章候选、冲突和等待作者处理的节点；
- 复用 R5 Manifest、补查、复检和最小后验，扩展批次预算共享、provisional 状态及跨章证据依赖；评估记录来源版本和覆盖范围，重复事件幂等，来源变化后按依赖复核。

退出标准：

- 真实 3–10 章批次可以运行、暂停、恢复、回退和定稿；
- 当前批次未处理完不能开始下一批；
- provisional 内容不会进入正式长期记忆；
- 取消、失败和重启不损坏 canonical 内容。
- 修改前序章节后只使实际依赖它的后续候选 stale，并可从最早受影响的 ChapterRun 恢复，不无条件重跑整批。
- 固定多章样本能识别“有事件但无推进”、重复冲突和阶段承诺未兑现；评估区分规划目标与实际结果，不把候选中的回报当作已兑现；
- 作者处理完本批后确认近期规划候选，才能作为下一批依据；故事弧/卷/全书修改仍经影响方案批准，评估不静默重写高层结构；
- 补查、审阅核验、复检和批次/故事弧评估计入同一授权预算，失败恢复不重复付费或重复物化。

## 11. R7：长篇记忆、连续性与影响分析

目标：让批次能力扩展到数十万至百万字，并安全处理高层设定变化。

范围：

- 宪法、结构、状态、摘要和证据五层记忆；
- Context Manifest 完整装配、解释、预算和哈希，并向正文工作台提供“本章为何使用这些人物、设定、伏笔与历史事实”的只读解释投影；
- 近场叙事、远场骨架、事实有效区间和过期状态；
- 记忆幂等重建和调用工件保留策略；
- 扩展 R5 `chapter.posthoc` 至五层长篇记忆，保留陈述者/相信者/知情者、故事内有效时间和叙述揭示位置；定稿证据与语义解释分开，来源变化后增量失效与重建；
- 观察与裁决保持职责边界，默认依据带证据差异，歧义时经应用层有界补读；证据不足保持待定，不强制独立模型调用，不将人物陈述直接当作客观事实；
- 普通事件、潜在线索与已建立承诺分开，规划埋设、正文建立和兑现分开；跨卷跟踪故事弧回报、人物变化与终局推进，不把未登记细节全部变成叙事债务；
- 50–100 章 PR Harness 与 500 章 Nightly/Release Harness，覆盖 requirements 7.1 的轻量、20,000 条密集记忆及 100,000 条压力样本，包含关系、历史版本、候选与证据；
- requirements 9.3 的百万字交付验收：至少一部经正常产品流程从原创创意推进到百万字完结的实测，分开记录容量、连续性、独立叙事评分及成本，事前冻结预算和评价门槛；
- `future_only`、`in_story_change` 和 `retcon`；
- 高层变更影响范围、证据、失效和恢复快照；
- 定稿后记忆尚未提取、过期或冲突时的生成前检查与恢复入口。

退出标准：

- 长篇召回、证据支持和过期状态指标在轻量与密集集分别达标，压力集可安全操作并报告退化；百万字实测与 9.3 的独立分项评分、成本门槛通过，不能以“架构可扩展”收尾；
- 每次生成能够解释所使用的 canonical 来源；
- 高层变化不会静默改写历史定稿；
- 清理完整调用工件后仍能解释 canonical revision 的上下文组成。
- 谎言、传闻、梦境、不可靠叙述和后续揭示的固定样本通过语义回归，待定/冲突不进入确定事实检索，重建保留适用的作者裁定；
- 原创连续创作样本通过事先冻结的故事弧/跨卷质量门槛，分别报告有效推进、重复冲突、承诺兑现、终局贡献和每万字可接受正文的费用、等待与作者修改时间；合成检索通过不能替代此项验收。

## 12. R8：导入小说整书档案

目标：快速导入后立即阅读和编辑，并在后台生成可恢复的整书档案候选。

范围：

- TXT/Markdown 编码识别和确定性切章；
- 原始文件安全归档；
- 冻结章节 revision/hash 的 `SourceManifest`；
- 按章提取、按卷聚合和全书实体解析；
- 别名、同名、身份合并、时间演变、冲突和跨章节证据；
- stale 检测、增量重算和仅重试失败步骤；
- 版本化整书候选包和统一原子确认。

退出标准：

- 导入不等待模型即可阅读和编辑；
- 后台任务可暂停、恢复和取消；
- 最终按整书候选包审阅，不暴露内部切片为确认单位；
- 正式资产保留跨章节证据和冲突处理结果。

## 13. R9：双平台商业发布硬化

目标：达到 Windows/macOS 可分发、可升级、可恢复和可支持的商业发布门槛。

范围：

- Release CI、签名、公证、安装、升级和回滚；
- 项目空间分析、调用工件压缩、去重和安全瘦身；
- 迁移备份、完整性检查和恢复演练；
- Provider 真实连接、费用、拒绝和额度错误验证；
- 性能、可访问性、隐私和诊断日志；
- 目标作者封闭测试，分别覆盖无经验作者试写、专业作者已有方案和已有正文导入；
- 复验 requirements 9.3 百万字四维证据与发布版本一致，双平台容量/恢复和受变更影响的创作范围重新验证；

退出标准：

- 双平台安装包、升级和卸载不影响用户项目；
- 商业发布阻断验收全部通过；
- 至少 8 名目标作者完成封闭测试，包含至少 3 名无小说经验者与 3 名长篇作者，记录首次正文时间、决策次数、费用理解及修改成本并关闭阻断问题；
- 百万字四维验收、三条起点、窄窗口阅读和批次问题定位全部通过，未达标不能将其延后到 R10 后仍宣称满足首版交付。

## 14. R10：完整 V1 增强能力

目标：在商业闭环稳定后增加高级能力。

候选范围：

- 单批最多 50 章；
- 符合发布门槛的官方订阅运行时；
- 完整 `AuthorProfile`、`AuthorTeam` 本地安装/选择/导出和可导入工作流模板，可延至 V1.x；R5 的项目文风约定与样章引用属于首版，不依赖这些模板；
- 更完整的命名快照、剧情分支和跨平台恢复；
- 经测量后必要的本地向量检索或 Rust sidecar。

## 15. 阶段过关规则

- 阶段完成必须满足退出标准并保留自动测试、Harness、构建或人工验收证据。
- Agent 能力按“薄入口验证 → 质量过关 → 正式界面接入”推进；禁止在质量能力尚未证明时提前扩展依赖它的完整业务 UI。
- 当前阶段未完成时，不以临时旁路提前实现依赖其数据契约的后续业务。
- 发现上游产品或架构错误时先修改权威文档，再修改当前功能设计和代码。
- 小型修复不建立文档；涉及行为、接口、数据或状态机变化时更新原功能设计。
- 任何阶段不得提交凭据、用户正文、本地数据库或签名材料。
