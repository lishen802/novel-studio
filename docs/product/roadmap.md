# 织境 Story Studio 开发路线图

- 状态：当前唯一权威开发顺序
- 更新日期：2026-08-17
- 相关文档：[产品需求](requirements.md)、[产品设计与技术架构](architecture.md)

## 1. 推进原则

1. 智能体创作能力优先：先通过 Harness 证明能规划、能写、能审、能改，再扩展对应正式界面。
2. 纵向切片：每阶段只实现形成可验证结果所需的领域、应用、持久化、运行时、绑定和 UI。
3. 可靠性先于扩量：候选隔离、定稿安全、取消、恢复和费用边界先于批次数和长篇规模。
4. 质量证据过关：不以页面数量或代码量判断完成，必须有自动测试、Harness、双平台构建或作者验收证据。
5. 不平行重写：复用现有正文、revision、资产、ChangeSet、Provider、Agent Run、JobEvent、导入和恢复能力。
6. 当前阶段出现设计变化时直接修改产品文档和原功能设计，不建立单独修复计划。

## 2. 主阶段

```text
R0 测试与构建基线（完成）
→ R1 长任务与项目可靠性（完成）
→ R2 产品壳与模型基础设施（收口中）
→ R3 Agent Kernel 与创作质量 Harness
→ R4 作品策划与正式资产闭环
→ R5 单章高质量写作闭环
→ R6 3–10 章批次创作闭环
→ R7 长篇记忆、连续性与影响分析
→ R8 导入小说整书档案
→ R9 双平台商业发布硬化
→ R10 完整 V1 增强能力
```

## 3. R0：测试与构建基线

状态：已完成。

成果：

- Go、React、迁移、Provider、导入、快照和分支测试基线；
- fake/Recorded Provider；
- Windows/macOS Wails 生产构建；
- 旧项目迁移和恢复 fixture；
- 凭据、正文和本地数据库不进入仓库或测试日志。

## 4. R1：长任务与项目可靠性

状态：已完成。

成果：

- Model IO 不持有阻断正文保存的工作区全局锁；
- project/store generation 和 job lease；
- 可恢复 `JobEvent`、`JobSnapshot` 和 cursor 补拉；
- 项目跨进程 OS 锁、只读打开和恢复副本；
- 同步盘、网络目录、Windows 路径和原子写入风险处理。

## 5. R2：产品壳与模型基础设施

状态：基础完成，当前进行生产前端与后端收口。

目标：让后续智能体能力拥有稳定、真实、可测试的桌面入口和模型配置。

范围：

- 首页、最近项目、原生菜单、作品导航和阶段工作台；
- 应用级 `settings.db`、模型连接和不可变创作方案版本；
- API Key 使用操作系统凭据库；
- 前后端按钮绑定现有后端能力；
- 统一前后端角色标识；
- 真实连接和模型可用性测试；
- 模型名称、角色绑定和默认方案的保存与重载；
- 标题栏、窗口关闭、设置返回和原型一致性；
- 未实现能力明确显示未就绪，不使用 mock 伪造成功。

退出标准：

- 用户可通过界面创建、测试、更新和删除模型连接；
- 可发布包含 `planner`、`writer`、`continuity_reviewer` 的有效方案；
- 新项目固定创建时选择的方案版本；
- 使用真实模型完成一次可观察、可取消、可恢复的 AgentRun 冒烟测试；
- Windows/macOS 产品壳关键交互通过验证。

## 6. R3：Agent Kernel 与创作质量 Harness

状态：下一核心阶段。

目标：在继续扩展上层业务页面前，证明智能体能够稳定完成规划、写作、独立审阅和有边界修订。

范围：

- 版本化 Agent 任务协议、输入 Context、输出 Schema 和工作流；
- 规划、章节策划、正文写作、连续性审阅、内容编辑和文风修订能力；
- 角色按能力组合，不固定 Agent 数量或具体 Provider；
- Prompt、工作流、Schema、模型和参数的运行冻结；
- 原创固定种子和章节任务的创作质量 Harness；
- 单次直出、智能体初稿和修订稿对照；
- 锚点、长度、重复、机械句式、结构和格式自动门禁；
- 钩子、推进、人物声音、场景感、因果、情绪和可读性的人工盲评；
- 失败、取消、重试、预算、事件和候选持久化。

退出标准：

- 无需正式业务页面即可通过测试入口运行完整 Agent 工作流；
- 固定创意能够稳定产出结构化方案、章节细纲、正文和审阅结果；
- 修订稿相对单次直出在既定盲评和接受率指标上有可记录提升；
- 写作与审阅可使用不同模型；
- 任何失败不修改 canonical 正文或确认资产；
- 每次结果可追踪到模型、Prompt、工作流、输入版本和用量。

## 7. R4：作品策划与正式资产闭环

目标：完成“一句创意 → 三套方向 → 作品方案 → 人物/世界观 → 全书路线图 → 正式资产”的可恢复闭环。

范围：

- 原创作品阶段状态机；
- 三套显著不同的原创方向和比较、重做、组合；
- 可编辑、可锁定的作品方案；
- 人物弧、关系、世界规则、势力、地点和禁写项；
- 全书、卷、故事弧和章节范围路线图；
- 硬锚点、软锚点和禁止项；
- 作品方案候选映射到统一正式资产；
- 原子确认、幂等、失败回滚和来源证据。

退出标准：

- 一句中文创意可以生成并确认完整作品方案；
- 确认内容进入对应正式资产页，未确认内容不进入 canonical；
- 路线图确认后作品进入可写状态；
- 应用重启后能够恢复到正确阶段。

## 8. R5：单章高质量写作闭环

目标：生成一章达到作者可审阅、可修改和可定稿标准的网络小说正文。

范围：

- 章节目标和场景节拍；
- 章节正文候选；
- 连续性、人物动机、因果、节奏、世界规则、伏笔、重复和文风审阅；
- 基于证据的局部修订与新 attempt；
- 作者编辑、废弃、重写和定稿；
- 定稿后事实、状态和摘要候选；
- 创作质量 Harness 持续回归。

退出标准：

- 从已确认路线图节点生成完整章节候选；
- 自动审阅和修订不会静默改变作者约束；
- 作者可以完整查看版本、问题、修改和模型用量；
- 定稿事务安全更新 canonical revision。

## 9. R6：3–10 章批次创作闭环

目标：把已验证的单章能力扩展为默认 3–10 章的连续创作。

范围：

- 批次状态机和单作品/分支单活跃批次；
- 冻结 canonical head、路线图、锚点、方案版本和预算；
- 同批前序候选以 provisional 身份进入后序上下文；
- 每 3–5 章检查点；
- 硬约束失败、严重连续性问题和预算不足熔断；
- 修正继续、接受风险、停止和非破坏性回退；
- `GenerationAttempt`、`superseded` 和作者逐章定稿；
- 最小可用 `ContextManifest`。

退出标准：

- 真实 3–10 章批次可以运行、暂停、恢复、回退和定稿；
- 当前批次未处理完不能开始下一批；
- provisional 内容不会进入正式长期记忆；
- 取消、失败和重启不损坏 canonical 内容。

## 10. R7：长篇记忆、连续性与影响分析

目标：让批次能力扩展到数十万至百万字，并安全处理高层设定变化。

范围：

- 宪法、结构、状态、摘要和证据五层记忆；
- Context Manifest 完整装配、解释、预算和哈希；
- 近场叙事、远场骨架、事实有效区间和过期状态；
- 记忆幂等重建和调用工件保留策略；
- 50–100 章 PR Harness 与 500 章 Nightly/Release Harness；
- `future_only`、`in_story_change` 和 `retcon`；
- 高层变更影响范围、证据、失效和恢复快照。

退出标准：

- 长篇召回、证据支持和过期状态指标达到产品需求门槛；
- 每次生成能够解释所使用的 canonical 来源；
- 高层变化不会静默改写历史定稿；
- 清理完整调用工件后仍能解释 canonical revision 的上下文组成。

## 11. R8：导入小说整书档案

目标：快速导入后立即阅读和编辑，并在后台生成可恢复的整书档案候选。

范围：

- TXT/Markdown 编码识别和确定性切章；
- 原始文件安全归档；
- 冻结章节 revision/hash 的 `SourceManifest`；
- 按章提取、按卷聚合和全书实体解析；
- 别名、同名、身份合并、时间演变、冲突和跨章节证据；
- stale 检测、增量重算和仅重试失败步骤；
- 版本化整书候选包和统一原子确认。

退出标准：

- 导入不等待模型即可阅读和编辑；
- 后台任务可暂停、恢复和取消；
- 最终按整书候选包审阅，不暴露内部切片为确认单位；
- 正式资产保留跨章节证据和冲突处理结果。

## 12. R9：双平台商业发布硬化

目标：达到 Windows/macOS 可分发、可升级、可恢复和可支持的商业发布门槛。

范围：

- Release CI、签名、公证、安装、升级和回滚；
- 项目空间分析、调用工件压缩、去重和安全瘦身；
- 迁移备份、完整性检查和恢复演练；
- Provider 真实连接、费用、拒绝和额度错误验证；
- 性能、可访问性、隐私和诊断日志；
- 目标作者封闭测试。

退出标准：

- 双平台安装包、升级和卸载不影响用户项目；
- 商业发布阻断验收全部通过；
- 至少 8 名目标作者完成封闭测试并关闭阻断问题。

## 13. R10：完整 V1 增强能力

目标：在商业闭环稳定后增加高级能力。

候选范围：

- 单批最多 50 章；
- 符合发布门槛的官方订阅运行时；
- `AuthorProfile`、`AuthorTeam` 和可导入工作流模板；
- 更完整的命名快照、剧情分支和跨平台恢复；
- 经测量后必要的本地向量检索或 Rust sidecar。

## 14. 阶段过关规则

- 阶段完成必须满足退出标准并保留自动测试、Harness、构建或人工验收证据。
- 当前阶段未完成时，不以临时旁路提前实现依赖其数据契约的后续业务。
- 发现上游产品或架构错误时先修改权威文档，再修改当前功能设计和代码。
- 小型修复不建立文档；涉及行为、接口、数据或状态机变化时更新原功能设计。
- 任何阶段不得提交凭据、用户正文、本地数据库或签名材料。
