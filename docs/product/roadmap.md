# 织境 Story Studio 开发路线图

- 状态：当前唯一权威开发顺序
- 更新日期：2026-09-03
- 相关文档：[产品需求](requirements.md)、[产品设计与技术架构](architecture.md)

## 1. 推进原则

1. 智能体创作能力优先：先通过 Harness 证明能规划、能写、能审、能改，再扩展对应正式界面。
2. 纵向切片：每阶段只实现形成可验证结果所需的领域、应用、持久化、运行时、绑定和 UI。
3. 可靠性先于扩量：候选隔离、定稿安全、取消、恢复和费用边界先于批次数和长篇规模。
4. 质量证据过关：不以页面数量或代码量判断完成，必须有自动测试、Harness、双平台构建或作者验收证据。
5. 不平行重写：复用现有正文、revision、资产、ChangeSet、Provider、Agent Run、JobEvent、导入和恢复能力。
6. 当前阶段出现设计变化时直接修改产品文档和原功能设计，不建立单独修复计划。

## 2. 主阶段

```text
R0 测试与构建基线（完成）
→ R1 长任务与项目可靠性（完成）
→ R2 产品壳与交互基础（完成）
→ R2.1 模型基础设施收口（完成）
→ R3 Agent Kernel 与创作质量 Harness（完成）
→ R4 作品策划与正式资产闭环（当前，设计完成，实现中）
→ R5 单章高质量写作闭环
→ R6 3–10 章批次创作闭环
→ R7 长篇记忆、连续性与影响分析
→ R8 导入小说整书档案
→ R9 双平台商业发布硬化
→ R10 完整 V1 增强能力
```

## 3. R0：测试与构建基线

状态：已完成。

成果：

- Go、React、迁移、Provider、导入、快照和分支测试基线；
- fake/Recorded Provider；
- Windows/macOS Wails 生产构建；
- 旧项目迁移和恢复 fixture；
- 凭据、正文和本地数据库不进入仓库或测试日志。

## 4. R1：长任务与项目可靠性

状态：已完成。

成果：

- Model IO 不持有阻断正文保存的工作区全局锁；
- project/store generation 和 job lease；
- 可恢复 `JobEvent`、`JobSnapshot` 和 cursor 补拉；
- 项目跨进程 OS 锁、只读打开和恢复副本；
- 同步盘、网络目录、Windows 路径和原子写入风险处理。

## 5. R2：产品壳与交互基础

状态：已完成。

成果：

- 首页、最近项目、原生菜单、作品导航和阶段工作台；
- 应用级 `settings.db`、模型连接元数据和不可变创作方案版本；
- 标题栏、窗口关闭、设置返回和原型一致性；
- 后端未实现能力显示未就绪，不使用 mock 伪造成功。

## 6. R2.1：模型基础设施收口

状态：已完成。

目标：让后续智能体能力拥有真实、完整、可测试的模型配置与调用入口。

范围：

- API Key 使用操作系统凭据库；
- 前后端按钮绑定现有后端能力；
- 统一前后端角色标识；
- 真实连接和模型可用性测试；
- 模型名称、角色绑定和默认方案的保存与重载；
- 删除连接时同步清理凭据；
- 可理解的错误、加载、成功和费用反馈。

退出标准：

- 用户可通过界面创建、测试、更新和删除模型连接；
- 可发布包含 `planner`、`writer`、`continuity_reviewer` 的有效方案；
- 新项目固定创建时选择的方案版本；
- 使用真实模型完成一次可观察、可取消、可恢复的 AgentRun 冒烟测试；
- Windows/macOS 产品壳关键交互通过验证。

## 7. R3：Agent Kernel 与创作质量 Harness

状态：已完成。项目负责人已确认真实模型校准无问题，并同意本阶段收尾。

目标：在继续扩展上层业务页面前，证明智能体能够稳定完成规划、写作、独立审阅和有边界修订。

范围：

- 版本化 Agent 任务协议、输入 Context、输出 Schema 和工作流；
- 规划、章节策划、正文写作、连续性审阅、内容编辑和文风修订能力；
- 将 `chapter_planner` 收口为可演进的章节导演协议，明确 canonical 来源、创作建议、场景视角、欲望、阻力、信息释放、状态变化、锚点、禁止提前揭示项和允许即兴范围；
- 角色按能力组合，不固定 Agent 数量或具体 Provider；
- Prompt、工作流、Schema、模型和参数的运行冻结；
- 原创固定种子和章节任务的创作质量 Harness；
- 单次直出、智能体初稿和修订稿对照；
- 锚点、长度、重复、机械句式、结构和格式自动门禁；
- 钩子、推进、人物声音、场景感、因果、情绪和可读性的人工盲评；
- 失败、取消、重试、预算、事件和候选持久化。
- 面向上层界面的稳定公开阶段、运行投影和事件语义；内部 Agent 节点可以演进，但不得把工作流拓扑直接暴露给产品界面。
- 区分质量问题驱动与作者指令驱动的修订输入，冻结基线、目标、保持项和输入摘要；两者都只生成候选；
- 候选 Artifact 谱系可追踪到基线、工作流和 Context Manifest，为后续差异审阅、撤销和恢复提供稳定引用；
- Harness 能比较最小工作流、增强章节导演、专业状态分析和拆分独立审阅等版本；拆分审阅使用确定性 Finding Merger，新增节点不以“更多 Agent”本身作为通过依据；
- 只建设模型配置、运行观察、候选审阅和人工评分所需的测试入口或薄界面；冻结其他非必要 UI 美化和完整业务页面扩展。

退出标准：

- 无需正式业务页面即可通过测试入口运行完整 Agent 工作流；
- 固定创意能够稳定产出结构化方案、章节细纲、正文和审阅结果；
- 修订稿相对单次直出在既定盲评和接受率指标上有可记录提升；
- 章节导演和审阅拆分等增强只有在分项质量、失败率与成本报告达到预设门槛后，才可成为 R5 默认工作流；
- 写作与审阅可使用不同模型；
- 任何失败不修改 canonical 正文或确认资产；
- 每次结果可追踪到模型、Prompt、工作流、输入版本和用量。
- R4/R5 无需读取内部节点 ID 或改造 Agent Kernel 主协议，即可观察公开阶段并请求带谱系的作者定向修订候选；
- 对应能力未达到预先定义的分项质量门槛时，不进入其完整上层业务界面开发。

## 8. R4：作品策划与正式资产闭环

状态：当前阶段，设计完成，实现中。

目标：完成“一句创意 → 三套方向 → 作品方案 → 人物/世界观 → 全书路线图 → 正式资产”的可恢复闭环。

范围：

- 原创作品阶段状态机；
- 与原型一致的作品构建工作台：顶部阶段轨、左侧分类/实体导航、中央结构化候选、右侧绑定当前对象的 AI 对话和底部推进操作；
- “逐步审阅”与“自动推进”两种模式；自动推进只连续生成候选，遇到锁定字段、冲突、高风险修改、费用授权或正式写入时暂停；
- 三套显著不同的原创方向和比较、重做、组合；
- 可编辑、可锁定的作品方案；
- 人物弧、关系、世界规则、势力、地点和禁写项；
- 全书、卷、故事弧和章节范围路线图；
- 全书、卷、故事弧、未来 3–10 章的四层滚动规划规则；默认只刷新近期层，高层变化必须进入作者批准的影响方案；
- 硬锚点、软锚点和禁止项；
- 作品方案候选映射到统一正式资产；
- 字段级和实体级 AI 调整：对话先产生带目标、基线版本、差异、影响范围、费用和幂等键的修改提案，作者确认后才执行；
- 上游修改后的下游失效标记、影响说明和作者选择，不静默级联重写；
- 原子确认、幂等、失败回滚和来源证据。

原路线图 R3 的“正式资产确认与写入”并入本阶段：智能体生成作品方案后，必须由作者确认，才写入人物、世界观、大纲、关系、时间线和伏笔等正式资产。

退出标准：

- 一句中文创意可以生成并确认完整作品方案；
- 确认内容进入对应正式资产页，未确认内容不进入 canonical；
- 路线图确认后作品进入可写状态；
- 应用重启后能够恢复阶段、候选、锁定项、待确认动作和运行进度；
- 作者能够直接编辑或通过 AI 对话调整任一已生成对象，冲突和失效状态可见，未经确认不发生正式写入或新的付费调用。

## 9. R5：单章高质量写作闭环

目标：生成一章达到作者可审阅、可修改和可定稿标准的网络小说正文。

范围：

- 章节导演任务：场景序列、视角、人物欲望、阻力、信息释放、状态变化、锚点、禁止提前揭示项和允许即兴范围；
- 按需专业状态分析：连续性、人物动机与知识边界、伏笔与叙事债务、世界规则只输出结构化约束和风险，由单一主写模型统一完成正文；
- 章节正文候选；
- 连续性、人物动机、因果、节奏、世界规则、伏笔、重复和文风审阅；
- 拆分审阅彼此隔离，并由确定性 Finding Merger 去重、归类、关联证据和暴露冲突；
- 独立的去 AI 味修订阶段，处理套话、机械排比、总结腔、空泛修辞和声音同质化；该阶段只接收章节全文，不接收设定、大纲与审阅发现，使其以读者视角打磨文字，与依据问题清单定点修改的有界修订保持职责分离；
- 基于证据的局部修订与新 attempt；
- 与原型一致的三栏正文工作台：左侧卷章树和章节状态、中央沉浸式正文编辑器、右侧上下文解释与章节 AI 对话；
- 编辑器具备本地自动保存、revision 历史、查找替换、字数统计和可恢复的阅读偏好；
- 选区改写绑定正文 revision、Unicode rune 范围和原文哈希，先展示候选差异，支持全部采纳、部分采纳、放弃和撤销；
- 章节级 AI 写入与费用动作使用结构化待确认提案，并处理过期、冲突、执行中、失败和结果未知状态；
- 作者编辑、废弃、重写和定稿；所有采纳都创建新 revision，不原地覆盖 canonical 正文；
- 可最小化的生成运行面板使用稳定的作者可见阶段，完成后由作者主动打开正文候选；
- 提供定稿后异步作业挂点、`memory_pending_rebuild` 和最小事实预检候选；R5 不把未完成的后验结果写入正式长期记忆；
- 定稿后作业不阻塞继续编辑；其未完成状态会在下一次依赖该记忆的生成前提示或阻断，完整 `chapter.posthoc` 在 R7 落地；
- 创作质量 Harness 持续回归。

退出标准：

- 从已确认路线图节点生成完整章节候选；
- 自动审阅和修订不会静默改变作者约束；
- 作者可以完整查看版本、问题、修改和模型用量；
- 选区改写和 AI 对话修改在正文已变化时不会错位覆盖，并可从 revision 历史撤销；
- 后置记忆任务失败不影响已定稿正文和编辑器可用性；
- 定稿事务安全更新 canonical revision。

## 10. R6：3–10 章批次创作闭环

目标：把已验证的单章能力扩展为默认 3–10 章的连续创作。

范围：

- 批次状态机和单作品/分支单活跃批次；
- `GenerationBatch → ChapterRun` 层级运行；每章拥有独立 Context Manifest、attempt、用量、候选和恢复点，批次只协调依赖、provisional 传递、检查点和熔断；
- 冻结 canonical head、路线图、锚点、方案版本和预算；
- 同批前序候选以 provisional 身份进入后序上下文；
- 每 3–5 章检查点；
- 硬约束失败、严重连续性问题和预算不足熔断；
- 修正继续、接受风险、停止和非破坏性回退；
- `GenerationAttempt`、`superseded` 和作者逐章定稿；
- 批次运行在作品和章节工作台中共享稳定阶段投影，可最小化、恢复，并能定位到每章候选、冲突和等待作者处理的节点；
- 最小可用 `ContextManifest`。

退出标准：

- 真实 3–10 章批次可以运行、暂停、恢复、回退和定稿；
- 当前批次未处理完不能开始下一批；
- provisional 内容不会进入正式长期记忆；
- 取消、失败和重启不损坏 canonical 内容。
- 修改前序章节后只使实际依赖它的后续候选 stale，并可从最早受影响的 ChapterRun 恢复，不无条件重跑整批。

## 11. R7：长篇记忆、连续性与影响分析

目标：让批次能力扩展到数十万至百万字，并安全处理高层设定变化。

范围：

- 宪法、结构、状态、摘要和证据五层记忆；
- Context Manifest 完整装配、解释、预算和哈希，并向正文工作台提供“本章为何使用这些人物、设定、伏笔与历史事实”的只读解释投影；
- 近场叙事、远场骨架、事实有效区间和过期状态；
- 记忆幂等重建和调用工件保留策略；
- `chapter.posthoc` 只读取作者定稿 revision，产出带证据和有效区间的事实、状态、摘要、伏笔与叙事债务候选；一致性校验通过后才更新正式记忆；
- 后验提取拆分为观察与裁决两个职责：观察节点逐条比对定稿正文与现有记忆并只输出差异，不做判断；裁决节点只读取差异报告，不重读正文，将事实候选裁定为采纳、待定或冲突三态，并把未登记事件归类为伏笔或叙事债务；
- 50–100 章 PR Harness 与 500 章 Nightly/Release Harness；
- `future_only`、`in_story_change` 和 `retcon`；
- 高层变更影响范围、证据、失效和恢复快照；
- 定稿后记忆尚未提取、过期或冲突时的生成前检查与恢复入口。

退出标准：

- 长篇召回、证据支持和过期状态指标达到产品需求门槛；
- 每次生成能够解释所使用的 canonical 来源；
- 高层变化不会静默改写历史定稿；
- 清理完整调用工件后仍能解释 canonical revision 的上下文组成。

## 12. R8：导入小说整书档案

目标：快速导入后立即阅读和编辑，并在后台生成可恢复的整书档案候选。

范围：

- TXT/Markdown 编码识别和确定性切章；
- 原始文件安全归档；
- 冻结章节 revision/hash 的 `SourceManifest`；
- 按章提取、按卷聚合和全书实体解析；
- 别名、同名、身份合并、时间演变、冲突和跨章节证据；
- stale 检测、增量重算和仅重试失败步骤；
- 版本化整书候选包和统一原子确认。

退出标准：

- 导入不等待模型即可阅读和编辑；
- 后台任务可暂停、恢复和取消；
- 最终按整书候选包审阅，不暴露内部切片为确认单位；
- 正式资产保留跨章节证据和冲突处理结果。

## 13. R9：双平台商业发布硬化

目标：达到 Windows/macOS 可分发、可升级、可恢复和可支持的商业发布门槛。

范围：

- Release CI、签名、公证、安装、升级和回滚；
- 项目空间分析、调用工件压缩、去重和安全瘦身；
- 迁移备份、完整性检查和恢复演练；
- Provider 真实连接、费用、拒绝和额度错误验证；
- 性能、可访问性、隐私和诊断日志；
- 目标作者封闭测试。

退出标准：

- 双平台安装包、升级和卸载不影响用户项目；
- 商业发布阻断验收全部通过；
- 至少 8 名目标作者完成封闭测试并关闭阻断问题。

## 14. R10：完整 V1 增强能力

目标：在商业闭环稳定后增加高级能力。

候选范围：

- 单批最多 50 章；
- 符合发布门槛的官方订阅运行时；
- `AuthorProfile`、`AuthorTeam` 和可导入工作流模板；
- 更完整的命名快照、剧情分支和跨平台恢复；
- 经测量后必要的本地向量检索或 Rust sidecar。

## 15. 阶段过关规则

- 阶段完成必须满足退出标准并保留自动测试、Harness、构建或人工验收证据。
- Agent 能力按“薄入口验证 → 质量过关 → 正式界面接入”推进；禁止在质量能力尚未证明时提前扩展依赖它的完整业务 UI。
- 当前阶段未完成时，不以临时旁路提前实现依赖其数据契约的后续业务。
- 发现上游产品或架构错误时先修改权威文档，再修改当前功能设计和代码。
- 小型修复不建立文档；涉及行为、接口、数据或状态机变化时更新原功能设计。
- 任何阶段不得提交凭据、用户正文、本地数据库或签名材料。
