# 织境 Story Studio 产品与交互设计

- 状态：当前唯一权威产品与交互设计
- 相关文档：[产品需求](requirements.md)、[系统技术设计](../architecture/system-design.md)、[文档索引](../README.md)

## 1. 设计定位

织境的界面应让作者感到自己在与一个可控、可追溯的 AI 创作团队共同完成一本小说，而不是在一个复杂项目管理工具中填资料，也不是在普通聊天窗口里丢失作品结构。

设计采用阶段自适应工作台：创意期以对话为主，方案期以结构化文档为主，正文期以编辑器和审阅队列为主。无论阶段如何变化，作者始终能看到当前作品、当前事实、正在执行的 AI 工作和下一步可做的事。

## 2. 体验原则

- 先开始，再细化：一句创意即可开始；结构化信息由 AI 先提出，作者逐步确认。
- 对话表达意图，页面承载状态：聊天不是项目数据库，候选、事实和 revision 有明确位置。
- 作者可随时接管：任何页面都允许作者直接编辑，不强迫通过 AI 间接修改。
- 确认节点清晰：方向、作品方案、影响方案和正文定稿必须有可见确认动作。
- 技术细节渐进披露：默认显示创作目标、进度、预算和问题；模型、Token、Context Manifest 只在高级详情中出现。
- 不让长篇失控：当前批次、未定稿章节、历史事实和候续影响始终可见。
- 不制造虚假完成感：AI 的流式文本、建议和执行中状态都不能被表现为已经定稿。
- 覆盖范围透明：导入分析、长期记忆和自动审阅必须明确展示已处理、未处理和存在冲突的范围，不能把局部结果表现为完整理解。

## 3. 信息架构

### 3.1 首页

首页只提供三条明确入口：

1. 从一个想法开始；
2. 导入小说并续写；
3. 继续最近作品。

存在最近项目时，左侧显示原创、导入、打开项目等紧凑动作和可直接打开的最近项目列表；中间突出最近作品、上次工作位置、待审阅数量、可恢复任务或恢复提示。“打开项目”属于文件操作，不替代“继续最近作品”这条产品路径。

没有最近项目时，中间显示欢迎引导，主要动作是“从一个想法开始”和“导入小说并续写”，并提供“打开已有项目”作为文件入口。首页不展示 Provider 配置、模型 ID、复杂资产表或项目设置，也不额外显示可点击的软件品牌下拉块。

### 3.2 作品导航

打开作品后，首页左栏替换为作品导航；新建、导入、打开和最近项目不继续占用作品侧栏。一级导航为：

```text
创作驾驶舱
正文与章节
审阅与候选
导入与续写
作品档案
版本与交付
```

“作品档案”展开为作品方案、故事架构、人物与势力、世界设定、时间线与事实、伏笔与关系；“版本与交付”展开为版本与恢复、剧情分支、导出和项目维护。专门页面继续存在，只降低低频档案的导航优先级。

应用级设置在作品导航之外，包含模型连接、订阅连接、创作方案、作者模板和高级偏好。项目设置通过“文件 → 项目设置…”进入，不与应用设置混合。

### 3.3 系统菜单与项目命令

macOS 使用原生系统菜单，Windows 提供功能等价的窗口菜单。软件名称菜单只显示关于、设置、检查更新、服务、隐藏和退出等应用操作。项目操作统一放入“文件”菜单：

```text
新建原创作品…
导入小说并续写…
打开项目…
打开最近项目
关闭当前项目
项目设置…
导出…
项目维护…
```

“编辑”承载撤销、重做、剪贴、查找和对选中文字调用 AI；“视图”承载作品导航、AI 面板、候选队列、专注写作和外观切换；“窗口”和“帮助”遵循平台习惯。关闭或切换项目命令必须先刷新未保存正文并安全处理运行任务和项目 lease。

### 3.4 阶段自适应工作台

宽屏工作区支持作品导航、主要画布和 AI/审阅面板三栏，但三栏不是所有阶段固定展开。主画布和右侧面板由权威作品状态决定，正式产品不提供要求作者手工切换的“构建/创作/审阅”模式。

```text
┌────────────────┬──────────────────────────────────┬───────────────────┐
│ 作品导航       │ 当前工作画布                     │ AI 创作对话       │
│                │                                  │                   │
│ 当前阶段       │ 方向 / 方案 / 路线图 / 编辑器    │ 上下文标签        │
│ 当前批次状态   │ 候选 / 证据 / 差异 / 正式资产    │ 建议与动作卡      │
│                │                                  │ 多行输入框        │
└────────────────┴──────────────────────────────────┴───────────────────┘
```

AI 面板默认状态为：创意方向阶段展开，作品方案阶段展开或保持作者选择，路线图阶段可折叠，批次运行和正常写作阶段隐藏，作者审阅阶段按标注展开。窄窗口下一律折叠为可固定的右侧抽屉。抽屉不能覆盖未保存正文；打开、关闭或切换画布不能丢失输入内容。

## 4. 阶段与主界面

### 4.1 创意阶段：AI 创作驾驶舱

作者创建新作品后，中心区域首先是一段自然语言引导和三个方向卡，而不是空白大纲。

作者输入示例：

> 一本诡异修仙小说，主角能看到功法的副作用，想写成长篇升级流。

AI 返回三张可比较的方向卡。每张卡包含：一句话卖点、类型和情绪价值、主角/代价、核心冲突、成长路径、节奏、结局方向和差异说明。

卡片操作为：`查看详情`、`选择此方向`、`修改后采用`、`重新生成`。选择不立即产生正式人物或世界观，先进入作品方案候选。

### 4.2 作品方案阶段：可编辑方案文档

中栏显示一份分区《作品方案》：故事定位、规格、主线、人物、世界观、关系、结构、节奏、伏笔和结局方向。

每个分区都支持：

- 直接编辑；
- 锁定；
- 展开 AI 推理摘要与来源；
- 在右侧对话中引用该分区提出修改；
- 查看候选差异；
- 接受、拒绝或继续修改。

作品方案顶部持续显示状态：`草案`、`等待作者确认`、`已确认` 或 `存在未确认修改`。只有已确认版本能生成正式路线图。

作者解锁已确认的核心设定、人物能力、世界规则、主线或结局边界时，界面先要求选择变更意图：

- `仅影响未来`：从指定章节或事件之后采用新设定；
- `故事内发生变化`：由一个剧情事件解释规则或状态变化；
- `追溯修正历史`：新设定从故事早期即应成立。

提交后先进入全局影响分析，不直接保存为新的正式硬约束。影响画布分别展示历史定稿冲突、确认资产、待解决候选、路线图/锚点、伏笔和人物弧；历史定稿只能查看证据或创建修订候选，不能被自动改写。

### 4.3 路线图阶段：全书而非表格地狱

路线图按“全书 → 卷 → 故事弧 → 章节范围”分层展示。默认只显示卷和故事弧，避免一开始铺开数百章。

每个节点展示目标、关键事件、人物变化、伏笔、字数/章节预估和状态。作者可以拖动排序、直接编辑、锁定关键转折，或提出“第二卷节奏太慢”之类的自然语言意见。

AI 返回影响方案与可预览 revision。作者确认前，不改变当前路线图。

路线图节点和章节范围支持三类创作锚点：

- `必须发生`：硬锚点，例如结果、信息揭示或不可改变的动作；
- `希望做到`：软锚点，例如情绪、节奏和氛围；
- `禁止出现`：不可接受的情节、行为或设定突破。

锚点卡显示来源、适用范围、锁定状态和最近一次生成的满足情况。硬锚点只能由作者修改、解锁或明确放弃。

### 4.4 批次生成阶段：轻量确认，明确运行

点击 `AI 写作` 或输入“继续写 6 章”后，显示轻量确认卡。默认推荐 3–10 章；超过 10 章时界面切换为高级范围并提示级联偏离、预计耗时与费用风险：

```text
本批范围：第 21–26 章
预计正文：约 18,000 字
创作方案：热血升级流（写作：Cursor Claude；审阅：OpenAI）
预算：订阅额度 / API 上限
自动审阅：连续性、人物、因果、节奏、伏笔
检查点：每 3 章
硬锚点：2 项   软锚点：1 项   禁止项：2 项

[开始创作] [调整] [取消]
```

只有章节数、预算、模型方案和范围等可验证参数使用控件；作者可以从对话输入自然语言，系统将其解释后放入确认卡。

运行画布显示章节队列、当前步骤、预算进度、锚点状态、下一检查点和可恢复错误。默认不显示 planner、writer、reviewer 等内部角色，只有“查看运行详情”才展开。

批次运行时 AI 对话默认隐藏，运行画布优先。作者需要追加任务指令时通过明确动作临时呼出 AI；系统不把 Provider 流式文本当作正文编辑器或候选完成状态。

运行画布不把当前 React 页面或 Wails 流式事件当作作业本身。页面重载、Bridge 重新挂载、窗口休眠后恢复或应用重新打开时，先显示“正在恢复任务状态”，再从最近持久化进度补齐缺失事件；已经显示的章节、步骤和费用不能因重复事件再次累计。模型正在生成时，正文编辑和保存仍应可用，不能让长时间的 Provider 调用冻结编辑器。

跨章检查点汇总主线偏离、硬锚点、人物状态、世界规则、时间线和严重审阅项。通过后自动继续；发现阻断问题时进入 `需要作者确认`，停止后续模型调用，并提供：

- `修正并继续`：修改触发问题的候选并重新检查；
- `回退生成进度`：选择上一个检查点或某个未定稿章节作为重启点；
- `接受风险继续`：保留问题并明确确认；
- `结束批次`：停止后续生成并保留已有候选。

应用不能仅用警告图标表示熔断；暂停原因、已保留章节、尚未发生的费用和继续后的影响必须以文字说明。

选择 `回退生成进度` 后打开影响确认卡：

```text
重启位置：第 6 章
将标记为已取代：第 6–8 章候选及其审阅结果
继续保留：第 1–5 章候选、全部定稿和历史记录
计划调整：修改第 5 章末尾动作锚点
重新调用：第 6–10 章，预计 42k Token
当前事实版本：canonical head 01J...

[确认并创建新尝试] [返回调整]
```

“已取代”内容仍可在历史详情中查看，界面不得使用“永久删除”或让作者误以为 canonical 正文被回滚。回退范围涉及已定稿章节时，按钮改为 `创建历史修订影响方案`。

### 4.5 批次审阅阶段：候选队列与编辑器

批次结束后，正文编辑器成为中栏主画布，左侧显示候选队列，右侧显示 AI 对话、自动审阅和影响方案。

```text
候选队列                 当前第 7 章                   审阅与对话
✓ 第 1 章已定稿          正文 / 修订差异               连续性：通过
✓ 第 2 章已定稿          直接编辑                      人物：需注意
● 第 7 章待审阅          [定稿] [重写] [废弃]          作者意见输入
○ 第 8 章待审阅
```

作者可直接改正文、选择一段交给 AI 修改、对全章或整批提出意见。直接编辑后，系统说明可能影响的后续候选；AI 修改前先展示影响方案。

作者选中文字提出意见时，右侧面板显示选中 revision、原文范围和作者说明。AI 先生成影响方案与局部修订候选；正文或 canonical head 在确认前变化时，旧方案失效并要求重新分析。

### 4.6 正常写作与资产控制

正文页面是成熟写作阶段的默认工作面。作者可完全自行写作；右侧 AI 对话默认隐藏，只在作者主动输入、选择文本、使用上下文动作或按 `Cmd/Ctrl+J` 时参与。

人物、世界观、大纲、时间线、事实、伏笔页面不是创作前的必填步骤，而是：

- 查看 AI 当前依据；
- 直接修改和锁定；
- 让 AI 提出新增/修改候选；
- 追溯证据与影响范围。

例如“设计三个有压迫感的反派”会生成三张人物候选卡，而不是仅在对话中产生三段文本。

### 4.7 导入续写

“导入小说并续写”与“从一个想法开始”并列。验证源文件后直接创建导入型项目，不先进入空白项目表单。

快速导入显示文件、版权/使用权确认、编码、重复检测、卷章切分和原始文本范围，不调用模型。完成后默认打开“正文与章节”；作者立即可阅读、编辑、新建章节和完全自行写作。

正文顶部在档案未生成时显示非阻断提示：

```text
尚未生成整本小说档案
AI 可以理解整本书并形成统一的大纲、人物势力、世界设定、时间线和伏笔档案。

[AI 生成整书档案] [稍后]
```

作者启动的是一个整本书层面的档案任务。上下文过长时，系统在后台自动执行分段理解、分卷合并、全书实体统一、别名合并、冲突保留和全书综合。章节级步骤仅是可恢复技术单元和证据来源，不作为用户可确认的最终档案。

运行画布显示整书原文覆盖、分卷合并、全书综合、预算、暂停/恢复和错误。任务启动时冻结来源章节/revision manifest；作者仍可编辑正文。来源章节在运行期间变化时，完成页列出变化并要求增量重算或重新合并，过期整书候选包不能确认。

整书综合完成后，候选按全书大纲、人物与势力、世界设定、全书时间线与事实、伏笔与关系分类展示。每项是跨全书合并后的结论，并可展开多个原文片段、章节/revision 或导入行范围。冲突项并排显示不同证据，不自动选择一方。

作者按分类检查、编辑和解决冲突。所有分类完成且阻断冲突解决后，页面提供 `确认整书档案入库`，一次形成一致的 canonical story archive 版本。后续重跑只能产生新候选和差异，不能静默修改已确认档案。

## 5. 对话设计

### 5.1 对话不是通用聊天

每条消息都关联当前作品、阶段、选中对象和 canonical head。输入框上方使用可移除标签展示上下文：

```text
[第 7 章] [选中文字 286 字] [当前批次] [人物：沈砚]
```

作者可用 `@` 选择章节、人物、大纲节点或世界规则，但不要求学习命令语言。对话历史保存在本地，并可按阶段、章节、批次或资产筛选；不同作品的对话绝不混入。

### 5.2 回复类型

AI 回复只能属于下列之一：

| 类型 | 界面表现 | 是否改变正式数据 |
| --- | --- | --- |
| 说明/建议 | 普通消息 | 否 |
| 选择方案 | 可比较卡片 | 否，直到选择/确认 |
| 结构化修改 | 差异候选卡 | 否，直到接受 |
| 影响分析 | 范围、成本与动作 | 否，直到确认 |
| 运行进度 | 队列与状态卡 | 不直接改正文 |
| 错误恢复 | 原因、保留状态和下一步 | 否 |

AI 不能只在消息中说“我已修改”；所有修改必须指向候选 revision 或已执行操作。

### 5.3 对话输入与发送

- 支持多行输入，`Cmd/Ctrl+Enter` 发送；
- 发送前显示将要引用的文本、章节和模型连接；
- 流式输出不强行滚动作者正在阅读的正文；
- 发送失败保留作者输入，可重试或编辑；
- 长对话可压缩显示，但原始消息可查看；压缩摘要不能替代正式资产与证据。

## 6. 确认、差异与危险操作

### 6.1 确认层级

| 操作 | 所需确认 |
| --- | --- |
| 选择故事方向 | 明确选择卡操作 |
| 应用作品方案 | 分区/整套确认 |
| 开始批次 | 章节、预算、模型来源确认 |
| 重写候选 | 影响方案确认 |
| 定稿章节 | 定稿操作，可查看自动审阅 |
| 覆盖历史正文 | 二次确认并创建候选/恢复点 |
| 废弃候选 | 明确废弃，保留审计记录 |
| 批次熔断后继续 | 显示未解决风险并明确确认 |
| 切换到收费 API | 默认本次任务确认；项目级授权必须带连接范围、金额/Token 上限和过期时间 |

### 6.2 差异阅读

所有文本、方案和资产修改可切换：`当前版本`、`候选版本`、`并排差异`、`影响说明`。差异默认突出作者修改、锁定字段和会影响后续正文的事实。

高层硬约束变更的影响说明分为四组：

- 历史定稿冲突：只读报告，显示章节和原文证据；
- 待解决候选：可选择重写、调整路线图、保留为例外、废弃或创建分支；
- 正式资产与记忆：显示需要新增生效区间、标记过期或创建冲突候选的条目；
- 未检查范围：说明未扫描的正文、原因和继续深度分析的预计费用。

`追溯修正历史` 在执行前自动创建一致性快照，并提示是否建立剧情分支。影响方案生成后若 canonical head 变化，确认按钮禁用并要求重新分析。

### 6.3 版本与恢复机制分工

产品使用四种互补机制，界面不得把它们作为同义功能呈现：

| 机制 | 解决的问题 | 默认行为 |
| --- | --- | --- |
| 章节 revision | 回看和恢复单章正文历史 | 每次保存、定稿或应用正文候选自动创建 |
| 恢复草稿 | 找回崩溃或未完成的本地编辑 | 系统自动维护，不要求作者手工管理 |
| 项目快照 | 在迁移、批量应用或重大修改前恢复整个项目 | 系统自动创建，作者也可命名创建 |
| 剧情分支 | 长期保留互斥的故事方向 | 仅在跨多章、改变主线/结局或作者明确选择时创建 |

普通改字不提示创建剧情分支；局部候选重写使用 ChangeSet 和 revision。分支操作必须先创建一致性恢复点，并说明切换影响的是整部作品正文和结构化资产。

### 6.4 项目空间与历史调用

“项目维护”页面分别显示正文/资产、revision/候选、Context Manifest、完整调用工件、索引/缓存和快照/分支的占用。作者可以执行 `压缩历史调用`，但不能选择删除 canonical 正文、候选 revision、作者指令或必要证据。

压缩前显示预计释放空间和影响：

```text
完整调用记录：1.8 GB
压缩后预计：240 MB
长期保留：Manifest、来源引用、模板版本、用量和哈希
降级内容：较早的完整 Prompt、流式调试事件、Provider 请求体

[创建恢复点并压缩] [取消]
```

高级运行详情默认读取轻量 Manifest。仅在完整调用工件仍处于保留范围时提供“查看完整组装请求”；否则显示“完整请求已压缩清理”，并允许查看来源引用、装配顺序、哈希和不可恢复内容说明。

## 7. 模型连接与设置

模型设置是应用级独立页面，而非作品工作台中的必填表单。

页面分为：

- API 连接：OpenAI、Anthropic、兼容接口；
- 订阅连接：仅显示通过正式发布门槛的 Codex 与 Cursor 官方运行时；未满足官方协议、版本兼容或许可条件的连接不出现在稳定功能中；
- 创作方案：为规划、写作、审阅、记忆和影响分析分配模型；
- 作者模板：选择和管理 AuthorProfile/AuthorTeam；
- 高级详情：能力、Token、上下文、回退、运行日志。

每个模型显示来源、健康状态、可用能力、模型目录、预算语义和测试结果。订阅连接明确标注为订阅来源，不假装是底层模型厂商 API。

新项目记录创建时选中的默认创作方案版本。应用默认方案之后发生变化，只影响后续新项目；已有项目保持原方案版本，只有作者在“文件 → 项目设置…”中主动升级、更换或按角色覆盖时才改变。项目页面只能选择应用已经配置好的连接和模型，不重复填写 API Key。每次运行仍冻结实际连接、模型、参数、来源和预算。

内容政策拒绝使用独立状态和说明，不归类为网络错误。作者选择其他连接继续前，界面重新展示模型来源、费用和可能不同的内容边界；既有输入、候选和定稿正文保持不变。

## 8. 状态、错误与恢复

用户可理解的状态优先于技术码：

- `正在为第 7 章规划场景`；
- `第 8 章等待自动审阅`；
- `Cursor 登录已失效，请在官方窗口重新登录`；
- `本批 API 预算已到上限，已保留 6 章候选`；
- `影响方案已过期，因为第 7 章刚刚被定稿`。
- `整书档案已完成 4 / 6 卷的分段处理，尚未生成可确认的全书候选包`；
- `当前模型因内容政策未生成本章，正文和已有候选均已保留`。

错误卡必须给出可执行动作：继续、重新登录、选择替代模型、重试当前步骤、查看保留候选、取消或稍后处理。错误不显示正文、密钥、SQL 或内部堆栈。

应用重启或前端 Bridge 重新挂载后，驾驶舱根据持久化状态和作业事件 cursor 恢复当前阶段、批次队列、候选、待确认操作和可恢复任务；不依赖内存中的聊天流事件。恢复过程允许短暂显示“正在补齐进度”，但不能把暂未补拉的步骤误报为失败或重新开始。

项目已被另一个应用实例以可编辑模式打开时，错误卡显示占用实例、开始时间等可安全获得的信息，并提供 `重试`、`只读打开`、`创建恢复副本` 和 `取消`。不得以“强制解锁”为默认动作；只有操作系统锁已经释放且项目完整性检查通过时，才允许清理过期锁元数据。

项目处于 OneDrive、iCloud Drive、Dropbox、网络映射目录或其他同步位置时，界面给出非阻断风险提示，说明同步程序可能锁定数据库或延迟原子替换。运行期发生共享冲突时，保留未保存编辑到恢复草稿，并提供重试、另存恢复副本和打开项目位置；不能将共享冲突笼统显示为项目损坏。

## 9. 视觉与可访问性

- 正文阅读区优先保证行宽、字体、段落和差异可读性；
- 状态既使用文字也使用形状/图标，颜色不作为唯一信息；
- 卡片操作使用动词标签，例如“确认方案”“定稿本章”“查看影响”；
- 键盘焦点在导航、编辑器、对话和候选队列之间稳定移动；
- 选中文字打开对话后，可返回原位置；
- Windows/macOS 使用各自惯用的快捷键和文件对话框；
- 第一版只优化桌面窗口，不设计移动端。

## 10. 交互验收

1. 新作者可以只用一句创意进入三方向比较，不会被强制要求填写大纲、人物或世界观。
2. 所有 AI 产生的可应用内容都有卡片、候选、差异或确认动作，不会因一条聊天回复静默生效。
3. 作者可以直接编辑正文、作品方案和故事资产，并且能看到由此导致的后续影响。
4. 作者可从对话开始 1–50 章批次，但在运行前始终看到范围、模型来源和预算。
5. 默认批次为 3–10 章；长批次风险、检查点和熔断原因可见，硬锚点偏离时不会继续静默生成。
6. 批次熔断后可从未定稿位置重启；下游候选明确显示为已取代而非被永久删除，操作前可预见重新调用范围和费用。
7. 作者修改锁定硬约束时必须选择变更意图，并能区分历史冲突报告和待解决候选；历史定稿不会静默变化。
8. 运行、暂停、恢复、错误、重试和定稿对不懂技术术语的作者仍可理解。
9. 导入正文无需等待 AI 即可阅读、编辑和新建章节；整书档案可以后台自动切分，但最终只呈现全书聚合候选，作者解决冲突并整包确认后才进入 canonical story archive。
10. API 与订阅模型的费用来源、内容拒绝和回退行为在 UI 中可辨认；不出现静默收费或静默换模型。
11. 用户能区分章节 revision、恢复草稿、项目快照和剧情分支，并能预测每种恢复操作影响的范围。
12. 项目维护页面能压缩历史调用工件并显示空间收益；压缩后仍能通过 Manifest 和不可变来源解释正式正文的生成上下文。
13. 批次运行时重新加载前端或模拟事件漏推，进度画布能从持久化 cursor 恢复，重复事件不会重复累计步骤、Token 或费用。
14. AI 正在执行长时间模型调用时，作者仍可编辑和保存正文；取消任务或切换项目时能看到明确的等待/取消状态。
15. 第二个应用实例不能同时写入同一项目；作者可以安全选择重试、只读打开或创建恢复副本，并能区分同步目录共享冲突与项目损坏。
16. 有最近项目时首页可直接继续作品；没有最近项目时显示欢迎引导。打开作品后首页入口不继续占用作品侧栏。
17. 应用名称菜单不混入项目操作；应用设置可以在无项目打开时配置模型连接和默认创作方案，修改默认不会静默改变已有项目。
