# 织境 Story Studio 产品与交互设计

- 状态：当前唯一权威产品与交互设计
- 相关文档：[产品需求](requirements.md)、[系统技术设计](../architecture/system-design.md)、[文档索引](../README.md)

## 1. 设计定位

织境的界面应让作者感到自己在与一个可控、可追溯的 AI 创作团队共同完成一本小说，而不是在一个复杂项目管理工具中填资料，也不是在普通聊天窗口里丢失作品结构。

设计采用阶段自适应工作台：创意期以对话为主，方案期以结构化文档为主，正文期以编辑器和审阅队列为主。无论阶段如何变化，作者始终能看到当前作品、当前事实、正在执行的 AI 工作和下一步可做的事。

## 2. 体验原则

- 先开始，再细化：一句创意即可开始；结构化信息由 AI 先提出，作者逐步确认。
- 对话表达意图，页面承载状态：聊天不是项目数据库，候选、事实和 revision 有明确位置。
- 作者可随时接管：任何页面都允许作者直接编辑，不强迫通过 AI 间接修改。
- 确认节点清晰：方向、作品方案、影响方案和正文定稿必须有可见确认动作。
- 技术细节渐进披露：默认显示创作目标、进度、预算和问题；模型、Token、Context Manifest 只在高级详情中出现。
- 不让长篇失控：当前批次、未定稿章节、历史事实和候续影响始终可见。
- 不制造虚假完成感：AI 的流式文本、建议和执行中状态都不能被表现为已经定稿。

## 3. 信息架构

### 3.1 首页

首页只提供三条明确入口：

1. 从一个想法开始；
2. 导入小说并续写；
3. 继续最近作品。

首页可展示最近项目、最近批次状态和恢复提示，但不展示 Provider 配置或复杂资产表。

### 3.2 作品导航

打开作品后，左侧为稳定导航：

```text
创作驾驶舱
正文与章节
作品方案
故事架构
人物与势力
世界设定
时间线与事实
伏笔与关系
导入分析
版本与恢复
导出
```

应用级设置在作品导航之外，包含模型连接、订阅连接、创作方案、作者模板和高级偏好。

### 3.3 三栏工作台

宽屏工作区采用三栏；中栏是当前阶段的主要画布，右栏是 AI 创作对话。

```text
┌────────────────┬──────────────────────────────────┬───────────────────┐
│ 作品导航       │ 当前工作画布                     │ AI 创作对话       │
│                │                                  │                   │
│ 当前阶段       │ 方向 / 方案 / 路线图 / 编辑器    │ 上下文标签        │
│ 当前批次状态   │ 候选 / 证据 / 差异 / 正式资产    │ 建议与动作卡      │
│                │                                  │ 多行输入框        │
└────────────────┴──────────────────────────────────┴───────────────────┘
```

窄窗口下，对话栏折叠为可固定的右侧抽屉。抽屉不能覆盖未保存正文；打开、关闭或切换画布不能丢失输入内容。

## 4. 阶段与主界面

### 4.1 创意阶段：AI 创作驾驶舱

作者创建新作品后，中心区域首先是一段自然语言引导和三个方向卡，而不是空白大纲。

作者输入示例：

> 一本诡异修仙小说，主角能看到功法的副作用，想写成长篇升级流。

AI 返回三张可比较的方向卡。每张卡包含：一句话卖点、类型和情绪价值、主角/代价、核心冲突、成长路径、节奏、结局方向和差异说明。

卡片操作为：`查看详情`、`选择此方向`、`修改后采用`、`重新生成`。选择不立即产生正式人物或世界观，先进入作品方案候选。

### 4.2 作品方案阶段：可编辑方案文档

中栏显示一份分区《作品方案》：故事定位、规格、主线、人物、世界观、关系、结构、节奏、伏笔和结局方向。

每个分区都支持：

- 直接编辑；
- 锁定；
- 展开 AI 推理摘要与来源；
- 在右侧对话中引用该分区提出修改；
- 查看候选差异；
- 接受、拒绝或继续修改。

作品方案顶部持续显示状态：`草案`、`等待作者确认`、`已确认` 或 `存在未确认修改`。只有已确认版本能生成正式路线图。

### 4.3 路线图阶段：全书而非表格地狱

路线图按“全书 → 卷 → 故事弧 → 章节范围”分层展示。默认只显示卷和故事弧，避免一开始铺开数百章。

每个节点展示目标、关键事件、人物变化、伏笔、字数/章节预估和状态。作者可以拖动排序、直接编辑、锁定关键转折，或提出“第二卷节奏太慢”之类的自然语言意见。

AI 返回影响方案与可预览 revision。作者确认前，不改变当前路线图。

### 4.4 批次生成阶段：轻量确认，明确运行

点击 `AI 写作` 或输入“继续写 20 章”后，显示轻量确认卡：

```text
本批范围：第 21–40 章
预计正文：约 60,000 字
创作方案：热血升级流（写作：Cursor Claude；审阅：OpenAI）
预算：订阅额度 / API 上限
自动审阅：连续性、人物、因果、节奏、伏笔

[开始创作] [调整] [取消]
```

只有章节数、预算、模型方案和范围等可验证参数使用控件；作者可以从对话输入自然语言，系统将其解释后放入确认卡。

运行画布显示章节队列、当前步骤、预算进度和可恢复错误。默认不显示 planner、writer、reviewer 等内部角色，只有“查看运行详情”才展开。

### 4.5 批次审阅阶段：候选队列与编辑器

批次结束后，正文编辑器成为中栏主画布，左侧显示候选队列，右侧显示 AI 对话、自动审阅和影响方案。

```text
候选队列                 当前第 7 章                   审阅与对话
✓ 第 1 章已定稿          正文 / 修订差异               连续性：通过
✓ 第 2 章已定稿          直接编辑                      人物：需注意
● 第 7 章待审阅          [定稿] [重写] [废弃]          作者意见输入
○ 第 8 章待审阅
```

作者可直接改正文、选择一段交给 AI 修改、对全章或整批提出意见。直接编辑后，系统说明可能影响的后续候选；AI 修改前先展示影响方案。

### 4.6 正常写作与资产控制

正文页面是成熟写作阶段的默认工作面。作者可完全自行写作；右侧 AI 对话只在作者主动输入或选择文本时参与。

人物、世界观、大纲、时间线、事实、伏笔页面不是创作前的必填步骤，而是：

- 查看 AI 当前依据；
- 直接修改和锁定；
- 让 AI 提出新增/修改候选；
- 追溯证据与影响范围。

例如“设计三个有压迫感的反派”会生成三张人物候选卡，而不是仅在对话中产生三段文本。

### 4.7 导入续写

导入中心先显示文件、卷章切分、重复检测和原始文本范围，再显示 AI 抽取候选。

结构化候选按类型分组：大纲、人物、世界观、关系、事件、时间线、事实和伏笔。每项可展开原文证据，支持确认、编辑、拒绝和重新分析。确认完成后提供 `进入 AI 创作驾驶舱并继续写作`。

## 5. 对话设计

### 5.1 对话不是通用聊天

每条消息都关联当前作品、阶段、选中对象和 canonical head。输入框上方使用可移除标签展示上下文：

```text
[第 7 章] [选中文字 286 字] [当前批次] [人物：沈砚]
```

作者可用 `@` 选择章节、人物、大纲节点或世界规则，但不要求学习命令语言。对话历史保存在本地，并可按阶段、章节、批次或资产筛选；不同作品的对话绝不混入。

### 5.2 回复类型

AI 回复只能属于下列之一：

| 类型 | 界面表现 | 是否改变正式数据 |
| --- | --- | --- |
| 说明/建议 | 普通消息 | 否 |
| 选择方案 | 可比较卡片 | 否，直到选择/确认 |
| 结构化修改 | 差异候选卡 | 否，直到接受 |
| 影响分析 | 范围、成本与动作 | 否，直到确认 |
| 运行进度 | 队列与状态卡 | 不直接改正文 |
| 错误恢复 | 原因、保留状态和下一步 | 否 |

AI 不能只在消息中说“我已修改”；所有修改必须指向候选 revision 或已执行操作。

### 5.3 对话输入与发送

- 支持多行输入，`Cmd/Ctrl+Enter` 发送；
- 发送前显示将要引用的文本、章节和模型连接；
- 流式输出不强行滚动作者正在阅读的正文；
- 发送失败保留作者输入，可重试或编辑；
- 长对话可压缩显示，但原始消息可查看；压缩摘要不能替代正式资产与证据。

## 6. 确认、差异与危险操作

### 6.1 确认层级

| 操作 | 所需确认 |
| --- | --- |
| 选择故事方向 | 明确选择卡操作 |
| 应用作品方案 | 分区/整套确认 |
| 开始批次 | 章节、预算、模型来源确认 |
| 重写候选 | 影响方案确认 |
| 定稿章节 | 定稿操作，可查看自动审阅 |
| 覆盖历史正文 | 二次确认并创建候选/恢复点 |
| 废弃候选 | 明确废弃，保留审计记录 |
| 切换到收费 API | 预先授权或本次确认 |

### 6.2 差异阅读

所有文本、方案和资产修改可切换：`当前版本`、`候选版本`、`并排差异`、`影响说明`。差异默认突出作者修改、锁定字段和会影响后续正文的事实。

## 7. 模型连接与设置

模型设置是应用级独立页面，而非作品工作台中的必填表单。

页面分为：

- API 连接：OpenAI、Anthropic、兼容接口；
- 订阅连接：用户本机已登录的 Codex 与 Cursor 官方运行时；
- 创作方案：为规划、写作、审阅、记忆和影响分析分配模型；
- 作者模板：选择和管理 AuthorProfile/AuthorTeam；
- 高级详情：能力、Token、上下文、回退、运行日志。

每个模型显示来源、健康状态、可用能力、模型目录、预算语义和测试结果。订阅连接明确标注为订阅来源，不假装是底层模型厂商 API。

## 8. 状态、错误与恢复

用户可理解的状态优先于技术码：

- `正在为第 7 章规划场景`；
- `第 8 章等待自动审阅`；
- `Cursor 登录已失效，请在官方窗口重新登录`；
- `本批 API 预算已到上限，已保留 6 章候选`；
- `影响方案已过期，因为第 7 章刚刚被定稿`。

错误卡必须给出可执行动作：继续、重新登录、选择替代模型、重试当前步骤、查看保留候选、取消或稍后处理。错误不显示正文、密钥、SQL 或内部堆栈。

应用重启后，驾驶舱根据持久化状态恢复当前阶段、批次队列、候选、待确认操作和可恢复任务；不依赖内存中的聊天流事件。

## 9. 视觉与可访问性

- 正文阅读区优先保证行宽、字体、段落和差异可读性；
- 状态既使用文字也使用形状/图标，颜色不作为唯一信息；
- 卡片操作使用动词标签，例如“确认方案”“定稿本章”“查看影响”；
- 键盘焦点在导航、编辑器、对话和候选队列之间稳定移动；
- 选中文字打开对话后，可返回原位置；
- Windows/macOS 使用各自惯用的快捷键和文件对话框；
- 第一版只优化桌面窗口，不设计移动端。

## 10. 交互验收

1. 新作者可以只用一句创意进入三方向比较，不会被强制要求填写大纲、人物或世界观。
2. 所有 AI 产生的可应用内容都有卡片、候选、差异或确认动作，不会因一条聊天回复静默生效。
3. 作者可以直接编辑正文、作品方案和故事资产，并且能看到由此导致的后续影响。
4. 作者可从对话开始 1–50 章批次，但在运行前始终看到范围、模型来源和预算。
5. 运行、暂停、恢复、错误、重试和定稿对不懂技术术语的作者仍可理解。
6. 导入抽取结果可回看原文证据；确认后进入与原创作品相同的驾驶舱和批次流程。
7. API 与订阅模型的费用来源和回退行为在 UI 中可辨认；不出现静默收费。
