# 产品基线

## 产品定位

织境 Story Studio 是面向长篇小说作者的本地优先桌面创作系统。它不是单纯的 AI 文本生成器，而是把小说正文、结构化故事资产、作者控制、异构模型协作和可恢复版本历史统一在一个项目中。

## 已确认的核心能力

1. 在桌面软件中按卷、章节和场景查看、编辑正文。
2. 直接查看和调整全书、分卷、故事弧、章节与场景大纲。
3. 管理主角、配角、人物弧、戏份目标、势力及归属。
4. 管理世界规则、地点、物品、伏笔和地图。
5. 查看并编辑角色、势力、地点等实体的关系拓扑。
6. 查看多轨时间线，并把事件与角色、势力、地点和章节关联。
7. 导入已写小说，分析正文并重建大纲、角色、世界、关系和时间线，随后继续创作。
8. 作者可以调整大纲、角色戏份、文风、禁写项和设定，并选择影响范围。
9. 多智能体可以分别使用不同供应商和模型进行规划、写作、审稿、事实检查和仲裁，降低单模型自洽偏差。
10. 支持项目快照、分支、安全恢复和完整项目导入导出。

## 产品原则

- 本地优先：正文和核心资产默认保存在本机。
- 作者主权：模型建议必须可审阅、拒绝、回滚和追溯。
- 事实可证：重要事实、冲突和审稿意见应关联正文证据。
- 异构复核：关键审稿流程应支持跨供应商、跨模型盲审。
- 长篇连续性：任何生成都必须受故事状态、时间线、知识和未回收伏笔约束。
- 商业可交付：从一开始考虑许可证、升级、签名、崩溃恢复、数据迁移和隐私。

## 当前阶段边界

正式桌面产品已经完成 P3 智能创作运行闭环和 P4 小说导入基础：P0 本地项目与章节编辑基础、P1 结构化故事世界、P2 可审阅变更/版本历史/项目快照/剧情分支均已落入正式 Go + SQLite 架构。P3 现已支持 OpenAI Responses 与 Anthropic Messages 流式协议，API Key 仅存 macOS Keychain 或 Windows Credential Manager；作者可以为规划、正文写作和连续性审阅分别配置连接与模型，且正文与审阅必须异构。系统按 `context-v2` 清单组装并按优先级裁剪项目上下文，确认事实、目标章节大纲和场景始终作为硬约束；运行会固化令牌与上下文预算、记录 Provider 实际用量，支持取消、独立重试并阻止运行期间切换分支或恢复快照。P4 第一切片现已支持 TXT/Markdown 原稿安全归档、编码识别、SHA 重复检测、确定性卷章切分、持久化任务、作者预览选择和正式章节原子应用；原始正文保留在本地项目包，UI 只接收有界预览。下一阶段基于持久化章节和原文行范围实现分章模型抽取、跨章合并，以及故事线、人物关系、大纲、世界设定和时间线候选的逐项确认。所有智能体产物仍作为待确认候选提交，绝不直接覆盖正文或结构化资产。
