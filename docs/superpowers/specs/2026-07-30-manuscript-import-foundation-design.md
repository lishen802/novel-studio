# P4 小说导入与结构化重建基础设计

- 日期：2026-07-30
- 状态：已批准实施
- 前置规格：`2026-07-15-commercial-product-design.md`
- 本次范围：P4 第一条可验收导入纵向切片

## 1. 目标

让作者在已打开的本地项目中选择一份 TXT 或 Markdown 小说文件，安全地完成原文留档、编码识别、章节切分、导入预览和原子写入。导入过程必须保留稳定的任务记录，为下一切片的分章模型抽取、跨章合并、证据化候选和逐项确认提供数据基础。

本切片完成后的最小闭环：

```text
选择 TXT / Markdown
→ 校验格式与大小
→ 识别编码并规范换行
→ 计算 SHA-256、阻止重复导入
→ 把原文件只读副本保存到项目 imports 目录
→ 识别卷/章节标题并生成预览
→ 作者选择要导入的章节
→ 单事务创建正式章节与初始 revision
→ 保留导入任务、原文位置和内容哈希
```

## 2. 方案选择

### 2.1 采用：分阶段暂存管线

确定性解析、模型重建、人工确认和正式应用是四个独立阶段。每个阶段只消费前一阶段的持久化输出，不通过 UI 内存传递整本小说。

优点：

- 长篇任务可以暂停、恢复和重跑；
- 原始证据和模型推断不会混入正式故事数据；
- 后续可增加 DOCX、EPUB 或本地模型而不改变正式故事领域；
- 失败不会产生半本小说或部分结构化资产。

### 2.2 不采用：整本书一次模型调用

该方案无法稳定覆盖长篇上下文，失败后难以恢复，也不能解释跨章实体合并依据。

### 2.3 不采用：解析后直接写正式数据

该方案缺少作者预览与拒绝点，章节误切分会直接污染项目，不符合作者主权和候选变更原则。

## 3. 本次范围

### 3.1 包含

- TXT、Markdown 文件选择。
- 最大 20 MiB 文件限制；空文件和不支持的扩展名被拒绝。
- UTF-8、UTF-8 BOM、UTF-16 LE/BE 和 GB18030 文本识别。
- CRLF/CR 统一为 LF；解析不修改用户原文件。
- 原文件 SHA-256、字节数、编码、格式和归档相对路径。
- 中文数字/阿拉伯数字章节标题、Markdown 标题和 `Chapter N` 识别。
- 卷标题识别，并把卷名保存为章节候选的分组信息。
- 无标题文本降级为单章“导入正文”。
- 每个章节候选保存标题、正文、顺序、原文行范围和内容哈希。
- 导入任务列表、详情、失败摘要和删除未应用任务。
- 作者选择章节后一次事务写入正式章节与初始 revision。
- 应用完成后任务不可再次应用；同一项目相同源哈希不可重复准备。
- 正式 React 导入中心与 Wails 薄绑定。
- `ImportManuscript` 授权能力门禁；V1 默认放行。

### 3.2 不包含

- DOCX、EPUB、压缩项目包解析。
- 人物、势力、地点、关系、事件、伏笔、故事线和大纲的模型抽取。
- 跨章人物消歧和候选合并。
- 抽取任务队列、暂停、继续和模型费用预算。
- 把结构化候选应用到正式故事资产。
- 从欢迎页直接创建项目并导入。

这些能力在 P4 后续切片中基于本设计的 Import Job、Source、Chapter Candidate 和 Evidence 契约继续实现。

## 4. 架构边界

```text
React ImportWorkbench
  ↓ StudioClient
Wails DesktopAPI（文件选择 + 薄转发）
  ↓
workspace.Service Import Use Cases
  ├── 授权与活动项目校验
  ├── 导入任务编排
  └── 预览/应用视图
  ↓ ports
  ├── ImportSourceArchive
  └── ImportStore
  ↓ adapters
  ├── projectfs Import Archive
  └── SQLite Import Store
```

章节解析器是纯 Go 包，只接收已解码文本并返回确定性结果；它不依赖文件系统、SQLite、Wails 或 Provider。平台适配器负责把不可信文件限制在项目 `imports/` 目录中。SQLite 适配器负责暂存记录和章节应用事务。

## 5. 领域模型

### 5.1 ImportJob

- `id`
- `project_id`
- `source_name`
- `source_format`: `txt` / `markdown`
- `source_encoding`
- `source_hash`
- `source_bytes`
- `archived_relative_path`
- `status`: `prepared` / `applied` / `failed`
- `chapter_count`
- `selected_chapter_count`
- `error_code`
- `error_message`
- `created_at`
- `updated_at`
- `applied_at`

`prepared` 任务可以预览、选择和应用；`applied` 任务只读；`failed` 任务保留安全错误摘要，不保留调用栈或任意磁盘路径。

### 5.2 ImportChapter

- `id`
- `job_id`
- `volume_title`
- `title`
- `body`
- `position`
- `source_start_line`
- `source_end_line`
- `content_hash`
- `selected`
- `created_chapter_id`

原文行范围使用一基、闭区间。后续所有证据片段均引用 `import_chapter_id + 行范围`，不依赖可能变化的正式章节正文。

## 6. 文件安全与归档

- 文件选择只接受 `.txt`、`.md` 和 `.markdown`。
- 在读取前后检查文件大小，避免替换竞态绕过限制。
- 拒绝目录、符号链接、设备文件和超过限制的文件。
- 归档文件名只使用任务 ID 和已验证扩展名，不使用用户输入拼接路径。
- 使用临时文件写入后原子重命名，权限为当前用户可读写。
- 数据库只保存项目内相对路径，避免把作者本机绝对路径暴露给 UI、日志或快照。
- 删除未应用任务时先删除数据库记录，再尽力清理对应归档；归档清理失败不破坏数据库一致性。

## 7. 解析规则

1. 去除文本开头 BOM，统一换行，但保留正文中的空行和全角字符。
2. 优先识别明确章节标题：
   - `第十二章 标题`
   - `第 12 回：标题`
   - `Chapter 12 - Title`
   - Markdown `# / ## / ###` 加上述章节形式
3. 单独的 `第X卷` 或 Markdown 卷标题更新当前卷，不生成空章节。
4. 标题行不进入正文；正文去除首尾空白，内部格式不改变。
5. 标题重复不自动合并，每个出现位置仍是独立章节。
6. 没有章节标题且存在正文时生成一个“导入正文”候选。
7. 解析结果为空时任务准备失败，且不得留下可应用任务。

## 8. 应用与一致性

- 作者必须至少选择一个章节。
- 应用事务重新读取任务状态并拒绝重复应用。
- 新章节追加在当前章节列表末尾，保持导入候选顺序。
- 每个新章节使用现有 `Chapter` 领域构造器并建立初始 revision。
- 事务全部成功后回填 `created_chapter_id`，更新任务为 `applied`。
- 任一章节或 revision 写入失败时整个事务回滚。
- 导入任务应用期间阻止分支切换、分支合并和快照恢复；应用前建立恢复点属于后续增强。

## 9. UI

在作品侧栏新增“导入分析”入口。第一版界面包含：

- “选择小说文件”按钮；
- 当前任务状态、格式、编码、大小、哈希摘要和章节数量；
- 按卷分组的章节列表；
- 章节标题、字数、源文件行范围和正文预览；
- 全选/取消全选与逐章选择；
- “导入所选章节”按钮；
- 已应用任务显示创建的章节数量，不允许再次提交；
- 错误使用中文安全摘要，不显示 SQL、堆栈或绝对路径。

导入完成后刷新 Workspace 章节列表，作者可以直接进入正文编辑。原型中的模拟实体抽取不复制到正式 UI。

## 10. SQLite v13

新增：

- `import_jobs`
- `import_chapters`

索引和约束：

- `import_jobs(project_id, source_hash)` 唯一；
- `import_chapters(job_id, position)` 唯一；
- `created_chapter_id` 外键指向 `chapters`；

- 删除未应用任务级联删除章节候选。

迁移必须保留 v12 项目数据，并通过 fresh schema 与 v12→v13 升级测试。

## 11. 后续结构化重建契约

下一切片新增 `import_runs`、`import_candidates` 和 `import_evidence`：

```text
ImportChapter
→ 章节摘要与局部实体/事件候选
→ 按规范名和别名做跨章候选合并
→ 全局故事线/大纲/关系/世界结构候选
→ 作者逐项确认、修改、合并或拒绝
→ 通过统一 ChangeSet 写入正式故事资产
```

候选状态固定为 `inferred`、`confirmed`、`conflicted`、`rejected`。每条模型候选至少有一个原文证据；模型无法提供证据时只能作为低置信度建议，不能成为事实候选。

## 12. 测试与验收

1. UTF-8、UTF-16 和 GB18030 中文样本能产生相同章节结构。
2. 中文章回、阿拉伯数字、Markdown、英文标题和无标题正文均有金标测试。
3. 相同输入产生相同章节顺序、行范围和内容哈希。
4. 不支持格式、空文件、符号链接和超限文件不创建任务或归档。
5. 相同源文件在同一项目被识别为重复，不影响其他项目。
6. 应用所选章节是单事务；注入失败后正式章节和任务状态均不变化。
7. 应用成功后重启仍可看到任务与创建章节映射。
8. 旧 v12 项目升级后原数据不变。
9. React 测试覆盖选择、预览、逐章勾选、应用和错误。
10. Go Race、前端测试/类型检查/构建、macOS production build 和 Windows 编译门禁通过。
