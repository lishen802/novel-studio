# AI 主创作长篇小说平台设计

- 日期：2026-08-04
- 状态：已确认，待实施计划
- 产品定位：中文网络长篇小说的本地优先 AI 主创作平台
- 前置：既有 Go + Wails v2 + React + SQLite 基线、项目包、版本与候选变更机制
- 交互规格：`docs/superpowers/specs/2026-08-04-ai-first-authoring-interaction-design.md`

## 1. 设计结论

织境的主产品不应是“作者先维护资料、AI 再辅助一章”的故事管理工具，而应是 AI 主动承担构思、作品方案、章节规划、正文生成和自动审阅的长篇小说创作平台。作者拥有方向、评价、修改、定稿与回滚的最终权利。

大纲、人物、世界观、关系、时间线、事实与伏笔仍是产品的核心数据，但它们的产品角色改变为：AI 长篇创作的受控长期记忆，以及作者随时查看、修改和锁定的控制面板。它们不是开始创作前必须手工填完的表单。

第一版成功的最低标准是：作者只提供一句中文网文创意，即可获得原创作品方案、确认全书章节路线图，并以“有界批次生成、自动审阅、作者定稿、长期记忆更新”的方式持续完成数十万字小说。产品架构必须可向百万字级长篇延展。

## 2. 目标与非目标

### 2.1 目标

1. 作者可以从一句创意、已有设定或已有正文开始。
2. AI 主动提出三套明显不同的原创故事方向，作者选定、修改或要求重做。
3. AI 将选定方向组织为完整、可编辑的《作品方案》，包含故事定位、创作规格、主线、主要人物、世界观、关系、冲突、结局方向、全书结构和章节节奏建议。
4. 作者确认作品方案后，AI 创建全书章节路线图；写作时只细化当前章节或当前批次的章节计划。
5. AI 可以连续生成一批正文候选，每批最多 50 章；每章均经过自动连续性、人物和节奏审阅。
6. 批次必须等待作者审阅和定稿后才能继续生成下一批。
7. 作者可以直接编辑、替换正文、添加自然语言意见或要求重做。AI 先给影响分析和修改方案，获确认后才重写受影响的候选章节。
8. 作者已定稿的内容成为正式事实与后续创作依据；候选稿永远不能静默覆盖正式内容。
9. 系统自动维护章节摘要、人物状态、事实、关系、未解决冲突、伏笔和当前剧情状态，避免作者手工整理长篇上下文。
10. 支持导入小说后自动抽取大纲、人物、世界观、时间线等候选资产，作者按原文证据确认后续写。

### 2.2 非目标

- 不把 AI 变成未经作者控制的无人值守整书发布器。
- 不要求作者理解 Provider、模型、Token 或上下文窗口才能开始写作。
- 不照抄、续写或改写参照小说的角色、专有名词、世界设定、具体情节链、场景或文字表达。
- 第一版不实现在线 AI 作者市场、真人作者撮合、平台代付模型额度、网页全文抓取或第三方 Provider 扩展。

## 3. 核心用户路径

### 3.1 从创意开始原创长篇

```text
一句创意 / 题材
→ AI 生成三套原创故事方向
→ 作者选择、编辑或重做
→ AI 生成完整《作品方案》
→ 作者确认核心设定、大纲、人物和世界观
→ AI 生成全书章节路线图
→ 作者输入创作指令并选择本批章节数（最多 50）
→ AI 逐章：计划 → 正文 → 自动审阅/修订
→ 批次等待作者审阅
→ 作者定稿、修改、重做或废弃
→ 更新正式事实与长期记忆
→ 下一批创作
```

创作规格例如预计字数、章节数、目标读者和叙事视角可以由 AI 建议，也可以由作者任意时点自行设置或修改。产品不将它们设计为强制前置表单。

### 3.2 参照作品启发创作

作者可以提供短篇全文、精选片段、简介/百科文本或公开简介链接。短篇可以完整分析；对于长篇，产品不将整本正文重复发送给模型，而是使用作者提供的摘要、片段或页面简介。

```text
参照材料
→ 读取公开简介或本地材料
→ AI 输出“类型与创作要素分析”
→ 展示借鉴的高层特征与明确避开的内容
→ 作者确认分析报告
→ AI 生成原创故事方向
→ 进入原创长篇主路径
```

链接模式只读取作者指定页面的公开可读内容，不自动追踪链接、不爬取原作全文。参照分析必须明确记录来源与发送给模型的数据范围。

### 3.3 导入小说并续写

```text
导入本地小说
→ 确定性归档、编码识别、卷章切分与原文行范围
→ AI 分章抽取候选大纲、人物、关系、世界观、事实、事件和伏笔
→ 跨章候选合并与冲突保留
→ 作者按原文证据确认、修改或拒绝
→ 形成已确认《作品方案》与长期记忆
→ 从最后已写章节进入批量续写
```

导入抽取产物必须是候选，不能直接写入正式故事资产。当前 P4 已完成确定性导入基础；本规格要求补齐模型抽取、跨章合并、证据审阅和续写接入。

## 4. 作者控制与创作状态

### 4.1 阶段确认

AI 默认在以下阶段等待作者确认：

1. 原创故事方向；
2. 《作品方案》的核心设定；
3. 对候选批次的章节定稿；
4. AI 提出的影响分析和修改方案。

作者可接受、编辑、删除、锁定、要求重做或自己从空白写起。作者直接写下或确认的内容优先级最高。

### 4.2 有界连续创作

作者在“AI 写作”入口通过自然语言指令、可见章节数量控制或两者共同指定创作批次。系统硬性限制单批最多 50 章，并在运行前显示本批章节数、预计 Token/费用和预算上限。

每章在后台经历“章节计划、正文生成、自动审阅与必要修订”，然后进入批次候选队列。批次完成后必须等待作者处理；只有当前批次全部定稿、重写完成或明确废弃，才能启动下一批。

### 4.3 正式状态与候选状态

| 内容 | 候选状态 | 正式状态 |
| --- | --- | --- |
| 正文 | 可生成、自动审阅、改写和废弃 | 作者定稿后进入章节正文 |
| 作品方案资产 | AI 或导入抽取候选 | 作者确认后进入正式故事资产 |
| 长期记忆 | 可参考但必须标记为临时 | 仅由定稿正文和确认资产更新 |

候选稿可以在同一批内作为临时连贯性参考，但不能成为下一批的正式事实依据。

### 4.4 修改与影响分析

作者可对一章或整批候选稿给出修改意见。系统先生成影响分析，包含受影响章节、不会受影响章节、修改理由和建议操作；作者确认后才生成新候选稿。

对长篇中途改设定，默认采取前向影响优先：分析和更新当前进度之后的未定稿章节、后续大纲和未来创作计划。距离当前很远的已定稿正文不主动建议重写；发生冲突时仅提示，除非作者明确要求才提出历史修订候选。

所有重写都必须保留前后版本、修改理由、影响范围和作者决定。

## 5. 长期记忆与上下文

系统在作者定稿一章后自动更新：章节摘要、关键事件、人物当前状态与关系、确认事实、已知信息、世界规则、伏笔状态、当前故事阶段、未解决冲突和后续必须承接的内容。

上下文装配优先使用已确认作品方案和已定稿长期记忆；当前批次候选仅以临时、可追溯的方式加入。上下文必须有字符和 Token 预算、确定性裁剪、包含/遗漏说明与版本化 Manifest。模型失败、预算超限或应用崩溃不得污染正式正文与正式事实。

## 6. 产品信息架构

### 6.1 首页与作品入口

首页优先展示三种入口：

1. 从一个想法开始；
2. 导入小说并续写；
3. 继续创作。

新建作品后，默认进入 AI 创作驾驶舱，而不是先进入资料管理页。

### 6.2 AI 创作驾驶舱

驾驶舱是作品的主视图，提供自然语言创作指令、当前阶段、批次章节数、最多 50 章约束、预算摘要、生成进度、自动审阅结果、待定稿队列、影响分析和下一步操作。

作者不必学习技术术语。模型、角色与参数默认隐藏；只在需要时显示“当前创作方案”和高级设置入口。

### 6.3 作品方案与故事档案

《作品方案》是一个整合视图，集中显示故事定位、创作规格、全书结构、人物、世界观、关系和节奏。大纲、人物、世界观、时间线与事实的专门视图保留，作为查看、编辑、锁定和追溯 AI 创作依据的工作台，而不是创作前置步骤。

## 7. 模型、凭据与运行时

### 7.1 应用级模型设置

模型连接、API Key、连接测试、默认创作方案和高级参数属于应用级设置，不属于某一部小说。API Key 仅存 macOS Keychain 或 Windows Credential Manager。

第一版模型连接分为 API 与订阅运行时。API 连接至少展示 OpenAI 和 Anthropic；订阅运行时展示用户已登录且通过能力验证的 Cursor 与 ChatGPT/Codex 连接。作者可以为不同小说选择不同的已配置创作方案，但无需再次输入密钥或配置技术角色。系统默认推荐规划、写作和审阅模型组合，并允许高级用户调整。

Cursor 中可用的 GPT、Claude、Gemini 等模型必须标明“来自 Cursor 订阅”；ChatGPT/Codex 订阅只表示当前账号拥有的 OpenAI/Codex 权益。订阅连接不得被描述为通用 API，不得静默切换到会产生额外费用的 API 连接。

### 7.2 运行安全

每个批次在外部模型调用前持久化运行、预算快照和章节范围。运行可取消、可恢复、可重试；达到预算或批次上限时停止后续调用。候选结果经过结构与引用校验后才进入审阅队列。

## 8. 未来 AI 作者市场

AI 作者市场是 V1 之后的联网扩展，不阻塞本地优先核心创作闭环。

市场提供可搜索、浏览和安装的 AI 作者人格与作者团，按玄幻、仙侠、都市、悬疑、言情、科幻等题材组织。模板可包含创作偏好、叙事与节奏约束、规划/写作/审阅分工、评估规则、版本、适配范围和授权信息。

模板不包含用户 API Key、用户作品正文或本地长期记忆。安装后，模板使用用户已在应用设置中配置的模型连接；用户可以将模板用于某部作品或某个创作阶段，并随时停用或替换。

第一版需要定义稳定的 Author Profile 与 Author Team 接口，以及本地安装和版本化语义；在线目录、搜索、分发、评价、商业授权和同步后续实现。

## 9. 迁移原则

现有 P0–P4 可靠性、项目包、SQLite、ChangeSet、版本、分支、导入归档、Provider、凭据隔离、运行恢复、预算与上下文裁剪必须保留并复用。

产品优先级调整如下：

1. AI 创作驾驶舱与“创意→作品方案→全书路线图→首批候选章节→定稿”闭环；
2. 有界批量创作、自动审阅、定稿驱动的长期记忆与影响分析；
3. 导入抽取、跨章合并、证据确认与续写接入；
4. 应用级模型设置与项目级创作方案引用；
5. Author Profile/Team 本地模板接口；
6. 在线 AI 作者市场。

现有以资料管理视图为中心的导航应在第一步改为 AI 创作驾驶舱优先。已存在的故事资产 UI 保留为作者控制面板。

## 10. 验收标准

1. 新作者仅输入一句中文创意，便可获得三套故事方向和完整候选《作品方案》，无需预先填写大纲、人物或世界观。
2. 作者确认作品方案后，可看到全书章节路线图，并能启动最多 50 章的连续创作批次。
3. 批次内每章完成自动审阅；批次结束后无法在未处理当前批次的情况下启动下一批。
4. 作者定稿一章后，系统能在后续创作上下文中使用该章摘要、事实、人物状态与伏笔。
5. 作者对候选章节或整批提出意见时，AI 先提供影响范围和修改方案；确认后仅重写受影响候选。
6. 已定稿历史正文不被 AI 自动改写；长篇中途变更默认只影响后续创作。
7. 导入 TXT/Markdown 小说后，系统可产生带原文证据的结构化候选；作者确认后能从最后章节继续创作。
8. 参照材料分析明确列出借鉴的高层特征与避开的内容；产品不自动抓取原作全文。
9. API Key 不进入项目包、数据库、日志、候选稿、市场模板或前端查询结果。
10. 模型调用失败、预算超限、中断恢复或候选重写不会损坏定稿正文、确认资产与长期记忆。
