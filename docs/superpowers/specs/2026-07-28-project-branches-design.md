# 完整项目剧情分支设计

日期：2026-07-28
状态：已批准

## 目标

为长篇小说创作提供真正的“剧情方案分支”。每个分支隔离整部作品的正文、故事架构、人物与势力、世界设定、时间线、事实、候选变更和版本记录，而不是只保存分支名称或部分章节。

第一版覆盖：

- 从当前作品状态创建分支；
- 查看分支血缘、当前分支和更新时间；
- 安全切换分支；
- 比较来源分支与目标分支；
- 预览并确认合并；
- 删除非当前、非主分支；
- 与旧项目包兼容，并能从中断的切换或合并中恢复。

## 产品语义

分支是指向一套完整作品状态的剧情方案，不是 Git 分支。作者可以在不同分支中尝试互斥情节，而不会污染其他方案。

项目始终有一个 `main` 主分支。旧项目第一次使用分支能力时，以当前 `project.db` 懒初始化主分支，不要求迁移或重新导入。

第一版只支持把子分支合并回直接来源分支，并采用严格快进规则：

1. 子分支创建时记录来源分支的内容摘要；
2. 合并时，来源分支必须仍处于该摘要对应的状态；
3. 如果来源分支在分叉后也发生变化，则阻止合并并提示冲突；
4. 成功合并后更新子分支的上游基线，因此同一子分支后续仍可继续快进合并；
5. 无变化的分支不能产生空合并。

这套规则避免第一版在正文、人物、事实等异构数据之间进行不可靠的自动三方合并。字段级三方合并属于后续版本。

## 存储设计

项目包继续以根目录的 `project.db` 作为当前活动工作数据库。新增：

```text
作品.zjproject/
  project.db
  branches/
    index.json
    heads/
      <branch-id>.sqlite
  snapshots/
```

`index.json` 是数据库之外的分支注册表，避免复制数据库时把过期的分支元数据一起复制。每个分支头是通过 SQLite 在线备份生成的一份完整数据库。

注册表记录：

- 分支 ID、名称、说明；
- 直接来源分支 ID；
- 来源分支最近一次同步时的摘要；
- 当前分支头摘要和单调递增代数；
- 创建、更新时间；
- 当前活动分支 ID。

数据库摘要使用 SHA-256。只有内容摘要改变时才增加分支代数，普通切换不会制造虚假变更。

## 安全切换

切换前先通过 SQLite 在线备份把当前工作数据库写入活动分支头。随后：

1. 将目标分支头复制到同目录暂存文件并落盘；
2. 将当前 `project.db` 改名为恢复备份；
3. 激活暂存数据库并清理 SQLite sidecar；
4. 原子写入注册表中的活动分支；
5. 应用服务重新打开数据库并校验项目身份；若失败则立即用原分支头执行反向安全切换；
6. 校验通过后向界面发布新的活动工作区。

应用启动或打开项目时先检查切换日志和恢复备份。若上次切换未完成，则回滚到最后一个完整状态。分支注册表使用临时文件、文件同步和原子改名提交。

## 比较与合并

比较读取来源和目标分支头，向作者展示：

- 新增、修改、删除的章节数；
- 章节标题和正文是否变化；
- 故事架构、人物世界、世界资产、时间线事实、候选变更等数据域的变化计数；
- 是否满足严格快进条件及阻止原因。

比较不修改项目。

合并必须分成预览与确认两步。预览返回一次性令牌及来源/目标摘要；确认时重新校验分支 ID、代数和摘要，防止作者预览后状态已变化。

第一版要求目标分支为当前活动分支。确认合并前：

- 刷新当前分支头；
- 自动建立项目恢复快照；
- 再次验证严格快进条件。

确认后以来源分支的完整数据库替换活动数据库，并把结果记录为目标分支的新分支头。来源分支保留，便于继续试写或审计。

## 边界与错误处理

- React 只调用 Wails 暴露的应用服务，不访问文件系统或 SQLite；
- Wails 绑定只做参数转发和错误净化；
- 应用服务负责许可校验、活动工作区互斥、预览时效和恢复点；
- 分支文件存储负责原子文件操作、注册表和中断恢复；
- SQLite 存储负责在线备份和只读比较数据；
- 不能删除当前分支、主分支或仍有子分支引用的分支；
- 切换、合并前必须先刷新编辑器的短周期草稿；
- 分支文件名只使用内部生成的安全 ID，不使用作者输入的名称；
- Windows 和 macOS 都只依赖同一文件系统原语，不引入 CGO 或 Rust。

## 非目标

第一版不实现：

- 任意两个无血缘分支的自动合并；
- 正文段落级或实体字段级三方冲突解决；
- 云端同步、多人协作或跨设备分支共享；
- Git 仓库导入导出；
- 分支历史压缩和增量块存储。

这些能力可以在完整项目分支的稳定存储契约之上继续演进。
