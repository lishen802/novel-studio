# 默认浅色主题设计

## 目标

将生产桌面应用的全部已实现界面统一为原型定义的浅色文学工作台。首页、作品工作台、设置、表单、弹窗、加载/错误状态和所有状态提示使用同一套色彩层级；不改变业务流程、Wails/Go 接口、持久化数据或未实现能力的边界。

## 视觉基准

以 `prototype/contract/design-contract.md` 和 `prototype/src/index.css` 为唯一视觉基准：

- 画布 `#f4f6f8`，表面与弹窗 `#ffffff`，悬停表面 `#f8f9fa`；
- 边框 `#e8eaed` / `#d1d5db`，文字 `#1f2937` / `#6b7280` / `#9ca3af`；
- 主操作为 `#1a1f2e`，仅作为按钮、活动导航和图标强调，不能成为大面积页面底色；
- 状态提示以浅色语义面板表达：成功 `#059669`、警告 `#d97706`、错误 `#dc2626`、信息 `#2563eb`；
- 弹窗遮罩保留 `rgba(0, 0, 0, 0.55)`，弹窗自身始终为白色。

## 主题行为

- 当前版本固定为浅色，不读取系统外观，也不渲染深色主题；根节点声明 `color-scheme: light`。
- 应用设置中不再提供“深色”或“跟随系统”操作；现有 `theme` 枚举和历史设置值继续可由后端/客户端读取，以保持旧 settings.db 和 API 契约兼容，但不会影响渲染。
- 主题设置区域改为只读说明，明确应用当前遵循浅色文学工作台，避免用户选择一个不存在的外观。

## 实现边界

### 1. 令牌与应用壳

在 `styles.css` 顶层定义复用的浅色令牌，替换根画布、启动加载页、首页和通用按钮/输入的深色硬编码。首页已有的全窗口浅色壳保留，正常运行时不重建 React 标题栏，继续使用系统原生标题栏与菜单。

### 2. 作品工作台

将项目侧栏、一级导航、章节列表、只读/文件风险提示、工作区主画布和 AI 面板迁移为白色/浅灰表面。活动项使用原型的主色轻底与深色文字；正文、结构化资产和编辑器继续保持足够长时间阅读的对比度。AI 面板、归档二级导航和响应式三栏行为不变。

### 3. 设置、弹窗与表单

应用设置、项目操作错误、导入/确认/资产等对话框以及所有输入控件统一为白色表面、浅灰边框、深灰文字和主色焦点环。危险动作保留红色语义，不能因主题迁移而弱化确认或禁用状态。

### 4. 提示、空状态与未就绪状态

模型未配置、功能未就绪、只读、文件系统风险、导入/恢复状态、错误和成功反馈均使用原型的浅色提示面板或语义标签。文案继续报告真实后端状态；不添加原型 mock 数据，也不把未实现能力显示为完成。

## 非目标

- 不实现真正的运行时浅色/深色切换；
- 不修改 Go/Wails 主题枚举、设置数据库 schema 或模型/项目领域接口；
- 不调整原生 macOS/Windows 标题栏、菜单或窗口控制；
- 不改变导航信息架构、AI 面板行为、读写权限或任何业务功能。

## 验收与测试

1. 主应用、首页、工作台、设置和对话框的测试断言浅色壳/提示语义类，且不再依赖深色专用类；
2. 设置测试验证主题选择器不再暴露可切换的深色/系统选项，旧主题值仍不会导致渲染失败；
3. 工作台、AI 面板、只读与文件风险测试继续验证真实行为，并覆盖浅色提示容器；
4. 使用单线程 Vitest 完整回归、TypeScript 类型检查、生产构建和 `git diff --check` 验证；
5. 在 macOS 和 Windows 上执行现有桌面人工冒烟时，确认系统标题栏保持原生、所有页面无深色大面积底板、键盘焦点至少达到 3:1 对比度。
