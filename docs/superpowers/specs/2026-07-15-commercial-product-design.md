# 织境 Story Studio 商业桌面产品总体设计规格

- 日期：2026-07-15
- 状态：待用户评审
- 产品阶段：正式产品研发前总体设计
- 目标平台：Windows、macOS
- 技术基线：Go、Wails v2、React、TypeScript、Vite、SQLite
- 架构路线：本地优先的模块化单体，Rust 按 ADR-0002 准入

## 1. 执行摘要

织境 Story Studio 是一款 AI 原生的长篇小说创作桌面应用。它不是在传统编辑器旁增加聊天框，而是让多个专业智能体真正参与构思、规划、写作、审稿、修订、事实提取和续写，同时让作者对题材、大纲、人物、世界、故事线、章节目标、正文和修改范围保持最终控制。

正式产品采用本地优先的 Go 模块化单体架构。React 负责作者工作台，薄 Wails Binding 只暴露类型化应用用例；Go 承担领域、应用、持久化、智能体运行时、模型供应商和平台适配；SQLite 保存正文、故事状态、运行记录和版本数据；Rust 首版不进入依赖，只有满足 ADR-0002 的明确条件后才以隔离 Sidecar 引入。

V1 聚焦已有一定写作目标或能力、希望 AI 真正承担创作工作的作者。零基础用户只输入一句题材即可自动完成整本小说的低门槛创作模式放入 V1.5/V2，不阻塞 V1。

V1 不实现商业授权，但从第一天预留许可证接口、权益门禁、安装身份和授权状态。未来默认商业模型为 30 天试用；试用到期后需要激活或续期才能继续使用受许可功能。无论授权状态如何，用户始终可以打开、读取、备份和导出自己的作品。

## 2. 已确认决策

1. 产品必须能真正写小说，而不只是管理素材或给出建议。
2. 作者可以在任何阶段干预、修改、锁定、拒绝、重做和回滚。
3. V1 的核心用户是有创作目标或一定写作能力的作者。
4. 零基础自动成书是后续版本能力，V1 只为其预留引导与默认策略接口。
5. 导入小说后必须重建可视化故事系统，并在作者确认后继续写作。
6. 关键审稿流程必须支持跨供应商、跨模型的异构复核。
7. 正式实现采用 Go + Wails v2，Rust 首版为空。
8. 现有 `prototype/web` 是 UX 基线，不是生产架构或生产数据模型。
9. V1 不实现许可证和激活，但架构必须允许后续加入 30 天试用与续期激活。
10. 产品本地优先，正文和核心资产默认不上传到织境自有服务器。

## 3. 产品定位

### 3.1 一句话定位

织境是一款由多智能体真正参与长篇小说构思、写作、审稿和续写，并由作者全程掌控的本地优先桌面创作应用。

### 3.2 核心价值

- **真正产出**：智能体需要生成可用的故事方案、章节规划和正文，而不是只回答问题。
- **长篇连续性**：每次生成都受人物状态、世界规则、时间线、事实、伏笔和已写正文约束。
- **作者主权**：AI 产出默认进入候选变更，不静默覆盖作者作品。
- **证据可追溯**：导入分析、审稿问题和事实判断能回到具体章节和原文证据。
- **异构复核**：不同智能体可以使用不同供应商和模型，降低单模型自洽偏差。
- **本地优先**：作品、索引、版本和运行历史默认保存在用户本机。
- **商业可交付**：从第一天考虑迁移、恢复、签名、升级、授权和隐私边界。

### 3.3 不做什么

- 不把产品做成通用聊天机器人。
- 不要求作者通过 Prompt 工程才能完成创作。
- 不让模型在无记录、无审阅的情况下直接改写正式正文。
- V1 不提供实时多人协作、社区、素材市场或云端必需依赖。
- V1 不实现一句题材持续无人值守生成整本小说。
- V1 不加入 Rust、CGO/FFI 或微服务架构。
- V1 不追随 Wails v3 Alpha API。

## 4. 用户与使用场景

### 4.1 V1 核心用户：创作型作者

特征：已有题材、核心创意、部分人物、大纲或已写正文中的至少一项；可能有写作经验，也可能只是清楚自己想写什么。

主要目标：

- 把模糊创意发展为可执行的长篇结构。
- 让智能体完成章节规划和初稿，作者进行方向与质量控制。
- 让不同模型检查连续性、人物、因果、节奏和设定冲突。
- 在修改故事方向后了解影响范围，并安全地产生修订方案。
- 导入已有小说，快速看清作品当前状态并继续写作。

### 4.2 后续用户：零基础创作者

特征：只有题材偏好或一句需求，例如“写一本都市修仙小说”。

后续版本通过创意提案、合理默认值、术语翻译和阶段确认降低门槛。底层仍复用 V1 的领域、运行时和变更审阅能力，不另建简化数据模型。

### 4.3 用户不需要理解的内部概念

普通使用者不需要理解 Token、上下文窗口、任务图、Schema、温度、向量索引或供应商能力。专业设置可展开，但默认界面使用“创意程度”“审稿严格度”“费用上限”等作者语言。

## 5. 版本范围

### 5.1 V1：专业创作闭环

V1 必须交付：

1. 作品库与本地项目生命周期。
2. 正文、章节、场景、卷和五级大纲。
3. 角色、势力、地点、物品、伏笔和世界规则。
4. 事实、证据、人物知识边界和冲突状态。
5. 时间线、关系拓扑和层级方位世界地图。
6. TXT、Markdown、织境项目包导入导出。
7. 导入小说的结构抽取、证据审阅和续写准备。
8. 真实 Provider 接入和异构多智能体运行。
9. 章节规划、正文写作、四类审稿、仲裁、修订、事实提取和最终审校。
10. 候选变更、差异审阅、接受、拒绝、局部应用和回滚。
11. 自动保存、快照、分支、备份、恢复和崩溃续跑。
12. Windows/macOS 安装、签名、升级、安全凭据和隐私设置。
13. 授权边界的空实现与可测试权益接口，但不出现真实试用或激活 UI。

### 5.2 V1.5：低门槛与效率增强

- 一句话创意向导和题材模板。
- AI 提供多个核心创意、人物组合和故事承诺供用户选择。
- 术语简化模式和渐进式高级设置。
- 多章批量生产，但在卷或阶段边界设置作者确认点。
- 全书连续性审计、分支比较和影响分析增强。
- 本地模型和自定义 OpenAI-compatible 端点增强。
- 许可证、30 天试用、激活、续期和离线宽限正式上线。

### 5.3 V2：连接与生态

- 加密云备份与跨设备同步。
- 团队协作、评论、权限和冲突合并。
- 插件/扩展机制。
- 模板市场或工作流市场。
- 在新的架构决策后评估云端任务服务或 Wails 新稳定代际。

## 6. 核心用户旅程

### 6.1 从创意创建小说

```text
创建作品
→ 填写题材、核心创意、目标篇幅和已知约束
→ 智能体提出创作简报与可选故事方向
→ 作者确认人物、世界和故事承诺
→ 生成全书/分卷/故事弧大纲
→ 作者编辑或锁定关键节点
→ 生成当前章节规划
→ 生成正文候选
→ 异构审稿与仲裁
→ 作者审阅变更并应用
→ 提取事实、状态、伏笔和时间线
→ 进入下一章
```

V1 不要求所有项都填写。作者可以从一句核心创意、一个大纲或一组人物开始；缺少的信息由系统生成候选，必须经过确认后进入正式设定。

### 6.2 导入并续写

```text
导入 TXT / Markdown / 项目包
→ 识别编码、章节和卷结构
→ 保存原始导入快照
→ 分批抽取人物、势力、地点、物品、事实、事件和伏笔
→ 重建大纲、故事线、时间线、关系和世界结构
→ 生成冲突、低置信度和缺失项清单
→ 作者按证据确认、修正或拒绝
→ 生成“当前故事状态”与续写方向
→ 创建续写分支和恢复点
→ 进入章节创作闭环
```

系统不得把 AI 推测直接升级为正式事实。所有导入结论都必须具有以下状态之一：正文证实、作者确认、AI 推测、存在冲突、已拒绝。

### 6.3 作者改变方向

作者修改人物、大纲、世界规则、文风或故事线时，系统先计算影响范围，并提供：

- 仅影响未来生成；
- 更新未完成规划；
- 创建替代剧情分支；
- 为已写正文生成修订建议，但不自动应用。

修改前自动创建恢复点。作者可以锁定实体、章节、段落、事实或大纲节点，锁定内容不进入自动改写范围。

## 8. 功能模块设计

### 8.1 作品库

负责新建、打开、最近使用、复制、归档、导入、备份和删除作品。

要求：

- 默认显示项目健康状态、最近修改、字数、章节和未处理问题。
- 删除进入系统回收或可恢复区，不立即永久抹除。
- 同一项目只允许一个写实例；第二个进程以只读或提示方式打开。
- 打开前检查 Schema 版本、迁移状态和未完成恢复任务。
- 项目损坏时进入恢复模式，允许从最近备份或完整性检查结果恢复。

### 8.2 创作简报

统一保存目标读者、题材、叙事人称、POV 策略、语气、节奏、文风、禁写项、篇幅目标和创作红线。每次修改生成不可变修订版本，工作流绑定具体修订版本，保证结果可追溯。

### 8.3 正文与场景

- 章节按卷排序，场景属于章节。
- 场景可保存 POV、地点、人物、故事时间、目标、冲突和结果。
- 编辑器必须本地即时响应；保存由 Go 应用服务事务性完成。
- 支持章节、段落和选择区域的锁定。
- AI 续写、重写和润色返回差异候选，不直接修改正式正文。
- 对大量正文使用虚拟列表或分段加载，避免一次渲染全书。

### 8.4 五级故事架构与故事线

结构层级为全书、分卷、故事弧、章节、场景。故事线是跨多个结构节点的独立轨道，例如主线、感情线、成长线和反派线。

每个节点保存目标、冲突、转折、结果、状态和关联实体。拖动、重排或删除节点时，应用层执行不变量检查与影响分析。

### 8.5 角色、势力与知识边界

角色除基本资料外，保存动机、秘密、关系、状态、人物弧、戏份目标和按章节变化的知识。人物“知道什么”和“事实是什么”分开建模，支持误解、谎言和错误信念。

### 8.6 世界、地点、物品与伏笔

世界规则可作用于全书、区域、时期或实体。物品保存持有者与流转记录。伏笔保存埋设、推进、回收、截止章节和证据。

层级地图只表达父子层级、相对方位、相邻关系和故事关联，不承担 GIS 或真实比例功能。

### 8.7 事实与证据

每条事实保存：

- 事实文本和分类；
- 状态与置信度；
- 适用范围；
- 原文证据及章节位置；
- 创建者和最后确认者；
- 生效与失效的故事时间；
- 与冲突事实的关系。

模型输出只能创建“候选事实”。作者确认或可靠规则校验后，才能成为正式事实。

### 8.8 时间线与关系拓扑

事件同时保存故事时间和叙述顺序。角色、势力、地点和物品关系是带类型、强度、公开状态、真实状态和有效区间的边。

可视化布局属于用户视图状态，不作为故事事实。删除实体不会静默删除关系或证据，而是形成待处理引用清单。

### 8.9 导入分析中心

导入分为确定性阶段和模型阶段。

确定性阶段：编码识别、章节切分、卷识别、内容哈希、重复检测、原始文件留档。

模型阶段：人物消歧、关系、事件、世界、事实、伏笔、故事线和大纲抽取。所有结果按批次保存，支持暂停、恢复、重新分析和人工合并。

分析中心按“已确认、待确认、低置信度、冲突”分组。点击任何结论都能定位原文证据。只有作者确认的结果参与续写上下文。

### 8.10 智能体团队

内置角色：

- 剧情规划师
- 上下文编辑
- 正文写手
- 连续性审查
- 人物审查
- 因果审查
- 节奏审查
- 审稿仲裁
- 修订编辑
- 事实提取
- 最终审校

每个角色可绑定供应商、模型、创造性、结构化输出策略、费用等级和自定义说明。系统提供推荐配置，普通用户不必逐个设置。

### 8.11 工作流与审稿中心

默认章节流程：

```text
章节规划
→ 上下文装配
→ 正文写作
→ 并行异构盲审
→ 问题仲裁
→ 定向修订
→ 事实与状态提取
→ 最终审校
→ 作者应用变更
```

每一步可暂停、取消、重试或替换模型重跑。审稿问题必须保存严重度、类别、证据、建议、模型和处理结果。作者可以接受、忽略并记录原因，或调用不同模型进行二次复核。

### 8.12 候选变更中心

所有 AI 对正式作品的修改统一表示为 `ChangeSet`。变更集可以包含正文差异、结构调整、实体更新、事实候选和时间线更新。

作者可以：

- 整体接受或拒绝；
- 按文件、章节、实体或字段局部应用；
- 查看修改理由和证据；
- 在应用前编辑候选内容；
- 恢复到应用前状态。

变更集应用必须在单个数据库事务中完成，并生成版本记录。

### 8.13 版本、分支与备份

- 自动保存不是版本；每次编辑只保证数据持久化。
- 快照是命名恢复点。
- 分支是指向一组版本的剧情方案，不等同于 Git 分支。
- AI 大规模修改、导入、恢复和迁移前自动创建恢复点。
- 数据库版本记录只保存受影响对象的前后状态或补丁，并配合周期性完整备份。
- 备份轮换默认保留最近小时级、日级和周级副本，具体数量由设置控制。

## 9. 总体技术架构

```text
React UI
  ↓ 类型化命令/查询、事件订阅
Wails Binding（薄）
  ↓
Go Application Layer
  ├── Authoring Use Cases
  ├── Import Use Cases
  ├── Agent Use Cases
  ├── Version Use Cases
  └── License Gate
  ↓
Go Domain Layer
  ├── Manuscript
  ├── Story Structure
  ├── Story World
  ├── Canon & Knowledge
  ├── Agent Run
  └── Revision & Branch
  ↓ interfaces
Infrastructure Adapters
  ├── SQLite / Assets / Backup
  ├── Model Providers
  ├── Keychain / Credential Manager
  ├── Update / License / Telemetry
  └── Optional Rust Sidecar
```

### 9.1 模块化单体原则

- 单一桌面进程承担主要业务，降低个人项目的部署与调试成本。
- 模块通过 Go 接口和应用用例通信，不跨模块直接操作表。
- 数据库可以共享，但表和迁移拥有明确模块归属。
- 不通过网络调用拆分本机模块。
- 将来确需云服务时，复用应用接口和数据契约，不先行服务化。

### 9.2 建议目录

```text
apps/desktop/                Wails 配置与正式 React UI
cmd/novel-studio/            Go 进程入口和依赖组装
internal/domain/             纯领域模型与不变量
internal/application/        命令、查询、事务和授权门禁
internal/persistence/        SQLite、迁移、资产、备份、恢复
internal/agents/             任务图、上下文、运行记录、证据与预算
internal/providers/          云模型、本地模型和自定义端点适配
internal/platform/           Wails、凭据、更新、许可证、日志、文件关联
packages/story-schema/       前端契约、生成类型和验证器
packages/ui/                 设计系统与故事可视化组件
prototype/web/               已验收原型，保持独立运行
rust/sidecars/               仅保存获批的隔离 Rust 工具
fixtures/                    无敏感信息测试小说和模型样本
tests/                       跨层、迁移、恢复和桌面测试
```

### 9.3 Wails 边界

Wails 只负责窗口、生命周期、菜单、事件和 Go/TypeScript 绑定。Binding 方法只调用应用服务，不包含 SQL、业务规则或 Provider SDK。React 组件不得直接调用持久化、文件系统、凭据或模型供应商。

### 9.4 React 状态

React 状态分为：

- 服务端状态：来自 Go 的项目数据和查询结果，使用缓存与失效策略；
- 编辑草稿：尚未提交的表单或正文局部状态；
- 视图状态：选择、折叠、缩放、布局和筛选；
- 运行流：通过带 `runId` 和序号的事件更新。

正式 UI 不再使用 Zustand 持久化整个项目。Zustand 可以保留为轻量视图状态容器。

## 10. 领域边界

### 10.1 Manuscript 聚合

负责卷、章节、场景、正文、锁定和顺序。不负责模型调用或数据库。

### 10.2 StoryStructure 聚合

负责大纲节点、故事线、章节目标和结构不变量。

### 10.3 StoryWorld 聚合

负责角色、势力、地点、区域、物品、关系和事件。

### 10.4 Canon 聚合

负责事实、证据、置信度、人物知识、冲突和作者确认。

### 10.5 AgentRun 聚合

负责运行、步骤、尝试、状态转换、预算、产物和恢复。

### 10.6 Revision 聚合

负责变更集、版本、快照、分支和恢复点。

领域对象不依赖 Wails、SQLite、HTTP、具体模型 SDK 或许可证供应商。

## 11. 项目文件与 SQLite

### 11.1 编辑态项目包

```text
作品名.zjproject/
├── manifest.json
├── project.sqlite
├── assets/
├── attachments/
├── imports/
└── backups/
```

分享或完整导出使用 `.zjstory` 压缩包。导入 `.zjstory` 时先解压到临时目录、验证清单和数据库完整性，再原子移动到目标位置。

### 11.2 SQLite 策略

- 开启外键、WAL、busy timeout 和事务。
- 正文按章节与场景存储，不保存为单个整项目 JSON。
- 使用版本化迁移；每次启动先备份再迁移。
- 使用 FTS5 建立正文、实体、事实和设定全文索引。
- 模型运行记录和变更集与正式内容分表保存。
- 数据库只保存密钥引用，不保存 API Key。
- 驱动通过接口隔离；首阶段对纯 Go 与 CGO 驱动进行跨平台打包、FTS、备份和性能验证，默认优先纯 Go。

### 11.3 表组

- 项目：projects、project_preferences、preference_revisions
- 正文：volumes、chapters、scenes、locked_ranges
- 结构：outline_nodes、story_lines、story_line_links
- 世界：characters、factions、locations、world_regions、items、relationships
- 状态：events、facts、fact_evidence、character_knowledge、hooks
- 智能体：agent_profiles、workflow_templates、runs、run_steps、run_attempts、run_artifacts
- 审稿：review_issues、review_evidence、review_dispositions
- 版本：change_sets、change_operations、revisions、snapshots、branches
- 系统：schema_migrations、jobs、file_assets、integrity_events

具体字段和索引在单独 SQLite Schema 规格中定义。

## 12. 多智能体运行时

### 12.1 持久化模型

```text
Run
→ Step
→ Attempt
→ Artifact / ReviewIssue / Evidence
→ ChangeSet
```

运行前先写入 `Run` 和配置快照，再进行任何外部模型调用。每个步骤拥有幂等键、依赖、超时、最大重试、预算和取消状态。

### 12.2 状态机

运行状态：queued、running、paused、awaiting_author、completed、cancelled、failed、recoverable。

步骤状态：pending、ready、running、succeeded、failed、skipped、cancelled。

应用意外退出后，启动恢复器将无心跳的 running 步骤标为 recoverable。已获得完整模型响应且通过校验的步骤不重复请求；未完成流式响应的步骤根据 Provider 能力重试或由作者决定。

### 12.3 上下文装配

上下文编辑智能体根据任务生成 Context Manifest，记录：

- 所用章节和内容哈希；
- 大纲、人物、世界、事实、时间线和伏笔版本；
- 作者偏好修订；
- Token 预算和裁剪理由；
- 被排除的信息及原因。

正文写手只接收当前任务需要的上下文。各盲审智能体互不读取彼此结论，仲裁步骤才汇总审稿结果。

### 12.4 输出协议

模型输出优先使用 JSON Schema 或结构化格式。所有输出经过语法、Schema、引用完整性和领域规则校验。无效输出可以修复重试，但必须记录原始错误和费用。

### 12.5 预算

预算支持：

- 单次运行最大金额；
- 项目每日/月度提醒；
- 高费用模型确认；
- Token 和费用预估；
- 达到硬上限后停止新步骤，不中断本地编辑。

## 13. Provider Adapter

统一接口至少包含：

- 模型发现与能力描述；
- 文本/结构化生成；
- 流式响应；
- 取消与超时；
- Token、价格和用量；
- 限流与重试提示；
- 上下文窗口和最大输出；
- 数据保留与隐私标签；
- 健康检查。

V1 优先支持若干主流云供应商、本地模型入口和 OpenAI-compatible 自定义端点。具体供应商清单由独立能力矩阵确定，不在领域层硬编码。

Provider 错误统一转换为鉴权、网络、限流、配额、内容安全、上下文过长、响应无效、取消和内部错误。上层不解析供应商私有错误文本。

## 14. 错误、恢复与可观测性

### 14.1 错误分类

- Domain：违反故事或版本不变量
- Validation：输入、Schema 或引用无效
- Persistence：数据库、磁盘、迁移或备份失败
- Provider：鉴权、限流、配额和模型错误
- Platform：凭据、窗口、升级、权限和文件关联
- License：试用、激活、续期和权益错误
- Internal：未预期错误

### 14.2 数据安全规则

- 正式内容和结构化资产在同一事务中更新。
- 大规模变更前创建恢复点。
- 数据库写失败时不显示“已保存”。
- 磁盘空间不足时停止新模型任务并提示导出/清理。
- 崩溃报告不包含正文、Prompt、模型响应或密钥。

### 14.3 日志

日志包含运行 ID、步骤 ID、错误类别、耗时和匿名技术信息。正文只记录哈希或内部 ID。用户可以导出经过脱敏的诊断包。

## 15. 安全与隐私

- macOS Keychain 和 Windows Credential Manager 保存模型凭据。
- 数据库仅保存 credential reference。
- 凭据不得进入日志、项目包、备份、崩溃报告或测试夹具。
- 模型调用前显示将使用的供应商和大致数据范围。
- 项目可配置禁止某些内容发送给云模型，只允许本地模型处理。
- 导入文件按不可信数据处理；解析器限制大小、路径、压缩深度和资源消耗。
- `.zjstory` 解压必须防止路径穿越和压缩炸弹。
- 自动更新包和未来许可证令牌都必须验证数字签名。
- 产品不执行模型输出中的任意命令、脚本或文件路径。

## 16. 未来授权与激活设计

### 16.1 目标商业规则

授权功能正式上线后的默认规则：

- 首次注册试用后获得 30 个自然日试用期。
- 试用到期后需要激活购买或续期订阅，才能继续使用受许可功能。
- 在线许可证按有限周期签发本地可验证租约，支持短期离线使用。
- 到期、网络异常或许可证撤销不得损坏、删除或加密用户作品。
- 用户始终可以打开、读取、搜索、备份和导出作品。
- 到期后停止新建、编辑、导入和 AI 运行等受许可操作；恢复和导出不受限制。

V1 不启用这些限制。V1 使用始终返回有效基础权益的 `NoopLicenseService`。

### 16.2 授权边界

```go
type LicenseService interface {
    CurrentEntitlements(ctx context.Context) (EntitlementSnapshot, error)
    Activate(ctx context.Context, request ActivationRequest) (EntitlementSnapshot, error)
    Refresh(ctx context.Context) (EntitlementSnapshot, error)
    Deactivate(ctx context.Context) error
}
```

应用用例通过 `EntitlementGate` 检查能力，例如 `project.create`、`project.edit`、`import.run`、`agent.run` 和 `provider.custom`。领域层、SQLite Repository 和项目文件格式不感知授权。

### 16.3 授权状态

- not_required：V1 空实现或特殊发行版
- trial：30 天试用有效
- active：已激活或订阅有效
- grace：租约过期但处于离线宽限
- expired：试用或订阅到期
- revoked：许可证已撤销
- unavailable：授权服务暂时不可用

`unavailable` 不立即等同于 `expired`。已成功验证过的设备在本地签名租约有效期内继续工作，租约到期后进入 7 天宽限；宽限期结束才限制受许可写操作。具体天数由服务端策略下发，但客户端默认上限不超过 7 天。

### 16.4 激活与设备

- 首次激活生成随机安装 ID，不使用硬盘序列号等侵入式硬件指纹。
- 服务端可把许可证绑定到有限数量安装实例。
- 本地保存服务端签名的许可证租约、公钥版本和最后可信时间。
- 私钥只存在服务端；客户端只包含公钥。
- 检测系统时钟明显回退时要求联网刷新，但不影响读取和导出。
- 换机通过旧设备停用或账号后台释放设备名额。

### 16.5 从 V1 升级到授权版本

- 项目数据库不增加许可证字段。
- 授权状态保存在应用级数据目录，而非作品目录。
- 升级后首次启动先迁移应用设置，再显示试用/激活说明。
- V1 用户的过渡权益由发行政策决定，技术上通过服务端签发 entitlement 实现。
- 即使授权模块故障，项目恢复工具和命令行导出工具也能读取项目。

## 17. 自动更新与发布

- 更新通道分 stable、beta、internal。
- 更新清单和安装包必须签名。
- 更新前检查数据库迁移兼容性并创建备份。
- Windows 和 macOS 分别生成原生安装包。
- macOS 完成 Developer ID 签名和公证。
- Windows 完成代码签名、安装、升级和卸载验证。
- 许可证服务上线后，应用版本兼容性与许可证权益分开判断，不能用授权接口强制数据库迁移。

## 18. 非功能要求

### 18.1 性能目标

以包含 100 万中文字符、300 章、500 个故事实体的测试项目为基线：

- 冷启动到作品库可用：目标 3 秒内。
- 打开项目并显示当前章节：目标 2 秒内。
- 本地编辑回显：单帧内完成，不等待数据库。
- 自动保存提交：停止输入后 500 毫秒内开始，正常磁盘下 1 秒内确认。
- 全文搜索首批结果：目标 300 毫秒内。
- 普通实体列表和关系查询：目标 200 毫秒内。
- 取消模型任务：UI 100 毫秒内反馈，后端立即传播 Context 取消。

性能目标在正式基准测试后可通过独立规格收紧，但不得降低数据安全要求。

### 18.2 可靠性

- 任意进程崩溃后不丢失已确认保存的正文。
- SQLite 迁移失败可自动回到迁移前备份。
- Provider 失败不改变正式正文和正式事实。
- 未完成任务可以恢复、重试或安全取消。
- 项目导入导出可往返验证核心数据与资产哈希。

### 18.3 可访问性与易用性

- 所有主要操作可用键盘完成。
- 关键图表提供文本树或列表替代视图。
- 不以颜色作为唯一状态信号。
- 普通模式隐藏模型技术参数，高级模式按需展开。
- 错误提示说明影响、是否已保存以及下一步操作。

## 19. 跨平台设计

- 核心 Go 模块不包含平台条件判断。
- 平台适配器使用接口和 build tags 实现。
- 所有文件名经过 Windows 保留名、非法字符、长路径和大小写规则校验。
- 内部路径统一使用规范化相对路径，禁止在数据库中保存平台绝对路径作为资产身份。
- Windows 与 macOS 原生 CI 分别验证凭据、文件锁、菜单、窗口、更新、签名和安装。
- 高 DPI、缩放、中文输入法、休眠唤醒和网络切换纳入桌面验收。

## 20. 测试策略

### 20.1 测试分层

- Go 领域测试：不变量、状态机、影响范围和授权门禁。
- Go 应用测试：用例、事务、幂等、取消和恢复。
- SQLite 集成测试：迁移、FTS、备份、恢复、并发和完整性。
- Provider 契约测试：结构化输出、流式、错误映射、取消和费用。
- Agent 测试：上下文清单、盲审隔离、重试、预算和变更集。
- React 组件测试：编辑、候选变更、错误与空状态。
- Playwright：核心作者流程。
- 桌面 E2E：Wails Binding、窗口、文件和系统凭据。
- 平台测试：安装、签名、升级、卸载和授权状态。

生产功能使用测试驱动开发。真实供应商测试只在受控环境运行；普通 CI 使用无敏感信息的录制响应和本地假 Provider。

### 20.2 核心验收场景

1. 给定一个创意和人物，作者能生成大纲、章节规划和正文候选，并选择性应用。
2. 导入一部长篇小说后，系统能恢复章节、大纲、人物、关系、世界、时间线、事实和证据。
3. 作者修正导入事实后，续写上下文只使用确认后的版本。
4. 写手、盲审和最终审校可以来自不同供应商和模型家族。
5. 模型调用中断或应用崩溃后，运行可恢复且不重复应用正文。
6. 任意 AI 变更都能看到差异、来源、费用和运行记录。
7. 快照恢复前自动保存当前状态，并能再次回到恢复前版本。
8. Windows/macOS 均可安装、打开、编辑、备份、升级和卸载。
9. 未来许可证过期时，受许可写功能被限制，但作品仍可读取、备份和导出。

## 21. 实施阶段与退出门槛

### 阶段 0：规格冻结

完成并评审：

- V1 产品需求与验收标准
- 领域模型与不变量
- 项目包与 SQLite Schema
- 多智能体任务、上下文、证据和变更协议
- Provider 能力矩阵与凭据安全
- 许可证接口与权益模型
- Windows/macOS 发布与非功能测试

退出门槛：不存在影响首个纵向切片的未决产品或架构边界。

### 阶段 1：桌面与数据纵向切片

创建作品、打开作品、编辑章节、SQLite 自动保存、快照、重启恢复、导出，并在 Windows/macOS 上运行。

退出门槛：正文保存和恢复达到可靠性要求，Binding、领域和持久化边界得到验证。

### 阶段 2：故事系统

实现大纲、故事线、角色、势力、世界、事实、时间线、关系和地图。

退出门槛：同一份故事状态能被所有视图一致读取和编辑，引用完整性测试通过。

### 阶段 3：真实智能体闭环

实现 Provider Adapter、任务运行时、上下文装配、章节写作、异构审稿、变更集和事实提取。

退出门槛：至少两个不同供应商完成一次可恢复的章节生产闭环。

### 阶段 4：导入与商业交付

实现长篇导入分析、备份恢复、升级、签名安装、隐私和诊断。

退出门槛：两平台端到端验收通过，用户数据恢复演练通过。

### 阶段 5：授权与低门槛模式

在 V1 稳定后实现 30 天试用、激活、续期、离线宽限和一句题材创作向导。

退出门槛：授权服务故障或到期不会阻止作品读取、备份和导出；零基础用户能在不理解专业术语的情况下完成首个故事方案。

## 22. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 模型生成质量不稳定 | 结构化上下文、异构审稿、作者确认、提示版本和可回滚变更 |
| 长篇上下文超限 | 上下文清单、分层摘要、事实库、场景状态和证据检索 |
| 多模型费用失控 | 预估、预算、硬上限、费用等级和步骤级记录 |
| SQLite/项目损坏 | WAL、事务、完整性检查、迁移前备份和轮换备份 |
| 原型架构泄漏到正式代码 | 保持 prototype 独立；正式 UI 只复用 UX、样式和可拆组件 |
| Windows/macOS 行为不一致 | 平台接口、build tags、原生 CI 和双平台纵向切片 |
| 授权系统污染核心业务 | LicenseService、EntitlementGate、应用级状态、项目数据无授权字段 |
| 授权服务器不可用伤害用户 | 签名租约、离线宽限、读取/备份/导出永久可用 |
| Rust 增加维护成本 | 严格执行 ADR-0002，首版不引入，优先隔离 Sidecar |

## 23. 设计结论

织境正式产品应围绕“故事状态 + 可恢复智能体运行 + 作者审阅变更”构建，而不是围绕聊天记录或单次文本生成构建。模块化单体能在个人主导开发的现实约束下保持清晰边界、跨平台交付速度和长期维护能力。

V1 的成功标准不是页面数量，而是作者能够完成一次可信的闭环：从创意或导入小说出发，获得结构化故事状态，让异构智能体写出章节、发现问题、生成可审阅修订，并在任何失败情况下保住作品和版本历史。

许可证在 V1 中保持空实现，但接口、权益门禁和数据边界从第一天存在。这样后续加入 30 天试用、激活和续期时，不需要修改项目格式、领域模型或作者作品。
