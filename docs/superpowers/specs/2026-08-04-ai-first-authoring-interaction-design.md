# AI 主创作阶段自适应交互设计

- 日期：2026-08-04
- 状态：已确认，待实施计划
- 产品规格：`docs/superpowers/specs/2026-08-04-ai-first-long-form-authoring-design.md`
- 技术方案：`docs/specifications/2026-08-04-ai-first-long-form-runtime-design.md`

## 1. 设计结论

织境采用“对话驱动 + 结构化结果 + 正文编辑器”的混合交互，不做纯聊天软件，也不让作者依靠大量表单完成创作。

核心分工：

- 对话负责表达创作意图、评价、修改意见和下一步命令；
- 结构化页面负责展示方案、状态、差异、证据和确认节点；
- 正文编辑器负责阅读、直接修改、替换和定稿；
- 轻量控制卡负责章节数量、预算、模型方案和影响范围等精确参数。

新书构思阶段以对话为主；形成作品方案后，工作画布逐渐成为主区域；进入正文阶段后，以编辑器和待审阅章节队列为主，对话面板常驻或随时展开。

## 2. 方案选择

### 2.1 未采用：纯表单

纯表单要求作者先填写题材、人物、世界观和大纲，仍然把想象与规划工作交给作者，偏离 AI 主创作定位。

### 2.2 未采用：纯聊天

纯聊天容易开始，但作品方案、人物状态、批次进度、候选差异和定稿依据会被埋进聊天记录。长篇项目不能把聊天记录当作正式故事状态。

### 2.3 采用：阶段自适应混合交互

AI 的自然语言回复只负责说明和引导。凡是可能成为正式作品内容、故事资产、批次命令或修改操作的输出，都转换为可查看、可编辑、可确认的结构化对象。

聊天消息不是正式事实。只有作者确认的作品方案、故事资产和定稿正文才进入 canonical 状态。

## 3. 全局界面框架

桌面工作区由三个逻辑区域组成：

```text
┌──────────────┬────────────────────────────────┬──────────────────┐
│ 作品导航     │ 当前阶段工作画布               │ AI 创作对话      │
│              │                                │                  │
│ 创作驾驶舱   │ 方向卡 / 作品方案 / 路线图     │ 当前上下文       │
│ 正文与章节   │ 正文编辑器 / 批次审阅          │ 作者指令         │
│ 大纲         │ 人物 / 世界 / 证据 / 差异      │ AI 建议与动作卡  │
│ 人物         │                                │                  │
│ 世界观       │                                │ [输入创作要求…]  │
│ 时间线       │                                │                  │
└──────────────┴────────────────────────────────┴──────────────────┘
```

左侧导航稳定存在。中间工作画布随创作阶段变化。右侧 AI 对话在宽屏下常驻，在较窄窗口中折叠为抽屉，不覆盖作者尚未保存的正文。

作者不需要手工切换“AI 模式”和“编辑模式”。系统根据当前阶段、选中对象和待处理任务改变工作画布与建议动作。

## 4. 阶段自适应布局

### 4.1 创意阶段：对话为主

新建作品默认进入 AI 创作驾驶舱。中心区域呈现对话和三套故事方向，不先打开空白人物表或大纲表。

```text
作者输入一句创意
→ AI 生成三套方向卡
→ 作者比较、追问、局部调整或重做
→ 选择一套方向
```

方向卡至少显示：

- 一句话卖点；
- 类型与主要爽点/情绪价值；
- 主角核心能力与代价；
- 核心冲突；
- 预期篇幅和节奏；
- 与另外两套方向的主要差异；
- `选择此方向`、`修改后采用`、`重新生成`。

AI 不能只返回一段难以比较的长文本。

### 4.2 作品方案阶段：结构化文档为主

作者选择方向后，中间区域打开《作品方案》，右侧对话继续存在。

作品方案包含故事定位、创作规格、主线、人物、世界观、关系、冲突、结局方向、全书结构和节奏。作者可以：

- 直接编辑字段或段落；
- 锁定不允许 AI 改动的部分；
- 选择一段后通过对话要求 AI 修改；
- 对整套方案提出自然语言意见；
- 查看修改前后差异；
- 接受全部、逐项接受或要求重做。

AI 修改作品方案时生成候选 revision，不直接覆盖作者当前看到的版本。

### 4.3 路线图阶段：全书结构为主

作者确认作品方案后，中心区域切换为全书章节路线图。

默认展示卷、故事弧和章节范围，作者可以逐步展开到单章。路线图支持：

- 调整卷、故事弧和章节顺序；
- 修改目标章节数和预计字数；
- 锁定关键转折、结局和必须发生的事件；
- 通过对话提出“第二卷节奏太慢”等意见；
- 查看 AI 给出的影响范围和调整方案；
- 确认后形成新路线图 revision。

第一版不要求一次性生成每章的完整细纲；只为全书建立可持续细化的路线。

### 4.4 批次生成阶段：进度与控制为主

作者可以直接说“开始写前 10 章”或点击 `AI 写作`。系统弹出轻量确认卡，而不是完整设置表单：

```text
本批章节：第 1–10 章
预计字数：约 30,000 字
模型来源：Cursor 订阅 / OpenAI API / 当前创作方案
预算摘要：预计用量与作者上限
自动审阅：连续性、人物、因果、节奏

[开始创作] [调整] [取消]
```

章节数量范围为 1–50。作者可以在对话里表达数量，也可以在确认卡中修改。

运行期间中心区域展示：

- 当前步骤和当前章节；
- 已完成、进行中、待生成和失败章节；
- 已消耗与预计剩余预算；
- 暂停、继续和取消；
- 每章自动审阅是否通过；
- 可恢复或需要作者处理的错误。

后台内部的 planner、writer、reviewer 等技术角色默认隐藏，仅在高级详情中展示。

### 4.5 批次审阅阶段：正文与队列为主

批次完成后，中心区域使用“章节队列 + 正文编辑器 + 审阅摘要”：

```text
┌────────────┬──────────────────────────┬─────────────────┐
│ 候选章节   │ 当前章节正文             │ AI 对话/审阅    │
│            │                          │                 │
│ ✓ 已定稿   │ 可直接编辑               │ 自动审阅问题    │
│ ● 待审阅   │ 显示修订差异             │ 作者修改意见    │
│ ↻ 修改中   │                          │ 影响方案        │
│ ! 需处理   │ [定稿] [重写] [废弃]     │                 │
└────────────┴──────────────────────────┴─────────────────┘
```

作者可以：

- 阅读后直接定稿；
- 在正文中直接修改再定稿；
- 选择一段正文并给出局部意见；
- 对一章提出整体意见；
- 阅读完整批次后提出整批调整意见；
- 要求 AI 重新生成一章；
- 明确废弃某章候选。

当前批次未全部定稿、替换或废弃前，不允许开始下一批。

### 4.6 正常写作阶段：编辑器为主

作者随时可以自己写，不需要先向 AI 发指令。作者直接修改正式正文时：

- 保存为新的章节 revision；
- 提示该修改是否可能影响后续候选；
- 对后续候选触发确定性失效检查或 AI 影响分析；
- 不自动撤销已定稿历史；
- 后续长期记忆以新定稿正文为依据重建或增量更新。

右侧对话支持基于当前章节、选中文本和当前批次给出指令，但不会把整个项目无差别发送给模型。

### 4.7 故事档案阶段：结构化资产为主

人物、大纲、世界观、关系、时间线、事实和伏笔继续保留专门页面。每个页面都支持两种操作：

1. 作者直接查看和编辑；
2. 通过对话要求 AI 生成或修改候选。

例如作者说“设计三个更有压迫感的反派”，结果应成为三张人物候选卡；作者选择后才进入正式人物档案，而不是只留在聊天文字里。

### 4.8 导入续写阶段：证据审阅为主

导入小说后，中心区域展示确定性卷章结果和 AI 抽取候选。作者可以在对话中要求补充分析，但确认操作发生在结构化证据页面：

- 候选大纲、人物、世界观、事件、关系和伏笔；
- 原文章节、行范围或片段证据；
- 跨章合并结果和冲突项；
- 确认、修改、拒绝和重新分析。

确认完成后生成作品方案和长期记忆，再进入同一批量续写工作流。

## 5. 对话系统

### 5.1 对话的作用域

每条作者消息必须绑定当前上下文：

- 当前作品；
- 当前阶段；
- 当前选中对象，例如作品方案段落、章节、人物或批次；
- 当前 canonical head；
- 作者明确附加的其他对象。

输入框上方显示可删除的上下文标签，例如：

```text
[第 7 章] [选中文字 286 字] [当前批次] [人物：沈砚]
```

作者可以通过 `@` 选择人物、章节、大纲节点或世界规则，但第一版不要求作者学习斜杠命令。

### 5.2 AI 回复类型

AI 回复分为六类：

1. 普通说明：回答问题，不产生项目修改；
2. 选择卡：故事方向、人物方案、情节方案；
3. 变更候选：对作品方案、故事资产或正文的结构化修改；
4. 影响方案：说明受影响章节、事实和预计成本；
5. 运行状态：批次进度、暂停、恢复和错误处理；
6. 下一步建议：根据当前阶段提供可执行动作。

产生项目变化的回复必须带明确动作按钮，不能要求作者通过模糊聊天确认来猜测是否已经生效。

### 5.3 对话与正式数据隔离

- 对话文本本身不进入正式大纲、人物、世界观或事实；
- AI 口头声称“已经修改”不代表修改成功；
- 所有修改都必须对应持久化候选或明确的已执行用例；
- 作者接受后显示新 revision 和影响范围；
- 对话可清理或压缩，但正式候选、作者决策和运行记录不能随聊天消失。

### 5.4 对话历史

每部作品拥有本地持久化的主创作对话，可以按阶段、章节、批次或故事资产筛选。切换工作画布不会丢失对话，也不会把另一部作品的消息带入当前上下文。

长对话可以显示压缩摘要，但作者能够查看原始消息。对话摘要只用于界面连续性和模型上下文选择，不能取代正式作品方案、正文、记忆证据或作者决策。

## 6. 表单与精确控制的边界

表单只用于必须精确、可验证或涉及费用的内容：

- 批次章节数；
- 预计字数；
- 预算上限；
- 模型/创作方案选择；
- 修改影响范围；
- 导入来源与章节选择；
- 定稿、废弃、覆盖等不可模糊的确认。

题材、人物、冲突、世界观和剧情创意默认通过自然语言与 AI 共创，不设计成新建小说前必须填完的表格。

高级模型参数只放在应用设置或创作方案高级设置，不出现在日常写作主流程。

## 7. 修改与影响分析交互

作者提出修改意见后，AI 默认先返回影响方案：

```text
你的意见：第 7 章主角暴露身份太早

建议：
- 重写第 7 章后半段
- 调整第 8 章开头的追捕原因
- 第 9–20 章无需修改
- 不影响已定稿第 1–6 章

预计重新生成：2 章
[确认修改] [调整范围] [取消]
```

确认前不修改候选正文。若作者在影响方案生成后又定稿或编辑了相关章节，旧方案显示“已失效”，需要重新分析。

对于百万字长篇，默认只调整后续未定稿内容。历史定稿只有在作者明确选择“创建历史修订候选”时才进入修改流程。

## 8. 错误、恢复与费用提示

错误必须在当前任务位置显示，并给出下一步，不使用只显示技术错误码的弹窗。

典型处理：

- 网络中断：保留已完成章节，显示 `继续`；
- 应用重启：驾驶舱显示可恢复批次；
- 登录失效：显示来自哪个 API/订阅连接及 `重新登录`；
- 模型下架：显示受影响角色和可选替代模型；
- 订阅额度耗尽：暂停，不静默切换到付费 API；
- API 预算达到上限：停止后续章节，保留已完成候选；
- 结构化输出失败：只重试当前步骤，不重新生成已完成章节；
- canonical head 变化：阻止应用旧候选并重新分析影响。

任何重试前都显示预计是否会再次产生模型用量。

## 9. 信息密度与渐进披露

普通模式只展示作者需要理解的内容：

- 当前阶段；
- AI 正在做什么；
- 本批章节和进度；
- 需要作者确认什么；
- 预计费用或订阅额度来源；
- 下一步动作。

高级详情再展示：

- 实际 Provider 和模型；
- 智能体角色；
- Context Manifest；
- Token 使用；
- Artifact；
- 审阅者原始输出；
- 回退和重试原因。

技术信息不得挤占正文阅读和创作决策空间。

## 10. 键盘与可访问性

- 对话输入支持多行，`Cmd/Ctrl+Enter` 发送；
- 编辑器、对话和候选操作的焦点顺序可预测；
- 所有卡片操作都有文字标签，不能只依赖颜色和图标；
- 生成进度通过文本和状态图标共同表达；
- AI 流式输出不持续抢夺滚动位置；
- 作者选中文字后打开对话，焦点可以返回原编辑位置；
- 危险确认按钮与普通继续按钮在位置和样式上明确区分；
- Windows 与 macOS 使用平台一致的快捷键显示。

## 11. 非目标

- 不把聊天记录作为项目唯一导航；
- 不在对话里隐藏正式修改；
- 不让作者通过聊天手工维护所有长期记忆；
- 不把 Provider、Token 和智能体术语放在新手主流程；
- 不实现移动端布局；
- 不在第一版提供多人实时协作聊天；
- 不让 AI 自动发布小说或绕过作者定稿。

## 12. 验收标准

1. 新作者只输入一句创意即可获得三套可比较方向，不需要先填写人物和世界观表单。
2. 选择方向后，AI 产出可编辑、可锁定、可逐项确认的作品方案，而不是仅返回聊天文本。
3. 作者可以通过对话修改作品方案，也可以直接编辑结构化内容；两种方式都形成 revision。
4. 作者用自然语言或轻量确认卡启动 1–50 章批次，并在开始前看到模型来源与预算摘要。
5. 批次运行、暂停、失败和恢复在驾驶舱中可理解，不要求查看日志。
6. 批次完成后，作者可以逐章阅读、直接修改、给 AI 意见、重写、废弃或定稿。
7. AI 对正文或故事资产的修改必须先成为候选，不能因为聊天回复而静默生效。
8. 作者修改第 7 章后，界面能说明哪些后续候选受影响，并在确认前不重写。
9. 人物、大纲和世界观页面既支持作者直接编辑，也支持 AI 生成结构化候选。
10. 导入小说的抽取结果可按原文证据确认，并从同一驾驶舱进入续写。
11. Cursor/Codex 订阅和 API 模型在界面中显示不同的额度来源，失败时不静默产生 API 费用。
12. 应用重启后可以从 SQLite 重建当前阶段、批次、候选和待确认动作；聊天流事件不是唯一状态来源。
13. 切换章节或功能页面后，对话历史仍可按原上下文找到，但不会自动把其他作品或无关章节加入模型请求。
