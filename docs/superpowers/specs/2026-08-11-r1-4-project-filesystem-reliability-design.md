# R1.4 项目文件系统可靠性设计

## 目标

完成 R1 的最后一个可靠性切片：在既有项目级 OS lease、真正只读 store 和恢复副本之上，识别不可靠文件系统，阻止会立即危及项目的可编辑打开，并在运行期写入失败时保留作者内容并引导安全恢复。

本设计覆盖 Windows 与 macOS。Windows 默认未启用长路径选项的环境是发布验证目标。

## 已批准的交互策略

同步盘、网络映射目录和其他可能干预 SQLite WAL 或原子替换的文件系统，默认不因路径名称被阻断。项目可以继续以可编辑方式打开，但工作区持续显示文件系统风险提示。

若运行期写入失败，应用不得丢弃编辑器内存中的文本或将失败操作误报为已保存。它会优先尝试保存恢复草稿，并提供重试、只读重新打开和创建恢复副本等安全路径。无法保存恢复草稿时，界面必须明确说明内容仍留在当前编辑器中，提示作者复制文本后创建恢复副本或排除外部锁定。

## 方案比较

### 方案 A：集中式项目可靠性守卫（采用）

`internal/platform/projectfs` 提供无损打开探针、路径预算与 Windows/Unix OS 错误分类；`internal/application/workspace.Service` 保存当前项目的文件系统健康状态并把已分类的运行期失败转化为稳定用例结果；Wails/React 只呈现状态和恢复动作。

这样 SQLite、快照、分支、导入、恢复副本和正文保存共享同一组语义，文件错误不会散落在各业务用例中。

### 方案 B：仅在 SQLite store 内处理

SQLite WAL 与写入错误可集中处理，但快照恢复、分支原子替换、导入归档和恢复副本仍需各自补充文件系统处理，不能满足完整范围。

### 方案 C：由每个用例处理

初期改动较小，但错误类型、恢复行为、用户提示和跨平台测试会分散，无法建立可验证的数据保护边界。

## 架构与边界

新增的项目可靠性端口由 `workspace.Service` 在可编辑打开前调用，并由桌面组合层注入 `projectfs` 适配器。它不暴露底层绝对临时文件路径、原始 SQLite/Windows 错误或作者文本。

探针与分类的职责如下：

| 层 | 职责 |
| --- | --- |
| `projectfs` | 固定短相对路径预算、包目录写入与原子操作探针、同步/网络目录风险线索、平台文件错误归类 |
| `sqlite` | 保留驱动级错误原因并映射为稳定的数据库写入类别，不将字符串匹配扩散到业务代码 |
| `workspace.Service` | 仅在已取得 editable lease 后执行预检；保存 `ProjectFilesystemHealth`；在运行期失败时更新为 degraded，拒绝将失败写入视为成功 |
| Wails / React | 返回可序列化风险与恢复建议；常驻风险横幅；保存失败时保持本地编辑状态并触发恢复路径 |

`OpenProjectReadOnly` 不执行任何可写探针，也不写入风险记录。创建、可编辑打开、恢复副本目标目录和会在包内新增文件的操作各自使用同一套路径预算及已分类错误。

## 无损可编辑打开探针

探针在 lease 已获取、`PrepareEditable` 和迁移/恢复写入之前执行。它仅在包内新建唯一的短名临时目录；失败或成功后均清理该目录。探针按以下顺序运行：

1. 检查项目根与临时目录可创建、写入、`Sync`、关闭和删除；
2. 在临时 SQLite 数据库提交一条短写入后回滚另一条短写入，关闭后验证已提交值和已回滚值；
3. 验证 WAL 和 SHM 工件可在临时数据库生命周期中建立、可见且可清理；
4. 在临时数据库执行 `wal_checkpoint(TRUNCATE)`，确认 checkpoint 成功；
5. 对两个临时普通文件验证同目录不覆盖创建与原子替换，并对替换后的内容和目录同步结果作校验。

任何探针失败都会释放新取得的 lease，保持当前工作区不变，并返回一个明确、可恢复的打开错误。探针绝不触碰 `project.db`、`project.db-wal`、`project.db-shm`、快照、分支、导入档案、恢复目录或 canonical 内容。

目录特征只能产生 `warning` 风险：例如识别为同步根、网络卷或返回已知兼容性线索。没有可靠特征并不代表安全；每个实际写入仍必须分类处理错误。

## 运行期降级与恢复

项目健康状态包含：`normal`、`warning` 和 `degraded`，以及安全的原因类别与建议动作。`warning` 允许继续编辑；`degraded` 也不静默关闭项目或丢弃内存内容，但会使 UI 持续显示更强的风险提示。

以下失败类别进入统一映射：

- 外部占用：Windows sharing violation、lock violation、SQLite busy/locked；
- 不可写：只读、访问拒绝、路径已消失；
- 容量或 I/O：磁盘满、短写入、底层 I/O 错误；
- 一致性敏感操作：WAL/SHM 建立或 checkpoint 失败、同目录原子 replace/rename 失败。

事务或替换失败必须由其现有原子性边界回滚；R1.4 不尝试部分重放或覆盖 canonical 内容。正文保存失败时，前端保留未提交文本并调用已有恢复草稿机制。若该次恢复草稿成功，状态标记为可恢复；若失败，错误动作必须包含“复制文本”和“创建恢复副本”。其他业务写入失败显示同一风险面板，但不得伪造恢复草稿成功。

当后续写入或显式健康复检成功时，`degraded` 可降回 `warning`（若仍有文件系统风险线索）或 `normal`。风险状态仅属于当前进程打开的工作区，不写入项目包，也不向只读打开写入数据。

## Windows 路径契约

项目包内目录保持固定短名：`attachments`、`exports`、`imports`、`recovery`、`snapshots`、`branches` 与固定数据库、lease 和临时文件名。卷名、章节名、候选标题、作者输入和 Prompt 片段不得进入物理路径。

路径预检针对 `filepath.Clean` 后的绝对包根，加上每种操作的最长固定内部相对路径和短 UUID/哈希文件名。创建项目在创建目录前验证父目录与包名预算；打开项目验证现有根和可写内部路径预算；恢复副本验证目标父目录、生成的恢复副本包名与临时包名。超过 Windows 默认兼容预算时返回专用错误，提示用户选择更短的父目录，而不是依赖系统长路径开关。

现有跨平台保留名归一化继续适用于创建及恢复副本命名；Windows 还必须拒绝或替换末尾空格/句点及非法路径组件，且不把用户标题直接用作内部文件名。

## 错误与界面契约

桌面错误码新增稳定的项目可靠性分类，例如打开探针失败、路径过长、同步/网络风险、外部共享冲突、不可写、空间/I-O、checkpoint 和原子替换失败。错误信息不包含原始 OS 路径细节、SQL、Prompt 或正文。

`ProjectView` 或独立的工作区健康查询向前端提供风险级别、原因、推荐操作和是否应保留风险横幅。React 工作区在可编辑项目中显示非阻断横幅；保存失败时在编辑器附近显示操作卡，保证重试不会覆盖当前 textarea 内容。现有 lease 冲突卡继续负责“另一个应用实例正在编辑”，不与运行期文件系统风险混为一谈。

## 测试与验收

Go 单元与集成测试必须证明：

1. 每一个探针阶段成功、失败、清理和 canonical 文件未变化；
2. WAL/SHM、checkpoint 和同目录原子替换探针覆盖真实临时文件与可注入失败点；
3. 编辑打开在探针失败时不激活新 store、不替换当前工作区且释放 lease；
4. 运行期 Windows sharing violation、SQLite busy、只读、磁盘满、I/O、checkpoint 和 replace 失败都映射到稳定类别并使健康状态正确转换；
5. 正文保存失败保留编辑器文本；恢复草稿成功与失败分别呈现；canonical revision 不变；
6. Windows 默认路径预算覆盖长根、恢复副本、临时文件与保留名，macOS 保持可移植命名；
7. 只读打开不执行写探针、不创建业务工件且不持久化健康状态。

React 测试覆盖风险横幅、保存失败后文本保留、恢复动作和只读禁用状态。Foundation CI 继续运行 Linux race/vet 与 macOS/Windows 构建，并在 Windows 原生 job 运行 lease、路径和可注入 sharing-violation 聚焦测试。手工验收新增同步目录/同步客户端锁定、长根路径、checkpoint 与原子替换失败的 Windows/macOS 专用副本场景。

## 非目标

- 不根据路径名称永久禁止同步盘、网络盘或外接盘；
- 不引入云同步、后台文件同步或同步服务集成；
- 不改变 R1.3 lease、只读和恢复副本的语义；
- 不改变项目数据库 schema，也不向项目包持久化诊断状态；
- 不为规避 Windows 路径限制而引入长路径系统设置、符号链接或 Rust/CGO。
