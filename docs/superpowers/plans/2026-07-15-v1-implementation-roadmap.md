# Novel Studio V1 Implementation Roadmap

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已批准的商业产品设计拆成可交付、可验收的 V1 研发路线，最终发布 Windows 与 macOS 双平台的长篇小说多智能体创作桌面软件。

**Architecture:** 采用本地优先的模块化单体。Go 承载领域、应用、SQLite、智能体运行时、模型适配和平台能力，Wails v2 暴露薄桌面绑定，React/TypeScript 只处理界面与交互；Rust 仅在有量化证据且 ADR 批准后，以版本化 sidecar 引入。所有 AI 写作结果先形成可审阅变更集，正文、结构化故事模型、任务和版本历史均落在项目包内。

**Tech Stack:** Go 1.25.7+、Wails v2.13.0、React、TypeScript、Vite、SQLite、Vitest、Testing Library、Go `testing`、GitHub Actions；可选 Rust sidecar。

---

## 1. 实施原则

- 正式产品代码与 `prototype/web` 隔离；原型只作为已经验收的 UX 参考。
- 先完成领域契约和架构决策，再搭建依赖它们的生产模块。
- 每个阶段都形成一条可运行的纵向链路，不建设只有接口、没有用户价值的空框架。
- 所有生产功能执行测试驱动：先写失败测试，再实现最小代码，再重构。
- React 不直接访问 SQLite 或模型供应商；Wails 绑定不承载业务规则。
- 多智能体必须保留“不同角色可选择不同供应商和模型”的能力。
- V1 不启用商业授权限制，但所有受限能力经过 `LicenseService`/能力门禁，默认实现永远允许。
- 每个里程碑同时检查 Windows 与 macOS；不把跨平台问题留到发布阶段。

## 3. P0：桌面基础纵向切片

**目标：** 建立能在 Windows/macOS 构建的正式 Wails 应用，并打通“创建项目 → 新建章节 → 编辑 → 自动保存 → 重启恢复”的最小闭环。

**范围：**

- 根 Go module、Wails v2 入口、正式 React/Vite 前端和生产目录边界。
- 项目包目录、SQLite 迁移、项目/章节最小领域模型。
- 应用服务、薄 Wails API、前端项目库和章节编辑器。
- 自动保存、原子写入、快照与崩溃恢复基线。
- `NoopLicenseService` 及受限能力统一门禁。
- Go、前端及 Windows/macOS CI 构建验证。

**退出门禁：**

- [ ] macOS 与 Windows CI 均能完成 Go 测试、前端测试和 Wails 构建。
- [ ] 用户能创建项目和章节，输入正文后无需手动操作即可持久化。
- [ ] 强制终止后重新打开，已确认保存的正文不丢失；未提交草稿有恢复提示。
- [ ] SQLite schema 可从空库确定性迁移到当前版本。
- [ ] UI 没有直接访问数据库、文件系统或模型供应商。
- [ ] V1 授权门禁默认放行，关闭该实现不会影响领域模型和持久化结构。

## 4. P1：故事工程与结构化模型

**目标：** 让作者能直接管理世界、人物、关系、时间线、大纲、故事线和伏笔，并让章节与这些结构互相引用。

**核心任务：**

- [ ] 编写故事工程领域规格和不变量：实体身份、引用、生命周期、删除策略、冲突规则。
- [ ] 实现世界观、人物、关系、事件、时间线、大纲节点、故事线、伏笔、场景卡领域模型。
- [ ] 建立 `StoryRepository`、应用服务和 SQLite 映射，所有删除使用可恢复软删除或明确引用检查。
- [ ] 实现可视化工作台：人物关系、时间线、大纲树、故事线/伏笔状态。
- [ ] 实现章节与场景、人物、事件、线索的双向引用。
- [ ] 实现一致性检查器的确定性规则层，不依赖大模型也能发现孤立引用和时间冲突。

**退出门禁：**

- [ ] 同一故事事实只有一个规范来源，界面视图均由它投影产生。
- [ ] 结构编辑不会静默破坏章节引用；冲突能定位到实体和章节。
- [ ] 10 万字、200 章、500 个故事实体的基准项目仍能流畅导航和搜索。
- [ ] 结构化数据可完整导出并重新导入，无语义丢失。

## 5. P2：版本、快照与可审阅变更集

**目标：** 建立任何 AI 写作能力都必须依赖的安全修改机制。

**核心任务：**

- [x] 定义 `Revision`、`Snapshot`、`ChangeSet`、`PatchOperation` 和审阅状态机。
- [ ] 支持章节级版本历史、差异展示、还原、分支草稿和冲突检测。
- [x] 将正文与首批结构化故事模型（大纲节点、角色档案、故事事实）的修改统一表示为变更集。
- [x] 支持逐项接受、拒绝、编辑后接受和整组原子应用；大组应用前自动创建恢复点。
- [x] 自动保存与显式版本分离，避免每次击键污染可读历史。
- [ ] 为大文本差异和恢复性能建立基准测试；只有达到 Go 瓶颈证据后才评估 Rust sidecar。

**退出门禁：**

- [ ] 任何 AI 结果都不能绕过变更集直接覆盖正文或故事设定。
- [x] 接受/拒绝操作可重复执行且不会产生重复写入。
- [ ] 还原任意版本后，正文和相关结构化引用保持一致。
- [x] 异常中断不会留下“正文已改、故事模型未改”的半提交状态。

## 6. P3：供应商适配与多智能体运行时

**目标：** 建立供应商无关、任务可恢复、可观测、可审计的异构多模型协作系统。

**核心任务：**

- [ ] 定义 Provider 能力契约、模型目录、流式响应、工具调用、结构化输出、错误分类与成本统计。
- [ ] 首批接入至少两类兼容方式不同的供应商，验证适配边界不是围绕单一 API 设计。
- [ ] 实现本地凭据安全存储：macOS Keychain 与 Windows Credential Manager。
- [ ] 实现智能体角色、任务、运行、步骤、依赖、重试、取消、暂停、恢复与事件日志。
- [ ] 支持规划、起草、连续性审阅、风格审阅等角色分别配置供应商和模型。
- [ ] 实现上下文装配器：按任务选择章节、设定、摘要、检索结果和写作规则，并记录来源。
- [ ] 所有产出进入 P2 变更集；运行失败不会污染项目状态。

**退出门禁：**

- [ ] 更换某个角色的供应商不需要修改领域或界面代码。
- [ ] 应用重启后未完成任务可识别、可恢复或可安全重试。
- [ ] 用户可查看每次运行使用的模型、输入来源、输出、耗时、token/成本估算和错误。
- [ ] 密钥不进入项目包、日志、崩溃报告或 Git。

## 7. P4：小说导入与结构重建

**目标：** 导入已有小说后，自动恢复章节、故事线、人物关系、大纲、世界观和时间线，并允许作者校正后续写。

**核心任务：**

- [ ] 定义导入源、解析结果、证据片段、置信度、候选事实和合并决策模型。
- [ ] 首批支持 TXT、Markdown、DOCX；EPUB 作为后续格式扩展。
- [ ] 实现编码识别、章节切分、标题归一、原文保留和重复导入检测。
- [ ] 分层处理长文本：章节摘要 → 局部实体/事件抽取 → 跨章合并 → 全局结构重建。
- [ ] 每个抽取结论保留原文章节和证据片段，区分“文本事实”和“模型推断”。
- [ ] 实现人物消歧、别名合并、关系变化、时间排序、故事线聚类、伏笔候选识别。
- [ ] 提供导入审阅台，用户可确认、修改、合并、忽略后再写入正式故事模型。
- [ ] 导入任务可暂停、恢复和重跑，不覆盖用户已确认内容。

**退出门禁：**

- [ ] 导入错误不会修改原文件，也不会污染已有项目。
- [ ] 作者可从任意结构化结论跳回原文证据。
- [ ] 低置信度推断不会伪装成确定事实。
- [ ] 用固定金标小说集测量章节切分、人物实体和关键关系的精确率/召回率并达到规格阈值。

## 8. P5：创作工作流与质量闭环

**目标：** 将故事工程、智能体和变更集组合成真正能推进长篇小说的日常写作流程。

**核心任务：**

- [ ] 实现从大纲节点/场景卡生成章节草稿、续写、重写、扩写、缩写和局部润色。
- [ ] 实现“规划 → 起草 → 连续性审阅 → 风格审阅 → 作者批准”的可配置工作流。
- [ ] 建立项目级写作规则、角色语气、禁用项和参考风格，但避免直接复制受版权保护文本。
- [ ] 实现跨章检索、故事摘要滚动更新和上下文预算策略。
- [ ] 实现任务中心、模型用量、失败恢复、通知和后台运行体验。
- [ ] 实现全文搜索、章节状态、目标字数、进度和导出。
- [ ] 完成 DOCX、Markdown、TXT 导出及项目包备份/恢复。

**退出门禁：**

- [ ] 用户可从一个已有大纲完成完整章节，并能逐项控制 AI 修改。
- [ ] 多轮生成不会因上下文压缩而遗忘已确认的关键设定。
- [ ] 生成失败、模型切换和网络中断均有可理解的恢复路径。
- [ ] 导出的正文顺序、标题层级和段落格式正确。

## 9. P6：双平台发布与商业化预留验收

**目标：** 将功能完整的 V1 变成可安装、可升级、可诊断、可安全发布的商业桌面产品。

**核心任务：**

- [ ] 完成 macOS 签名、公证、DMG/ZIP 和 Windows 签名、安装器、卸载策略。
- [ ] 建立版本号、数据库兼容版本、配置版本和升级回滚规则。
- [ ] 实现隐私友好的诊断包，默认排除正文、提示词、密钥和模型响应。
- [ ] 完成大项目性能、内存、长时间运行、断网、磁盘不足、只读目录和异常退出测试。
- [ ] 完成安全威胁建模：本地凭据、项目包、导入文件、模型输出、IPC 和更新链路。
- [ ] 验证 `LicenseService` 门禁覆盖面，但 V1 继续使用 `NoopLicenseService`，不显示激活界面。
- [ ] 编写用户文档、迁移说明、故障恢复指南和发布检查表。

**退出门禁：**

- [ ] 两个平台的干净机器安装、首启、升级、卸载均通过验收。
- [ ] 项目包在 Windows 与 macOS 间往返打开无数据损坏。
- [ ] V1 无授权服务器也能长期正常运行；未来替换授权实现不需要修改领域模块。
- [ ] 发布构建不包含测试密钥、示例稿件、开发数据库或调试接口。

## 10. V1.5 与 V2 后续路线

### V1.5：商业授权启用

- [ ] 实现激活码/账号兑换、签名许可证租约、设备绑定和续期。
- [ ] 默认 30 天授权周期；到期前后台续期，最长 7 天离线宽限期。
- [ ] 到期后始终允许打开、阅读、搜索、备份和导出；限制新建、编辑、导入与 AI 任务。
- [ ] 授权时间判断同时考虑服务端签名时间、本地单调时间和回拨检测。
- [ ] 授权服务不可用时优先保护用户数据与可导出性，不把网络故障误判为盗版。

### V1.5/V2：零基础自动创作

- [ ] 增加类型、篇幅、受众、基调等低门槛入口。
- [ ] 智能体主动生成并解释世界观、人物、大纲与章节方案。
- [ ] 提供少决策和全自动两种模式，关键节点仍允许作者接管。
- [ ] 建立长篇自动推进的停止条件、质量门禁、预算上限和人工确认点。

## 11. 里程碑与建议节奏

以 2 周迭代为默认节奏，实际日期按团队规模与供应商接入情况校准：

| 里程碑 | 建议迭代 | 主要结果 |
|---|---:|---|
| M0 规格冻结 | 1 | ADR、领域词汇、测试策略、设计系统映射 |
| M1 基础纵向切片 | 2–3 | 可安装壳、项目/章节、保存恢复、CI |
| M2 故事工程 | 3–4 | 人物/关系/世界/时间线/大纲/故事线 |
| M3 安全修改 | 2–3 | 版本、差异、变更集、回滚 |
| M4 多智能体 | 4–5 | 双供应商、异构角色、任务恢复、审阅链 |
| M5 导入重建 | 4–5 | 长文本导入、证据化抽取、审阅合并 |
| M6 创作闭环 | 3–4 | 规划到成稿、连续性、导出与任务中心 |
| M7 发布候选 | 3–4 | 性能、安全、签名、安装、升级、文档 |

这些是工程排序，不是承诺工期。每个里程碑只有通过退出门禁才能进入下一个稳定基线。

## 12. 全程质量门禁

每个 PR 至少满足：

- [ ] 需求或验收标准能追溯到批准规格。
- [ ] 新行为先有失败测试，并覆盖成功、失败和恢复路径。
- [ ] `go test ./...`、前端单元测试、lint/typecheck 通过。
- [ ] 涉及持久化时包含迁移前进测试、旧数据兼容测试和事务边界测试。
- [ ] 涉及 AI 时包含确定性 fake provider；CI 不依赖真实付费 API。
- [ ] 涉及平台能力时说明 Windows 与 macOS 差异并在相应 runner 验证。
- [ ] 日志和测试夹具不含真实稿件、密钥或个人信息。
- [ ] 文档、ADR、数据字典和用户可见行为同步更新。

V1 发布前另外满足：

- [ ] 全量备份/恢复演练通过。
- [ ] 跨平台项目包兼容矩阵通过。
- [ ] 关键用户旅程端到端测试通过。
- [ ] 真实规模基准和 8 小时稳定性测试通过。
- [ ] 数据损坏、磁盘满、数据库锁、模型超时和升级失败均有演练记录。

## 13. 计划完成定义

当 P0–P6 全部门禁通过，且 V1 发布候选在 Windows/macOS 干净环境完成安装、创作、导入、AI 审阅、导出和恢复验收时，本路线图完成。授权启用与零基础自动创作按 V1.5 子计划继续，不阻塞 V1 发布。
